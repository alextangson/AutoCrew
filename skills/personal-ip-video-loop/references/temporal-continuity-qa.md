# 抽帧、闪帧与画面连续性审核

`check_slivers=0` 只证明时间线几何上没有短暂外露的 A-roll。它不检查导出像素。完整解码、正确帧率和静态抽样也不能证明连续性通过。

## 导出后的检查

1. 保存实际时间线、素材路径/源入点/播放速率、导出任务 ID 和成片哈希。
2. 对全片做短闪检测。对不透明全屏 B-roll，按时间线映射逐帧比较源画面与成片，排除字幕区。复杂裁切、调色、透明叠层必须使用等价变换或原生合成参照，不能直接比较未变换素材。
3. 检查每个切点前后至少 5 帧，尤其是用到源文件末尾的片段。只找 A-B-A 单帧闪回会漏掉临近切点的连续 2 帧泄漏，因此还要做源画面对照。
4. 候选点必须核对：原素材对应帧、ChatCut 合成预览、实际导出帧。按正常速度看可疑点及其前后上下文。正常切镜、故意定格、动画出入场和 24→30 fps 的正常重复帧不能自动判错。
5. 修复后重新导出，并复查全片同类问题。复用之前的零空隙结果不能替代新成片检查。任何未验证的正常速度播放或复杂合成范围须明确列出。

辅助脚本 `scripts/temporal_source_check.py` 只给出全屏素材对照候选，不自动删除帧、不批准成片。输入 JSON 包含 `fps` 和 `clips`；每个 clip 含 `name`、`path`、`startFrame`、`durationFrames`、`sourceInUs`，可选 `playbackRate`。路径应指向本机真实源文件。依赖 ffmpeg、ffprobe 和 numpy。

## 按原因记录与处理

| 证据 | 原因分类与处理方向 |
|---|---|
| 时间线存在短空隙，源素材正常 | 剪辑覆盖问题；按语义补尾帧或修气口，保持用户保留的真人段 |
| 原素材本身出现闪帧、重复或跳变 | 素材问题；修受影响素材，保留原件和时间映射 |
| 相邻 MG 重启对象状态，但所有帧都有内容 | 动画状态衔接问题；由 MG 负责人修衔接，不能用补空隙冒充修复 |
| 源素材和原生预览正常，导出露出底层或缺画面 | 导出解码/合成路径问题；先隔离复现。检查源尾、PTS、帧率、编码重排和导出重复性；尾部余量或转码只是候选规避，须经实际复导验证 |
| 帧率不同导致规则重复，但没有异源画面 | 帧率转换节奏；单独评价观感，不能称为露底或丢帧 |

不能仅凭含 B 帧就断言 B 帧导致问题。不能凭重导一次正常就宣称底层缺陷已根治。没有源码/日志证据时，报告可确认的故障层级与尚未确定的机制。

## 已观察到的回归案例

2026-10-09，《AI 是你的织布机，还是你的工作室？》v004：7 处共 9 帧露出真人，位于 95.633、172.533、296.700–296.733、307.767–307.800、318.533、328.200、387.433 秒。片段有完整覆盖，抽查原生预览和源尾帧正常。短片编码对照未稳定复现，所以不能确认为 B 帧问题。该案例说明必须审核实际导出文件，不能只审核轨道空隙与预览。


该案例后续修复：为接近 EOF 的 36 个源视频添加 1 秒克隆尾部，保持时间线使用范围不变，在副本替换引用。v005 两次独立完整导出、各 74 个全屏补充画面片段源对照均为零候选。可作为该类导出缺陷的已验证规避思路；不能据此要求所有项目统一转码，也不能宣称引擎缺陷已根治。采用时须保留原文件、验证构图/源映射不变，并复查实际新导出。
