# 发布前检查

发布前使用产品当前的检查结果，不在技能里复制一套会漂移的阈值。

1. 用 `autocrew_content {action:"get", id}` 读取目标稿件，确认当前版本、平台和作者认可状态。
2. 调用 `autocrew_pre_publish {action:"check", content_id}`，逐项解释 `checks`、`allPassed`、`summary`。工具可能按状态机推进到待发布；是否成功以返回结果为准，不能自己宣称推进完成。
3. 检查包含基础文字、平台要求、封面/成片和稿件阶段等条件。`autocrew_review {action:"full_review", content_id}` 仅提供机械检查；其 `passed` 不是语义审稿通过、不是作者批准，也不是“质量60分以上”。
4. 未审、审稿过期或残留问题必须披露并处理。宿主正式审稿用 `autocrew_review_desk pack/submit`，单宿主的 `host_self_review` 不等于独立评审或作者认可。实质文案修改回写作提交链检查；`auto_fix` 仅清理空白，不能自动解决事实、受众和表达问题，敏感词需结合上下文人工判断。
5. 封面要求、标签与字数要求使用这次工具回执，不读取本地封面文件，不直接调用源代码函数，也不为补字数编案例和数字。
6. 检查通过后，只有用户已明确授权本次发布的目标与内容才继续发布。稿件保存、AI 审稿、作者认可、待发布和发布完成分别说明；此技能不会自动替作者批准正文。

汇报用“已通过什么、还缺什么、下一步做什么”。所有检查满足也不等于已发布；收集实际发布工具回执后再报告发布结果。
