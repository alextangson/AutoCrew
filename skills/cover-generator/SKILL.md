# AutoCrew 个人 IP 封面

把选题对应的内容转成可审核的个人 IP 封面。内容决定本期创意，`~/.autocrew/cover-style.json` 约束长期身份、文字、材质与图层标准。本 skill 只交付 `3:4` 和 `4:3` 两种比例。

人物封面还必须遵守 [references/identity-lock.md](references/identity-lock.md)。当任务涉及修脸、改表情、横竖版延展或“更像本人”时，先读该文件再行动。

## 不可绕过的生成约束

- 所有候选、修订和比例延展都必须通过 `autocrew_cover_review` 使用 Image 2（模型标识 `gpt-image-2`）生成或编辑。调用后核对返回的 provider/model；未明确使用 `gpt-image-2` 的图片不得进入审核或交付。
- 禁止用 SVG、HTML、CSS、Canvas、DOM 截图、程序化绘图或模板排版来生成、拼装、补字或替代封面；它们也不能作为 Image 2 不可用时的降级方案。
- Image 2 未配置、调用失败或返回的模型不对时，停止并报告具体阻塞。不得切换 Gemini、其他生图模型或排版方案继续出图。
- 固定顺序是 `3:4 生成 → 3:4 审核/修订 → 用户明确批准 → 4:3 生成 → 4:3 审核`。未批准 `3:4` 前，禁止预生成或并行生成 `4:3`。
- 不生成 `9:16`、`16:9`、`2.35:1`、方形或其他比例；即使平台默认值或旧记录包含这些比例，也不沿用。
- 禁止调用 legacy `generate_ratios`，因为它会同时生成未需要的 `16:9`；只能用 `platform_ratios` 并显式传 `ratios=["4:3"]`。

## 工作原则

- 内容先于风格：先读标题和正文，提炼核心冲突、具体证据、视觉隐喻与目标受众。
- 用户没有 `content_id` 时，优先找到最近一篇相关内容；只有选题而没有内容时，先创建或生成该选题的内容变体，再做封面。
- 直接生成三案，不在出图前要求用户选择风格。
- 三案必须在主视觉、媒介、构图和标题钩子上真实分叉，不能固定套用“电影/极简/冲击力”三件套。
- 用户反馈后只重做指定方案，保留反馈记录；不要把一个局部修改变成整套风格漂移。

## 个人形象与参考图

第一次使用先建立个人形象库：引导用户上传 3–5 张近期真实照片，至少包含清晰正脸，并尽量覆盖侧脸、眼镜和不同表情。少于 3 张时继续提示补充，但至少 1 张即可试生成；没有真实照片时禁止生成带人物封面。

真实照片放在 `~/.autocrew/covers/templates/`，负责锁定身份；AI 生成的个人肖像备选放在 `~/.autocrew/covers/portraits/`，只负责补充表情、姿态和可用构图。生成肖像不能替代真实主身份照，也不能单独作为身份锚点。最终出封面时，前 3 个参考位优先使用真实身份、真实骨相、真实表情照片；只有用户明确选中某张生成肖像的姿态时，才允许它占 1 个参考位，且真实主身份照始终排第 1。

如果存在 `cover-style.json`，按其中的 `referenceImages` 优先级读取；否则按文件名排序。

建议命名：

- `00-current-identity.*`：当前生活照，最高身份优先级，负责脸型、五官、发型、眼镜。
- `10-editorial-bone-structure.*`：棚拍肖像，只补骨相、轮廓和镜头气质。
- `20-editorial-expression.*`：表情或造型参考，只补态度，不覆盖当前身份。

有人物时必须锁定同一个人的可识别身份。禁止把创作者做成泛化程序员、宅男刻板印象、柔弱女性化造型，或呆滞证件照表情。表情只能走两条路：克制、帅、有判断力；或明确夸张、能吸睛。

个人肖像备选默认生成三种明确分叉：克制有判断力的正面肖像、审视感三分之二侧身、带干净手势的夸张表达。人物皮肤保持低颗粒、真实摄影质感，画面不加文字，给后续封面排版留出头肩和手部安全区。`reference-portrait-realism` 可用于补充身份素材，但其毛孔、雀斑、痘印和相机颗粒规则不得原样带入最终封面；封面需要“干净但真实”，不是“靠瑕疵证明真实”。

## 封面生成

1. 用 `autocrew_content` 读取内容标题、正文、平台与状态。
2. 先确认封面 provider 为 relay、模型为 `gpt-image-2`；如果调用前无法读取配置，则在首次返回后先核对 provider/model，再展示图片。不满足时停止。
3. 调用 `autocrew_cover_review action=create_candidates`，传入 `content_id`、`ratio="3:4"`，需要时传 `custom_title`。这一阶段只生成 `3:4` A/B/C 三案。
4. 展示三案的图片、标题和设计理由，直接询问选 A/B/C 或给指定方案反馈。所有 `revise` 仍只处理 `3:4`，并继续核对模型为 `gpt-image-2`。
5. 只有用户明确表示某个 `3:4` 方案通过后，才调用 `approve`；“先看看”“方向可以”“再横版试试”不算批准。
6. `3:4` 批准后，调用 `autocrew_cover_review action=platform_ratios`，显式传入 `ratios=["4:3"]`，且只生成这一种延展比例：

   - 无人物方案可以按同一创意重新构图。
   - 人物已经通过用户确认时，必须锁定批准的 `3:4` 母版，只用 Image 2 对新增画布做 mask outpaint；禁止再用原 prompt 整张重画。
   - 延展后若人物偏小，只能在不损伤标题与平台安全区的前提下做确定性近裁；不得借“放大人物”再次生成一张新脸。

7. 单独展示 `4:3` 成品供用户审核。未通过时继续修订 `4:3`，不得改写或撤销已批准的 `3:4` 母版；通过后再交付两种比例。

## 人物、文字与图层标准

人物与文字同时出现时，默认图层从后到前：

1. 背景、结构图形和氛围纹理。
2. 主标题与核心关键词。
3. 完全不透明、边缘干净的人物主体。
4. 可读性优先的副标题和必要信息条。

标题可被人物自然遮挡一小部分以制造深度，但不得穿过脸、眼镜、皮肤或身体形成透明人物。人物上禁止重胶片、纸张或油画颗粒；颗粒只保留在文字、色块和背景，人物保持清晰真实摄影质感。允许适度上镜优化：均匀肤色、清理临时瑕疵、加强眼神光、整理发型和轮廓光；禁止改脸型、眼距、鼻唇比例、下颌骨或把本人平均化成网红脸。

标题规则：

- 从内容中提炼最短、最有冲突的钩子；中英混排时放大核心名词或数字。
- 粗体、无衬线、高对比、无渐变，200px 宽缩略图仍可读。
- 副标题必须与背景形成稳定对比；必要时使用纯色信息条或局部暗底，不能只靠细描边。
- 中文必须逐字正确。出现错字、乱码或排版问题时，继续用 Image 2 局部编辑或重新生成当前方案；禁止用 HTML/SVG 等确定性排版覆盖成品。

## 反馈翻译

把用户口语反馈转成可执行约束：

- “不像我” → 提高当前身份照优先级，锁定眼镜、脸型、眉眼、鼻唇比例和发型，禁止平均化美颜。
- “表情很呆” → 改成克制有态度或明确夸张；不要只做轻微微笑。
- “太宅男/程序员” → 移除工位、显示器、连帽衫、代码背景等刻板符号，改为创作者/导演式造型与镜头气质。
- “人物颗粒太重” → 人物皮肤和衣服降噪、低颗粒；文字与背景保留印刷或纸张颗粒。
- “副标题看不清” → 提高字号、字重和底色对比，保证缩略图阅读。
- “空间太空” → 放大人物与标题，增强交叠关系，但保持脸部安全区。
- “文字在人物前面” → 主标题退到人物背后，人物完全不透明，副标题另设前景信息条。
- “脸脏/有裂纹” → 只建立脸部与颈部局部 mask，去掉迁移到皮肤上的印刷颗粒；遮罩编辑不可用时直接失败，禁止降级成整张生成。
- 在 AutoCrew 封面面板中先打开“框选局部”，再在脸、标题或单一区域上拖出矩形、填写修改意见并回车。只有构图或创意方向真的改变时才整张重做。
- “横版人物变了” → 回到已批准竖版母版，中央人物与原文字全部设为不可编辑，只 outpaint 左右背景。
- “人物太小” → 先检查 200px 缩略图；优先做 5–12% 确定性近裁或重新分配背景，不重新生成脸。

## 交付验收

每张定稿必须通过：

- 比例和尺寸正确，横竖版没有机械裁切。
- 人脸身份像本人，眼镜和关键特征正确；没有多余肢体或五官错误。
- 人物不透明、低颗粒，标题不穿脸；文字/背景颗粒可保留。
- 主标题和副标题逐字正确，200px 缩略图可读。
- 同时检查 100% 人脸裁切与 200px 整图缩略图；前者看脏纹、AI 蜡感和五官，后者看标题、人物大小与点击理由。
- 同一方案的 `3:4`、`4:3` 必须是同一张脸、同一副眼镜和同一表情；只要人物发生漂移就不得入库。
- 每个成品的生成记录都明确显示 `gpt-image-2`；没有模型证据或走过 SVG/HTML 排版链的图片不得通过。
- 无水印、Logo、网址和无关英文装饰。
- 两种成品都存在于内容目录，审批后根目录有对应“封面”副本；报告最终绝对路径。

## 工具

- `autocrew_content`：读取/创建内容。
- `autocrew_cover_review`：`create_candidates`、`get`、`revise`、`approve`、`platform_ratios`。
- `autocrew_desk`：从别的宿主（Codex 封面师）进来时先 `claim`，收工 `release`；
  认领期间 `create_candidates` / `revise` / `approve` / `platform_ratios` 都要带 `claim_token`，
  否则会被持有者挡下。工作台内部走这个 skill 时不需要。
- `autocrew_asset`：必要时登记和检查成品资产。
