# 抖音口播：灵感到定稿

你一个人在这个会话里写完一篇。AutoCrew（`autocrew_draft`）只存稿、给数据、核事实；流程由你按下面的步骤推进。创始人表态的地方：选立意、选开头、提修改、说「定了」。

一个会话只做一篇。讲解片等别的作品另开会话。

## 硬规矩

- 没有素材不编亲历。一手材料只来自创始人的原话或 `start` 返回的 `firsthand`。`voice_refs` 是口吻参考（他怎么说话），不是范文，也不能证明亲历。
- 档案（`start` 的 `rules`、`never`）只剩底线：说人话、观众是不写代码的职场人、只写真事、只交能直接念的正文。体裁手册管结构；「写法」一节和范文教怎么留住人。底线不让，其余按体裁判断。
- 一条稿只认立意时锁住的依据：那本手册那一版、立意卡上引用的范文、开写时的写法（`angle` 回执和 `start` 的 `progress` 给全文）。中途升级了也不换。旧稿没有这些锁的，照旧方式续写。
- `save` / `angle` / `opening` / `prepare_final` 之后的每条回复，结尾都给回执里的 `workbench_url`：`[在工作台打开第 N 版](<workbench_url>)`。
- 存盘失败（`storage_error` / `storage_unavailable`）就停下，把原始错误告诉创始人；不得把稿子写成库外文件继续推进。

## 1 衍生

`autocrew_draft {action:"start", inspiration:"<创始人原话>"}`；灵感对应已有选题就加 `topic_id`（接手已有稿用 `content_id`，按 `progress` 从断点接着做）。从灵感展开 3–5 个方向，每个一行：讲什么、给谁看。参照 `context.series` 别和最近几条撞主线。

## 2 调研

查这个方向的真事、真数据、同类视频怎么讲、哪条爆了。要在稿里引用的原话或数字，用 `verify_quote{content_id, url, quote}` 登记：服务端现抓原网页逐字比对，过了才进证据台账。被拒说明那段不在原文里；服务端也抓不到的，就是未核验，不能当事实写。

再花约 10 分钟收目标用户的原话：相关抖音视频的评论（`ego-browser` 技能，只读，不点赞不评论）和 YouTube 评论（`npm run craft:fetch -- <视频网址> --comments 50`）。这些只当调研线索，不用 `verify_quote` 登记，写进稿里按未核验处理。抖音看不了就如实说，改用 YouTube 评论。

## 3 立意

读 `context.playbooks_index`：5 本体裁手册各自「什么时候选它」。体裁由手上的材料决定，不由题目决定。`playbooks_error` 有值就停下告诉创始人。

出卡之前，对你考虑的每个体裁调 `exemplars{genre, content_id}` 读范文全文（学结构、节奏、钩子的位置，不抄句子不借题材）。回执 `note` 说本体裁无范文，卡上就写「本体裁无范文」；`exemplars_unreadable` 就停下告诉创始人。

给 3 个立意，每张卡标一个体裁，选卡即选体裁。每张包含：体裁、我们想说什么（一句）、给谁看、一手素材（来自哪条 `firsthand` 或创始人原话；没有就写没有）、贯穿全篇的那个例子、爆点（观众能转述出去的那一句，出现在第几秒）、借哪篇范文的哪一招、放在第几秒（两三句）、开头 15 秒原话、为什么可能爆（引真实数字，没有就写没有）、4–6 行论证链。

动笔前你得知道这篇想说什么。反常识判断、干货方法这两种，主线要是我们自己的判断，外部资料只当证据；人物故事、实验演示的主线是那件事本身，判断放后面、只说一句。实验演示必须有创始人亲手做过的事：没有就问他能不能做一次，他不做就改体裁，别编实验。

创始人没选定就追问一句：选哪个，还是合成一个。选定后 `angle{content_id, base_version, genre, exemplars, main_line, for_whom, opening, why_viral, chain, founder_words, chosen_option}`：`exemplars` 是那张卡上实际引用的 `[{id, version}]`（没有就 `[]`），`founder_words` 照抄他的原话，`chosen_option` 放当时给他看的那张卡全文。

## 4 先磨开头

全文之前，先给 3 个写法不同的前 15 秒（不是同一句换词），用 `opening{content_id, base_version, candidates}` 记下再编号给他。他选了或改了一句，`opening{content_id, base_version, opening:<选中的全文>, founder_words}`。都不满意：问清哪里不行，再出一轮，`opening{candidates, founder_words:<他这次的话>}`；回 `back_to_angle` 说明连着两轮都没中，回第 3 步重出立意。没选开头时 `save` 第一版会被拒（`needs_opening`）。

## 写法：怎么让人看下去

观众随时可以划走，他留下来只有一个理由：**他想知道接下来会怎样**。写的时候，每一段都问自己一句：这一段结束时，观众心里有没有一个还没被回答的问题？没有，他就走了。

我们过去的稿子留不住人：播放前十的视频，平均只看 11–26 秒。别拿它们当写法的参照。

本体裁的对标范文会和这一节一起给你。范文是活的样子，这一节只是帮你看懂它们。学的是结构、节奏、钩子放在哪，不抄句子，也不借题材。创始人自己的口播转写也会给你，那个只用来学他怎么说话，不学怎么写。

### 开头：15 秒内回答两件事——这跟我有什么关系，为什么要听你说

- 第一句先亮这期的主题钩子，直接点中目标观众最想知道的那件事（想抄大公司 AI 转型作业的人、想知道哪些 agent 好用的人），再给画面或例子：观众手上的一个动作、一个反常的结果、一个具体的数字。最核心的矛盾或好奇点放在最前面，别让画面、铺垫把主题挤到第二段。不讲概念。
  - 「你想用一个苹果手机的钱买五个苹果手机」（创野小朱）
  - 「我把 7 个 AI 关进 7 个房间」（公与山河，188 万赞）
  - 「你让 AI 画打游戏的男生，会得到这样」（大师的 AI 小灶）
- 15 秒内抛出第一个缺口：一个观众以为自己知道答案、其实不知道的问题，或者一个跟直觉反过来的结果。
- 「为什么要听你说」靠动作带出来，不单独写一句身份介绍（「我们是做 X 的」）。用和这条题目有关的动作：「我自己从龙虾换到了 Pi，每天拿它干活」「我今年自己办过黑客松，也当了很多次评委」，或者「这篇我看了好几遍，写得很密，我帮你翻成人话」（第四种黑猩猩）。
- 稿子超过 5 分钟，30 秒内给一张路线图：要经过哪几站，看完能带走什么。秋芝 56 分钟的教程收藏 5.8 万，开头就是「从装上它、用起来，到管住它，再到个性化，最后高级扩展」，并且明说「分几次看完也没问题」。

### 中段：靠「下一个问题」往下带，不靠「第二点」

报菜单（「第一个坑」「第二步」）等于告诉观众还剩几段，他会自己算要不要看完。往下带人的办法，是每解决一个问题，就亮出下一个：

- **闯关**：创野小朱那条，每一轮都是「你找到一个漏洞，恭喜你学会了 X → 平台修好了 → 但『漏洞是死的，可人是活的』，你又发现……」。观众每过一关，都想看下一关怎么破。做东西的故事最适合这样写：「戴上字幕眼镜不就解决了？」「那价格怎么告诉顾客？」「这下总行了吧？」每一关都必须是真碰到过的坑。
- **一个例子走到底**：知识是在这个例子上「操作」出来的，不是讲出来的。公与山河整条片子就是一局游戏，创野小朱整条就是一次「买手机」。换例子，等于让观众重新进一次门。
- **规则讲清，再出事**：公与山河先用 1 分钟把游戏规则讲明白（猜对存活、猜错爆炸、无卡对话给对方一把枪），后面每一次背叛，观众都看得懂有多狠。故事里要先让观众知道「正常该怎样」，出事的时候才有冲击。
- **例子和做法要真**：给观众抄的做法，最好是真有人在用的（带出处的原话、真实工具）；每一关里举的东西，用观众工作里真会碰到的实物（客户清单、手机号、去年的活动数据），不用我们自己推出来的建议或报名表这类泛例子。只有推出来的道理、没有真人真物，观众会觉得在听人讲道理，没有收获感。
- **翻转只从真事里挑**：做好了 → 一测就出事 → 补救；以为是 A → 其实是 B。哪个环节真的出过意外，就把它放在中段最显眼的地方。没有真的意外，就不编。

写完中段，按秒往下过一遍：有没有哪 30–60 秒里，观众既没拿到新东西，也没有新问题？那里就是他划走的地方。

### 判断怎么说才不爹味

爹味不在于有没有观点，在于观众是被教育还是被邀请。小天讲「飞书 CLI 为什么破万星」：先摆数据（595 个 PR，合并时间中位数 6.5 小时），再说「我的答案不敢说是绝对正确，但是你们听听到底有没有道理」，然后才给判断，最后当场演示一遍。顺序是证据 → 拙见 → 演示，观众自己得出结论。

用「你应该」「你必须」「很多人都错了」开口，就是在教育人。结尾也一样：「先别急着 X，先问 Y」「就别 X 了」是在给观众布置作业，换着说法也是同一个句式，几条稿连着用就撞车了。判断说成我们对这件事的看法，可以挂「我觉得」「大概率」；连专家自己都说不准的，照实讲（「就算是 Stripe 的 CEO，也很难预测」）。要给建议就说成邀请，比如「原文不长，建议你自己读一遍」。

引用外部来源，要说出名字，再在引用那句话里顺带半句它凭什么懂：这个数是怎么来的、它在什么位置。比如「开会多两成不是问卷问出来的，是从全公司的日程表里拉出来的」「Stripe 是全球大量互联网公司收钱用的那根管道」。不单独成段，也不用「先说它为什么值得信」这种话宣布，那听着像在替它打包票。不写「有位作者」「有测评说」「有业内人士」这种没名字的来源；查不到名字、核不了的就不用。手上有原文的，告诉观众原文在哪。

### 抽象的东西，先翻成一句人话，再找一个家常的比方

- **概念一出现，立刻翻译**：小天说「Ontology，本体论，听着很悬吧？其实就是一句话：先让 AI 看懂你的世界，再让它动手改你的世界」。这一篇新出现的行业词不单独站着。同系列讲过的词（agent、skill 这类）不再解释，观众试读说没听懂也不补。
- **评判标准用大白话直接问**：结构提示和评判标准不自造比喻。别说「第二把尺子」「它够不够得着你每天正在干的活」，直接说「你能不能照着抄」「它到底能不能帮你提效」「这个会员费值不值得交」。
- **比方从观众的生活里找**：大锅饭把「堵不如疏」讲成「想让老公不在外面乱来，你自己也得健身」。先问自己：这个关系在家里、饭桌上、菜市场里长什么样？
- **讲机制，先找有出处的现成概念**：比如有限理性、互补品，说出是谁提的或原文怎么叫，再配一个观众见过的东西（「汽车变便宜了，汽油和道路就更值钱了」）。找不到现成概念再打比方；我们自己推出来的场景要在稿里说明是假设（「打个比方」「我编个例子」）。
- **一个比方用到底**：小天开头说淘金者和金矿，中间说手术刀，结尾说「金矿是什么，已经告诉大家了；铲子现在也交到你手里了；Ontology 的方法论，就是矿脉的地图」。比方换太勤，观众要重新理解一遍。
- **产品演示，拿一个真作品从头做到尾**：秋芝讲剪映，不是一个个报功能，而是拿一部短剧从剧本做到成片，中间放两次片段。观众关心的是这部短剧能不能做成，功能是顺带看完的。

### 爆点：给一个他能转述出去的东西

观众转给同事时会说的那一句或者那个名字，比如「TOCTOU：先检查后使用」「漏洞是死的，可人是活的」「关键词联想陷阱」。要求是口语、短，里面带着片子里讲过的具体东西。它应该在前半段就出现，后面反复回扣（创野小朱每一关都用「恭喜你，你学会了……」回扣一次）。

### 收尾：兑现开头，判断只说一句

- 开头许诺了什么，结尾要对得上，最好回到开头那个画面或问题。
- 判断放最后，只说一句。前面都在演示，判断自然就落地了。创野小朱结尾只有一句：「检查和使用之间的每一毫秒，都是留给攻击者的门缝」。
- 方法类稿子，给一句观众能直接复制的原话。

### 原料不是成句

创始人给你的口述，是按事情发生的顺序讲的；稿子要按观众好奇的顺序重新排。先问自己：观众最想知道答案的那个反常是什么？把它放到最前面。然后对每个细节问一句：它在主线上起什么作用？答不上来就删，比如「拿了个二等奖，掌声挺热烈」。

### 自查（交稿前花一分钟）

1. 只看前 15 秒：一个第一次刷到的人，知道接下来为什么要听吗？
2. 每段结尾，观众心里有没有一个还没被回答的问题？
3. 全片是不是只用了一个例子？
4. 爆点那一句，观众能不能原样转述出去？
5. 有没有一句是在教育观众，结尾有没有给观众布置作业？改成摆证据、说「我的看法是」。
6. 这一篇新出现的行业词后面，有没有紧跟一句人话？
7. 按创始人的口吻念一遍：哪句念着别扭？改成他跟朋友聊天时会说的话。

## 5 写和观众试读

按选定的开头、主线、手册骨架、锁住的范文和上面的写法写全文，`save{content_id, base_version, title, body}`。`format_warnings` 有内容就改掉再存。

第一版存下后做一次观众试读：把本技能目录下 `viewer-test-read-prompt.md` 里的 `{{BODY}}` 换成正文。试读者只拿到这份提示词，不看规则、手册、立意和范文。按宿主选通道：
- 有子代理（Claude Code）：起一个不继承本会话的子代理，只给这份提示词。
- 没有子代理但本机有 `codex`：存成临时文件跑 `codex exec --skip-git-repo-check --sandbox read-only - < 文件`，最长等 8 分钟。
- 两样都没有：不试读，记 `status:"unsupported"`。不要回退到旧的 Codex 审稿。

结果用 `save{content_id, base_version, body:<它读的那一版正文>, test_read:{status, notes}}` 附在那一版上：`ok` 时 `notes` 是试读原文；超时、出错是 `failed`，`notes` 写原因。划走点超过 2 处：先自己改一次再存（最多一次），把两版和试读一起给创始人看；试读只是参考，不替他做决定。

## 6 改

创始人说改哪里就只改哪里，别的不动，改完 `save`，带 `feedback:{founder_words:<他这次的原话，逐字>}`。他只说了意见、正文暂时不改，也照样带 `feedback` 存（同一版正文），意见不会丢。意见是方向性的、没指具体句子：先给简短诊断和改动清单，等他确认再动稿。意见改变了主线、受众或体裁，就回第 3 步重出立意（换体裁时重新预览范文）。

改稿过程中不判断「以后是不是都这样」，也不问他。意见只管这一篇，跨稿的事留到定稿。

## 7 定稿

创始人说「定了」，调 `prepare_final{content_id, base_version, citations}`：把稿中每处引述、数字、对外部事实的断言对上证据编号，对不上的给空数组。类比和编的例子标 `kind:"example"`，我们自己的判断标 `judgment`，这两种不需要出处。`text` 要是整句。请创始人在工作台看清单、对没出处的项选保留或让你补，再点「定了」。「定了」只有他能点；之后再改正文，清单作废，要重新 `prepare_final`。

```json
{ "action": "prepare_final", "content_id": "…", "base_version": 3, "citations": [{ "text": "稿里逐字的一句", "evidence_ids": ["ev-d1"] }, { "text": "打个比方，……", "evidence_ids": [], "kind": "example" }] }
```

然后 `feedback_history{genre?}` 读以前各稿的意见，和这篇的比。同一个意思在另外至少一篇不同的稿里也出现过，才提升级，`propose_promotion{content_id, target, cites:[{content_id, index}…], text, note}`：
- `target:"playbook"` + `genre`：改那本手册的骨架，`text` 是改后全文；
- `target:"exemplar"` + `exemplar_id`：给范文加一条批注（改前 → 改后片段）；
- `target:"method"`：改写法里的一条。

只出现在这一篇的不提，不再生成档案规则。提了就告诉他「等你拍板」里有一件；批了以后，范文批注会生成范文新版本，写法改动只出一份补丁、显示「已批，等发布」，随代码发布才生效。`pending_lessons` 里有旧会话攒下的待批规则或手册提案时，照回执的 `next_action` 列给他。

## 「你定」

第 1 步或第 3 步创始人说「你定」：你可以自己选，但把选了哪个、为什么摆出来；`founder_words` 记「你定」原话。

## 版本号

写入都带 `base_version`：你最后读到的版本号（`start` 的 `progress.version`，之后每次回执里的 `version`）。回 `version_conflict` 说明中间有人改过稿，多半是创始人在工作台手改：读回执里的 `latest_body` 和 `diff`，在最新版上重改，带 `latest_version` 再交，不要拿旧稿盖回去。
