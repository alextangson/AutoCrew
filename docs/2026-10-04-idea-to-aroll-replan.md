# 从灵感到拍 A-roll：重新规划（草案，待创始人拍板）

2026-10-04。本文替代 `2026-10-04-writing-path-simplify-spec.md` 的思路：上一版是在旧流程上减关卡，这一版从创始人要的流程倒推，只留每一步真正需要的东西。

## 创始人要的流程

灵感 → 衍生 → 调研 → 找会爆的立意 → 写文案 → 改 → 拍 A-roll

## 设计原则

- **一个会话、一个 agent 做完一篇。** 怎么做写在一个技能里，按步骤走，不拆子代理，也不发令牌。
- **AutoCrew 只做三件事：**
  - 存东西：稿子和版本；
  - 给数据：账号哪些内容爆过、同系列最近讲过什么；
  - 核事实：引文要能在原网页里找到，数字要有出处。

  它不再管流程走到哪一步，不再出关卡，也不再管「谁能审谁」。
- **创始人只在三个点上表态：**
  - 选立意；
  - 改稿；
  - 说「定了」。

## 每一步

| 步 | agent 做什么 | 创始人做什么 | AutoCrew 提供什么 |
|---|---|---|---|
| 1 衍生 | 从一句灵感展开 3–5 个方向，每个一行：讲什么、给谁看 | 挑一个，或说「你定」 | 账号定位、受众卡 |
| 2 调研 | 查这个方向：有什么真事、真数据，同类视频怎么讲的、哪条爆了 | 不用管 | 搜索、抓网页、核对引文是否逐字出自原文 |
| 3 立意 | 给 3 个立意，每个包含：<br>① 我们的判断（一句）<br>② 给谁看<br>③ 开头 15 秒原话<br>④ 为什么可能爆：引账号数据或对标视频的真实数字<br>⑤ 4–6 行论证链 | 选一个，或用自己的话改 | 账号爆款数据（205 条发布数据）、同系列最近几条的主线（避免撞车） |
| 4 写 | 按选定的立意和论证链写全文，套用档案里的 9 条规则和口吻样本 | 不用管 | 档案（规则、口吻样本） |
| 5 改 | 按创始人的话改，改哪里就只动哪里 | 提意见，直到满意 | 保存每一版 |
| 6 定稿 | 列出稿里所有数字和引文的出处，给创始人过目 | 说「定了」，稿子进「等 A-roll」 | 数字核对、状态推进 |

衍生和立意两步，创始人说「你定」时 agent 可以自己选，但必须把选了什么、为什么选摆出来。

## 和现在比，拿掉什么

- 冻结要求、简报版本、要求一改就得重跑调研
- 四视角调研、每路令牌、凑齐才能综合、单独的「综合」一步
- 选题卡的 20 个字段（只留第 3 步那 5 项）
- 写稿包、领包、包过期
- 认领令牌：只留一个简单的锁，防止两个会话同时改同一篇
- 交稿修复轮、软门禁、提纲必填、手法目录、编辑实验注入
- 写手自审、审稿台、系列审查表、审稿轮次、修订预算

## 留下什么（每样都防过真出过的事）

- **引文必须逐字出自抓回来的原网页**：防编造引用。
- **数字必须有出处，定稿时逐条给创始人过目**：防编数字。这一项从「交稿时拦下」改成「定稿时把清单摆出来」，没出处的数字要么补出处，要么由创始人点头保留。
- **一手亲历只能来自创始人的原话或材料**：防冒充亲历。
- **档案的 9 条规则和口吻样本**：创始人的品味。
- **只学创始人亲手改过的稿**：今天修好的那个 bug。

## 怎么落地

- **新路径单独做，不拆旧系统。**
  - 一个新技能，替换 write-script 里写稿的部分。
  - 一个很薄的新工具，大约 4 个动作：取数据、存稿、核数字、定稿。
  - 存储、引文核对、数字核对这些现有代码直接复用。
- **旧流程先留着，不再被技能调用。** 新路径跑顺 2 周后，再删旧工具、旧界面里的对应部分。工作台里总编辑对话那条线一期不动。
- **上一版规格里正在做的 Codex 审稿任务系统停掉。** 已经提交的代码先不合并，等这版定了再决定哪些留下。

## 创始人拍板（10-04）

1. **独立审稿**：要。初稿交出后，由 Codex 审一遍，只看三件事：主线一句话说不说得清、观众有没有收获、开头抓不抓人。意见附在稿子旁边，不打回。之后的修改不再重审；创始人可以手动点「再审」。
2. **没出处的数字**：定稿时列给创始人看，由创始人决定补出处还是保留，不拦着定稿。
3. **平台**：先只做抖音口播。其他平台继续走旧流程。
4. **今天上线的五路选题会**：新路径不走。第 3 步里创始人用原话选定立意，这条记录本身满足存盘入口守卫（first-body-guard），即「第一份 AI 正文必须有创始人选定的立意」。

## 实现规格

### 新技能：重写 `skills/write-script/SKILL.md`

按 6 步写，以创始人的视角为主，每步写清楚：做什么、停下来问创始人什么、调用哪个动作。要求如下：

- **衍生和立意**：创始人说「你定」时，agent 可以自己选，但要把选了哪个、为什么选摆出来；`founder_words` 照录「你定」原话。
- **改立意**：改稿中途，创始人的意见如果改变了主线或受众，就回到第 3 步重新出立意，已有调研保留。
- **范围**：一个会话只做一篇。讲解片等其他作品另开会话。
- **其他技能同步改**：
  - `topic-meeting`：注明抖音口播走 write-script，五路选题会只用于其他平台。
  - `video-session`：「选题 → 写稿自审」改为调用新流程。
  - MCP 初始化说明（`mcp/writing-instructions.ts` 与 server instructions）：写抖音新稿的路线改成新工具。

### 新工具：`autocrew_draft`（薄工具，复用现有代码）

| 动作 | 输入 | 做什么 | 返回 |
|---|---|---|---|
| `start` | `inspiration`；或 `content_id`（接手已有稿） | 建选题和稿件（平台固定为 douyin，状态为写稿中），再取上下文 | `content_id`，加三份上下文：<br>① 档案（定位、受众卡、当前平台生效的规则、口吻样本）<br>② 账号爆款：最近 90 天按播放和 5 秒留存排序的前 10 条，含标题和指标<br>③ 同系列最近 5 条的「主线 + 开头」<br>接手已有稿时，另附当前进度：是否已选立意、有几版 |
| `read` | `content_id`, `url` | 抓网页正文，复用现有抓取 | 正文摘要 + `page_id` |
| `cite` | `content_id`, `page_id`, `quote` | 逐字核对引文，复用 `validateQuote`；通过就记入这篇的证据台账 | 证据编号；不通过时附原因 |
| `angle` | `content_id`, `main_line`, `for_whom`, `opening`, `why_viral`, `chain[]`, `founder_words` | 记下创始人选定的立意，写入存盘入口守卫认可的决定记录。可重复调用，即改立意 | 立意版本号 |
| `save` | `content_id`, `title`, `body`, `note` | 存一版。第一版存下后，后台启动一次 Codex 审稿 | 版本号、格式提醒（`[停顿]`、画面提示）、Codex 审稿状态 |
| `review` | `content_id`, `rerun?` | 查 Codex 审稿结果；`rerun:true` 再审当前版 | 运行中 / 结果 / 失败原因 |
| `finalize` | `content_id`, `founder_words`, `keep_unsourced[]` | 列出稿中所有数字和引文的出处，复用 number-gate 的解析和匹配。<br>有没出处的数字、且未列入 `keep_unsourced` 时，只返回清单，不推进状态。<br>否则把稿件推进到「等 A-roll」 | 清单，或推进后的状态 |

**存稿和学习**

- `save` 一律记为 AI 写入（`provenance: model`）。
- 创始人在工作台里的手改照旧记为创始人，口味学习不变。

**并发锁**

- 每篇稿只有一个写入方：第一次 `save` 或 `angle` 时自动上锁。
- 别的会话来写，返回「被谁占着、闲置几分钟」。闲置满 10 分钟可以接管。
- 不要求认领令牌。

**定稿的创始人确认**

- 两个入口：
  - 工具入口：`finalize` 必须带 `founder_words`，技能要求照抄原话。
  - 工作台入口：「定了」按钮，写入来源为 `HUMAN_WRITE`。

**Codex 审稿**

- **运行器**：专用，不和生图共用代码。
  - 跑 `codex exec`，用只读沙箱，带 `--skip-git-repo-check`；
  - stdout 和 stderr 分开收，输出有上限；
  - 超时 8 分钟。
- **输出格式**：严格 JSON，三项结论各给「过 / 不过」，附一句理由；凡是「不过」，都要逐字引用原文。另有最多 8 条建议。
- **校验**：引文在稿中找不到时，重试一次，仍失败就记为审稿失败。
- **失败要看得见**：Codex 没装、没登录、超时、输出非法时，在稿件和 `review` 动作里显示原因原文，可以重试。
- **重启**：服务重启时，正在跑的审稿标为失败、可重试。
- **并发和忙碌判断**：
  - 全局同时最多跑 2 个审稿，多出来的排队；
  - `/api/update/busy` 要把正在跑的审稿算进去。
- **结果绑定**：审稿结果绑定版本号。之后又存了新版，旧结果照样显示，并标注「审的是第 N 版」。
- **审稿提示词**：单独放一个文件。内容包括：
  - 三项判据；
  - 档案规则作为参考；
  - 「外部资料最多 2 处、主线必须是我们自己的判断、段落不跳出论证链」作为第 1 项的判法。
- **自检**：`autocrew doctor` 加一项，检查 codex 命令可用且已登录。

**写作规则怎么到 agent 手里**

- `start` 返回的档案规则就是全部写作规则。
- 技能里不再另写一套写法。只补口播格式这一条：纯朗读正文，不写画面和停顿标注。

### 边界

| 情况 | 处理 |
|---|---|
| 平台不是 douyin | `start` 拒绝，提示改走旧流程 |
| 会话中断后再来 | `start{content_id}` 返回当前进度，接着做 |
| 接手旧流程的稿（例如卡帕西那篇） | 可以直接 `save` 新版，不强制补立意；需要改立意时再调 `angle` |
| 没选立意就存第一版 AI 正文 | 被存盘入口守卫拒绝，错误信息指向 `angle` |
| 引文对不上原网页 | `cite` 拒绝，说明没找到哪段 |
| 定稿时审稿还在跑或已失败 | 照样能定稿，清单里注明审稿状态 |
| 两个会话同时写 | 后来的一方收到「被占用」，闲置 10 分钟后可接管 |
| 正文为空或明显被截断 | `save` 拒绝 |

### Codex 会审吸收（11 条，与上文冲突时以本节为准）

1. **「定了」只能由创始人在工作台点**（会审 #1、#5）。
   - 现有不变量：AI 不能批准稿件，这是 09-29 堵住的批准伪造漏洞。
   - `finalize` 改名为 `prepare_final`，只做准备工作：
     - 生成数字和引文清单；
     - 绑定当前正文哈希；
     - 把稿件推到「等你认稿」（draft_ready）。
   - 工作台在这篇稿上显示清单和「定了」按钮。创始人点下按钮时：
     - 核对正文哈希，确认还是清单对应的那一版；
     - 写入现有的人工批准决定（`production-hooks` 那套）；
     - 推进到「等 A-roll」。
   - 清单生成之后正文又被改过，按钮失效，要重新 `prepare_final`。
   - 技能里写明：创始人在对话里说「定了」，agent 就调 `prepare_final`，并把工作台链接给他点。
2. **视频交接认创始人定稿，不伪造审稿通过**（#2）。交接验收（`acceptance.ts`）新增一种可接受状态：「创始人已对当前正文哈希定稿」。Codex 审稿是提示性质，不参与交接判断。
3. **引文映射**（#3、#8）。
   - `prepare_final` 要求 agent 提交「事实句 → 证据编号」映射，规则如下：
     - 稿中每处引述、数字、对外部事实的断言都要对上；
     - 对不上的标「未核验」，列在清单里给创始人看。
   - 创始人在清单里保留的未核验项，写成显式的「未核验引用」，进 `citations.json`，满足交接的出处覆盖要求。
   - 标题、封面字、目标时长这些制作决定，仍由后续现有的人工步骤补齐，本期不动。
   - 技能保留硬规矩：「没有素材不编亲历；一手材料只来自创始人原话或材料」。`start` 返回时，一手材料单列。number-gate 判为 `needsHuman` 的数字也进清单。
4. **只用一套占用机制**（#4）。沿用现有 claims，令牌由服务端按宿主会话内部保管，agent 不用传。`save`、`angle`、`cite`、`prepare_final` 都在写锁内检查占用；接管时换代，旧会话迟到的写入一律拒绝。
5. **清单项的身份**（#5）。清单每一项有稳定编号，由字段、出现位置和上下文哈希组成。重复提交幂等。
6. **立意记录用现成接口**（#6）。
   - `angle` 调 `recordFounderAngle(topic, main_line, founder_words)`。
   - 存稿时用 `_provenance: modelWrite(host, { direction: main_line })`。
   - 受众、开头、论证链作为附加数据另存，不造假卡片或假简报。
7. **read 返回原文**（#7）。返回原文片段，不返回摘要。每篇稿的抓取快照持久化，证据编号的序号可以跨重启延续。
8. **爆款数据**（#9）。复用 `listLatestOutcomes` 和 metric-review 的可疑值过滤，规则如下：
   - 只取抖音，按发布日期取最近 90 天；
   - 播放和 5 秒留存各给一份排行，附快照日期和样本数；
   - 缺失的指标照实标缺失，不补。
9. **接手已有稿的范围**（#10）。
   - 只接手处于写稿阶段、且有真实正文的稿。
   - 占位稿要先补立意。
   - 已冻结进制作的稿，返回现有的「重开」流程说明，不擅自重置。
   - 已发布的稿不接手。
10. **审稿任务去重**（#11）。
    - 每篇稿、每个正文哈希，同一时间只能有一个审稿任务，重复请求合并。
    - 每次尝试都有编号。
    - 用一个小的有界队列，同时最多跑 2 个；重启后，排队中的任务恢复，运行中的标为失败、可重试。

### 不做

- 不动工作台总编辑对话（引擎写稿）那条线，不动旧工具，不动其他平台。
- 不做进度看板。
- 不加审稿维度，不加关卡。
