# 反常识判断

大多数人默认的一个做法，被一份可靠的数据或一个真实现象推翻了，我们再往前推一步：那应该怎么做。观众要的是「原来我一直做反了」那一下。

## 什么时候选它

- 手上有一个能核验的反常识证据：实测数据、官方实验、可以复现的现象。先用 `verify_quote` 核一遍，核不过就不选这一类。
- 这个证据推翻的是观众正在做的某个具体动作，不是一个抽象观念。
- 我们能从证据里推出一个原作者没明说的判断。只是转述原作者的结论，就成了记者稿。

## 骨架

这是唯一允许判断先说的体裁，和「写法」里「判断放后面」冲突时，以这里为准。反转本身就是钩子。

- **开头**：第一句点出观众正在做的那个具体动作，带上产品名或按钮名。接着亮证据（谁、做了什么、规模多大），然后说出反转。判断用「我的看法是」摆出来，不用教育人的语气。
- **中段**：把这个做法实际改变的东西拆成两层，每层配一组数，原来的直觉为什么错就讲清楚了。证据只当配角，主线是我们的推论。做法从推论里推出来，三到四步，每步配一句原话。说完「别这么做」，要补一句什么时候可以这么做。
- **收尾**：把推论往外推一层，推到观众自己身上，最后留一个回扣开头动作的问题。

## 本体裁范文

- `bench-zuowaiwai-transformer`（左歪歪，赞 6 千，数据弱）：只学一样，把技术讲成人物故事。
- `bench-xiaotian-feishu-cli`（小天，归在信息差体裁）：前沿判断不爹味的顺序，证据 → 拙见 → 演示。
- 本体裁还缺一篇数据好的范文。

## 红线

- 数字只用核验过的，单位和口径照原文。结论不能比证据走得更远。
