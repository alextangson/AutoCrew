# 一条视频一张卡 + 状态自动推进 + 稿件页「下一步」（2026-10-12 草案，待创始人确认边界清单）

## 背景（10-11/12 真实案例）

《10月17日，前海见》一条视频在系统里变成 5 条稿子：抖音一条挂着成片 / 封面 / 发布；视频号、小红书、B站各一条空壳（Codex 为「登记」建的，状态停在选题）；公众号一篇独立文章。
- 稿件页顶部平台标签显示「视频号 选题 / B站 选题」，跟实际（四平台都发了）对不上。
- 稿件页没有往下走的入口，只有「返回修订 ▾」下拉；创始人 01:38 用它 8 秒内连推 5 次状态把公众号文章推到已发布。
- 剪完、发完的事实系统里都有，但看板列靠人推。

创始人已定（10-12）：
1. 网页定位 = 看进度 + 偶尔手动；审核都在对话里。
2. 同一条视频发多平台 = 一张卡，平台是卡上的标签；内容不同的（公众号文章）照旧单独一张卡。
3. 本条三个空壳已移入回收站（可恢复）。

## 根因（代码）

- `skills/publish-content/SKILL.md:59` 要求「每个平台独立一个条目，不能四平台共用一个 content_id」——这是空壳的来源。
- `Content.videoKit` 只有一个平台（`local-store.ts:231`），`pre_publish` / 发前检查按 `content.platform` 校验（`pre-publish.ts:103,155,174`）——结构上逼着一平台一条。
- 回执本来就按平台分槽存在一条稿里（`receipts.ts`，`slot:<轮>:<平台>`），对视频来说多建的平台稿是多余的。
- 视频稿没有当前正文的认稿记录时，看板一律放「写稿中」，不看回执（`explain.ts:123-126`）。
- 编辑器顶部平台标签用原始 status（`TopicNavigator.tsx` / `lib.ts:40`），不是推导出的阶段。
- 稿件页 `StageAdvance` 下拉直接推 status；`drafting` 时默认按钮是「返回修订」（`StageAdvance.tsx` 排序 bug）。
- 已有现成的推导「下一步」：`card-next.ts` + `CardNext.tsx`（走 inbox decide，不推 status）。

## 方案

### A. 一条视频一条稿，平台是它的发布目标
- 视频稿新增「发布目标平台」列表（默认取发布计划 `publish-plan.json` 里的平台；没有计划时取稿件平台）。
- `pre_publish` / 发前检查 / videoKit 改成按「这条稿 + 目标平台」校验，不再要求 `content.platform === 平台`。
- 改 `skills/publish-content/SKILL.md` 与示例计划：四平台共用一条 content_id；禁止为登记 / 发布新建平台稿。
- `create_variant` 对视频平台：如果同一选题已有视频稿，拒绝再建视频平台的变体，回一句「同一条视频发多平台不用新建稿，在发布计划里加平台」。文字平台（公众号等）不受影响。

### B. 看板卡 = 一条视频
- 卡片上显示平台标签：每个目标平台一个（未发 / 已定时 / 审核中 / 已公开 / 被驳回），数据来自回执槽。
- 编辑器顶部平台标签改成：视频稿一个标签组（抖音·视频号·小红书·B站 各自状态），文字稿各自一个标签，状态都用推导出的阶段，不用原始 status。

### C. 状态由事实推进
- 有发布回执（任一平台 live）→ 已发布，即使这条稿没有当前正文的认稿记录（导入的、先剪后认的）。卡上标一句「没走认稿」提醒，不挡推进。
- 推导出的阶段每次读看板 / 稿件页时现算（现在只在写入时投影，会滞后）。
- 文字稿（公众号）照旧按 status 走，但见 D 的按钮。

### D. 稿件页「下一步」取代状态下拉
- 顶部「返回修订 ▾」下拉删掉；换成一张「现在轮到你 / AI 在做」卡（按 `~/.cache/autocrew-redesign/draft-page-edges.md` 第 1–6 条，草图见 `review-preview/稿件页草图/`），卡里只有当前阶段的一个主按钮，复用 `card-next.ts` 的决定（认稿 / 看成片 / 选封面 / 标已发）。
- 往回退（退回修订、撤回认稿）收进卡片右上角「更多」菜单，带二次确认。
- 文字稿：同一张卡，按钮按 status 给一个（认稿 → 标已发布），不再给五个状态任选。

## 边界清单（= 验收清单，待确认）

1. **旧数据**：已有的「一条视频多条平台稿」不自动合并；看板上同选题、同成片的平台稿归到主稿卡下显示，主稿 = 挂着成片的那条。没有成片的空壳在看板上标「空壳，可删」，删要你点（进回收站）。
2. **只发了部分平台**：卡上未发的平台显示「未发」，不算整条已发布？——**按「任一平台发了就算已发布、卡上标出哪几个没发」**（现在 D1 就是这个口径）。
3. **某平台被驳回**：卡留在已发布，被驳回的平台标红并在卡上写原因。
4. **同一选题既有视频又有公众号**：两张卡，卡上标「同主题」互相跳转。
5. **没走认稿就发了**（本次就是）：照样到已发布，卡上一行「没走认稿」，不挡。
6. **在稿件页编辑时状态在别处变了**：卡片跟着切到新阶段，正在编辑的正文不被打断，有未保存改动只提示。
7. **下一步按钮重复点 / 网络失败**：按钮点下后变灰直到返回；失败在卡里写原因 + 重试，不静默。
8. **往回退**：二次确认；退回认稿 = 现有撤回逻辑（已认的稿被撤回会记录）。
9. **读取中 / 读取失败 / 稿件被删**：骨架先出；失败一行错误 + 重试；被删整页一行说明 + 回看板。
10. **AI 想新建平台稿**：视频平台被拒并告诉它在发布计划里加平台；文字平台照常。

## Codex 会审吸收（2026-10-12，以下覆盖上文冲突处）

1. **videoKit 改成按平台存**：`videoKits: Record<平台, VideoKit>`，逐平台原子更新，保留 draftHash / registerHash；旧的单个 `videoKit` 读时迁移成 `{[kit.platform]: kit}`；所有读写方（pre-publish、publish.ts、剪贴板）一起改。先改后端契约，再改技能文案。
2. **每个平台的发前检查照旧各管各**：check_id、载荷指纹、账号、排期、例外、提交时的把关结论都按平台保留。「没走认稿就发了」只影响显示，不放行任何新的提交。
3. **按平台的动作必须显式带平台和轮次**：卡上「标已发」、`confirm_published`、纠正都带规范平台名，不再默认取 `content.platform`。
4. **已发布 ≠ 没事可做**：卡片的总阶段（任一平台已投出 = 已发布）和「各平台还剩什么」分开。已发布后，未发的平台仍有「准备发布 / 标已发」，被驳回的有「重新提交」，待核的回执有「确认 / 纠正」。
5. **只有回执、没有认稿时**：列 = 已发布，带 `no_script_approval` 标记；**不**冻结正文、**不**补写认稿、**不**改正文。`topic_saved` 的稿只有在有已投出回执时才上看板。
6. **三种适配器**：本体启用的视频稿 → 推导的下一步（card-next）；影子模式 / 被排除的视频稿和文字稿 → 旧流转（服务端 preflight 照旧），主按钮取「下一个合法状态」里最靠前的那个（修 drafting 默认成「返回修订」的排序 bug），其余合法流转放进「更多」。不删任何现有恢复路径。
7. **「同一条视频」按制作认，不按选题认**：只有当来源稿已有制作记录（原片 / 成片事实）时，才拒绝为它建视频平台变体，提示在发布计划里加平台；同选题另做一条不同的视频，用 `create_variant` 带 `distinct_video: true` 放行。
8. **旧数据不归组**（覆盖边界第 1 条）：不做虚拟合并；旧的多条平台稿照旧各是各的卡，空壳 `topic_saved` 本来就不上看板。
9. **「更多」里的往回退逐个对应现有命令**：退回修订（只在制作前）、撤回成片 / 封面批准（revoke_approval）、某平台纠正发布（correct_publish）、重开这一条（reopen，开新一轮、解冻）。每个都写清后果、二次确认、带当前代次。
10. **正在编辑时外部变了状态**：有未保存改动就把编辑器保持挂载直到保存 / 丢弃；进度卡单独刷新。认稿绑定的是你看过并保存的那份正文。
11. **新鲜度**：看板读已经现算推导，问题在编辑器顶部平台标签用原始 status → 改成用推导出的阶段；不新增读时写入。
12. **已发布的定义**：任一平台槽是已定时 / 审核中 / 已公开 / 应已公开 = 已发布。全部被驳回 → 回待发布，卡上红字「全部被驳回」+ 原因。待核、读不到的状态照原样显示，不显示成「未发」。
13. **目标平台不新增存储**：= 发布计划里的平台 ∪ 已有回执的平台；回执独立显示，计划删掉平台不隐藏已有回执。保留「每轮每平台一个账号」的现有限制。
14. **文字稿按钮**：每个按钮对应一个服务端支持的流转，保留 preflight、创始人身份、正文新鲜度；标已发布仍要明确确认。
15. **共用的防重复动作执行器**：点下变灰，失败在卡内常驻显示原因 + 重试（不只弹 toast）；补上缺文件恢复、登记失败、待核回执确认这几个动作；「AI 在做」只在认领租约有效且有最近写入时显示，否则写「AI 已 N 小时没动静」。
16. **上线顺序**：后端契约（videoKits、按平台动作、推导字段）向后兼容先上 → 前端 → 最后改技能文案和变体限制。同一分支内按这个顺序分提交。

## 本批不做
- 文字稿（公众号）稿件页的完整改版（只换掉状态下拉）。
- 合并旧的多条平台稿的数据迁移（只做显示归组 + 可删）。
- 稿件页里的数据图表。
