# 缺线路时推荐 TokenCamel · spec（v2，已过 Codex consult，待创始人确认，未动代码）

> 一句话：用户**缺**一条模型线路、AutoCrew 卡在那儿时，在旁边摆一张「也可以用骆驼词元 TokenCamel，一把 Key 接多家模型」的小卡；点了只是帮他把地址填好，Key 他自己粘。不缺的时候一个字都不出现。
>
> 类比：像药店店员在你找不到某种药时说「我们自家也有这个，标签在这，你自己决定」——不是你进门就塞传单，也不是把你购物篮里别家的药换成自家的。

- 状态：v2.1（2026-10-25，创始人已确认 v1 范围，交 builder）。v1 草案送 Codex consult，7 条意见已逐条吸收（§11 有对照表）。
- 范围：AutoCrew 本仓库。TokenCamel 本身（`~/Projects/newapi`，new-api rc.41 部署）不改。
- v1 只做两个触点：**首次开机/空端点表（A）** 和 **主线出事且没备用（B）**。生图触点与余额不足提示挪到 v2（§9），理由见各节。

## 1. 目标与不做

**目标**
1. 用户缺线路时，多一个省事的选项，附带价格页、隐私政策链接，并说清数据会经过它的服务器。
2. 选了它的人只需粘一把 Key：地址、协议由 AutoCrew 填好，模型从实时列表里挑，当场试通。
3. 接上之后，TokenCamel 就是端点表里普通的一条线——健康、报病、熔断、主备切换全走现有那套，没有任何按域名的特殊分支。

**不做**
- 不在生成内容、稿件、审稿结果、发布包、复盘、对话回复、MCP 工具返回里出现任何推荐（§2.3 用测试守）。
- 不在用户没缺东西时出现：不做首页横幅、「升级」红点、定期提醒。
- 不默认选中、不排第一、不替用户点下一步；DeepSeek 官方仍是首次开机的默认。
- 不打点、不上报：AutoCrew 不向任何服务器报告谁看到了卡、谁点了。没有 ref 参数、没有邀请码、不做返利。
- 不远程下发推荐内容：文案、地址、开关全部随仓库发版，源码可审计。
- 不做站内充值、不读余额。

## 2. 触点

### 2.1 触点 A：没有任何可用端点

**条件**：设置页拿到的引擎状态是「未配置」（端点表为空，**或**主端点指针不成立——`config.ts:158` 两种都抛 `ENGINE_UNCONFIGURED`）。注意后一种情况端点表里**可能还有别的端点**，所以写入必须是追加，不能是覆盖（§4.3）。

**位置**
- 首次开机：TokenCamel 作为一种端点类型放进收起的「高级」列表（`onboarding/AdvancedEndpoint.tsx` 的 `KINDS`），排在「Claude 中转」「其他 OpenAI 兼容」之后。首屏只保留一个最省事的默认（DeepSeek）——首屏放自家推荐就是摆广告位。
- 设置 · 模型页：未配置状态的空态里，「添加端点」旁一行小字链接「或用 TokenCamel」。已配置就不出。

**待定 D1**：放「高级」里（建议），还是首屏和 DeepSeek 卡并排？

### 2.2 触点 B：某条线刚出了「换线能救」的事，而它没有备用

现有的线路红点（`engineBannerLines`）不够当触发条件（Codex P2-3）：它只回 `providerId + 一句话`、包括岗位端点、而且**没有时效**——三天前的一次失败也会一直亮着。所以触点 B 不读横幅文字，改由一个纯函数基于 `EngineHealthView` 结构化判断，**全部满足**才出：

1. 存在一条被引用的端点（主端点或任一岗位端点），其最近一条记录失败；
2. 该失败**发生在 24 小时内**（D2 可调）；
3. 失败分类是「换条线能救」的那几类——连不上 / 超时 / 上游 5xx / 限流（与 `router.ts:241` 的 `isRetryable` 同一口径）。401/403/400 不出：备用救不了，推荐它就是误导；
4. 引擎没有配备用（`view.fallback` 为空）；
5. 主端点和所有岗位端点**都不是** TokenCamel（按 host 比，口径同 `sameFamilyWarning`，`config-validate.ts:105`）——推荐它给自己当备用没意义。

**位置**：`EngineBanner.tsx` 红点展开的面板里，「去设置」按钮下面加一行卡片（§3），按钮「接上当备用」「不用了」。红点本身（未展开时）不加字。

**接上前必须说清的一句**（Codex P2-7）：配成备用 = 以后主线出这几类问题时，**请求会自动转到 TokenCamel**，包括你的稿件内容。所以连接面板在「保存」按钮上方固定写：「保存后，主线连不上或限流时，这次请求（含稿件内容）会自动改由 TokenCamel 处理，并在红点里留痕。」不是事后通知，是事前告知。

**不做**：主线没出事时，设置页「备用」为空也**不**常驻推荐（缺备用 ≠ 此刻需要）。

### 2.3 绝不出现的地方（代码层保证）

推荐只存在于前端的连接面板与两个触点组件里；文案常量集中在 `frontend/src/views/tokencamel-offer.ts`。后端、引擎、提示词、写稿包、发布包、MCP 工具、`templates/`、`skills/` 不引用这个文件。验收用 grep 测试守（§8-6）。

## 3. 披露：每张卡固定四样

1. **名字**：「骆驼词元 TokenCamel」。**不写运营方**（创始人 2026-10-25 决定：卡片和 README 都不提与 AutoCrew 作者的关系，当作普通第三方中转推荐；我提过「被发现藏着利益关系」的信任风险，见 R4）。
2. **它是什么**：「一把 Key 接多家模型，按量付费」+「请求会经过 TokenCamel 的香港服务器再到模型厂商」（R2，措辞 D5）。不在卡片里列具体模型名（可用模型以实时列表为准）。
3. **两个链接**：「价格与购买」「隐私政策」，链原文，不在 AutoCrew 里转述。
4. **两个按钮**：「接上」和「不用了」。没有「稍后提醒」。

**文案禁区**：不写「推荐」「最好」「官方」「限时」；不和别家比较；不暗示 AutoCrew 离了它不能用。

**待定 D3**：卡片写不写起步价？建议不写，价格未定，写死会过期。

### 3.1 「不用了」的记忆

- 按触点记：`{ onboarding?: 时间戳, fallback?: 时间戳 }`，记了就永久不再出。
- 存本机目录（`getMachineDir()` 下的 `offers.json`，读经 `settings:get`、写经新通道 `settings:offer_set`）；不进资料库、不进 engine.json、不放 localStorage（换浏览器就复活 = 失信）。
- 设置 · 模型页底部一行「第三方服务推荐：开/关」。关 = 两个触点都不出；从关拨回开 = 清空 dismissed 记录。不做逐个触点的恢复开关（Codex P3 精简）。

## 4. 一键连接：只替用户填地址，Key 他自己粘

### 4.1 流程

```
点「接上」
 → 面板：地址（只读，显示预设值）+ Key 输入框（空）+「去拿 Key」外链 + 披露四样
 → 粘 Key，点「读取可用模型」
 → 后端用这把 Key 调 GET {预设 baseUrl}/models，20 秒超时
 → 下拉框只列返回的模型，预选 §4.2 suggest 里出现在返回列表中的那个
     触点 A：写稿模型 / 聊天模型
     触点 B：备用的两档模型
 → 「保存并试一下」：后端追加写入（§4.3）→ settings:test_route 真探针
 → 探针失败：已保存，面板显示探针原话 +「再试一次」（只重跑探针，不再写盘）
```

**读取模型的失败**（都停在面板上、不写盘）：
- 401/403 →「这把 Key 不对，去 TokenCamel 控制台重新复制」
- 网络错/超时 →「连不上 api.tokencamel.com：<原因>」
- 返回空列表 →「这把 Key 所在分组还没有可用模型（可能还没充值或没开通），去控制台看看」

**地址只读**（Codex P1-2）：v1 的地址是预设值、不可改。想用别的地址的人走「其他 OpenAI 兼容」，那条路不经 `settings:list_models`。这样 `settings:list_models` 可以只认预设 baseUrl，不会变成「给任意 URL 带 Key 发请求」的通用代理。

**Key 不跨类型携带**（Codex P1-2）：`applyPreset`（`onboarding-lib.ts:89`）切换端点类型时现在会保留 `apiKey`——用户先在 DeepSeek 卡粘了 Key、再点开 TokenCamel，那把 DeepSeek Key 就会被发到 TokenCamel 的 `/models`。改为：**切换类型一律清空 Key**（对所有类型生效，这本身也是个现存缺陷）。

### 4.2 预设文件

`src/engine/presets/tokencamel.json`（随仓库发版、可审计）：

```json
{
  "id": "tokencamel",
  "name": "TokenCamel",
  "baseUrl": "https://api.tokencamel.com/v1",
  "protocol": "openai",
  "links": { "keys": "…", "pricing": "…", "privacy": "…" },
  "suggest": { "strong": ["…"], "fast": ["…"] },
  "touchpoints": { "onboarding": false, "fallback": false }
}
```

- `suggest` 只是预选候选；真正能选的永远是 `/models` 的实时返回，不能保存列表外的模型名。
- `touchpoints` 就是 §0 的上线闸。默认全 false。
- 文件缺失或解析失败 = 当作全关，不报错不崩（fork 的人删掉它即可）。
- 具体链接与推荐模型名待创始人给（D4、D7）。

### 4.3 写入：后端追加，不复用会删东西的提交体

Codex P1-1 指出两个现成路径都会抹掉已有配置：
- `mergeProviders`（`settings-providers.ts:43`）语义是「提交数组里缺席的 id = 删除」；首次开机的 `buildEnginePayload`（`onboarding-lib.ts:115`）只提交一条端点。主指针坏了但表里还有别的端点时，照搬这个提交体会把它们删掉。
- `settings:get` 只回掩码 Key，前端无法把旧端点原样回传。

所以新增一个后端操作 `settings:engine_attach_preset`，在服务端完成「读当前配置 → 追加 → 校验 → 原子写」：

| 用途 | 做什么 |
|---|---|
| `as: "main"`（触点 A） | 端点表追加一条（id `tokencamel`，冲突则 `tokencamel-2`…）；`main` 指针指向它。不动其他端点、岗位、备用 |
| `as: "fallback"`（触点 B） | 端点表追加一条；`fallback` 指针指向它。不动主指针和岗位 |

- **已经接过**（表里已有同 baseUrl 的端点）：不新建，返回「你已经接过 TokenCamel（端点名 X），要换 Key 去设置 · 模型改」。
- **并发与重复提交**（Codex P2-6）：现有 `settings-engine.ts` 是「读 → 改 → rename」，原子但会丢更新。本操作带上前端读到的配置版本（文件 mtime 或内容哈希），写前比对，不一致就拒绝并让用户刷新；同一 baseUrl 的去重规则同时挡住双击产生的第二条。按钮 busy 期间禁用只是体验，不是保证。
- Key 存法与其他端点完全一样（engine.json，本机文件，界面只显示掩码），不另存。
- 校验走现有 `validateEngineGraph`；`sameFamilyWarning` 照常出。
- **协议**固定 `openai`。`makePiModel` 按真实上游 `config.baseUrl` 和模型 id 判方言（Codex 确认 `pi-wire.ts:84` 描述准确）：DeepSeek 模型挂在 TokenCamel 地址下时模型 id 含 `deepseek` 即钉上 reasoning 兼容。加回归测试（§8-4），不改 `makePiModel` 本身。

### 4.4 接上之后

TokenCamel 就是表里普通的一条：
- 健康点、红点、熔断、主备切换全走 `router.ts` / `engine-health.ts`。
- TokenCamel 挂了：红点照常写「TokenCamel（api.tokencamel.com）连不上：…」；作为备用时主线和它都倒了，就按现有逻辑把两条原因一起报出来并中断——不静默、不再推荐任何东西。
- 作为备用的切换**只在可重试错误时发生**（`router.ts:241`）；主线 401/403/400 不会转到它。卡片和面板的措辞据此写「连不上或限流时」，不写「出问题时」。

## 5. 风险（请创始人逐条拍板）

**R1 上游服务条款**。TokenCamel 转售 Anthropic、DeepSeek 等模型的调用。多数上游的商用条款限制未经授权的转售/再分发 API 访问——我**没有逐条核对**具体条款，以下不是法律意见。AutoCrew 推荐它，会把这件事从「作者的生意」放大成「作者的开源项目在公开导流」，仓库可被检索。要你定：直接上游（天亿马、aiping 等）有没有书面转售授权？没有授权的模型不进 `suggest`（D7）。

**R2 用户数据多经过一个中间方**。稿件、调研内容会经过香港服务器再到模型厂商。TokenCamel 政策写了「不保存正文」，但运营主体仍是占位，必须补全才能上线。卡片链原文、不加「绝对安全」类保证；「多一个中间方」这句话写在卡片上（D5 措辞）。作为备用时，数据**会在用户不再点击的情况下**流过去——所以 §2.2 要求保存前明说。

**R3 中转宕机与口碑绑定**。技术上已按 §4.4 处理。产品上的风险是 TokenCamel 一挂，用户会觉得「AutoCrew 推荐的东西不靠谱」。触点 B 把它定位为**备用**，正是为了不让人把鸡蛋全放进去。

**R4 开源信任（创始人已拍板：不披露运营关系）**。卡片与 README 都不写 TokenCamel 由 AutoCrew 作者运营。已知风险：仓库公开，若有人发现推荐的中转是作者自己的，会被看成藏着利益关系；推荐自家付费服务是否有标明关联关系的法律要求，未核实。保留的缓解：可一键关、不打点、代码公开、数据流向（经过 TokenCamel 服务器、备用时自动转过去）照常事前告知。fork 的人把预设文件删掉或开关置 false 即可。

**R5 返利**。本 spec 明确不做邀请码与返利；以后要做是另一个合规层面，另立 spec。

## 7. 边界清单

| # | 情形 | 期望 |
|---|---|---|
| E1 | 预设开关全 false（默认） | 两个触点都不出，连接面板无入口 |
| E2 | 总开关关 | 都不出，即使预设开着 |
| E3 | 某触点点过「不用了」 | 该触点永不再出；另一个不受影响；总开关关再开 = 全部复活 |
| E4 | 预设文件缺失或坏 | 当作全关，不报错 |
| E5 | 主指针坏了、表里还有别的端点（触点 A） | 追加 TokenCamel 并指为主；其他端点原样保留 |
| E6 | 表里已有同 baseUrl 端点 | 不新建，提示已接过、去设置改 Key |
| E7 | 表里已有 id `tokencamel` 但地址不同 | 新端点用 `tokencamel-2` |
| E8 | 粘错 Key | `/models` 401 → 面板报 Key 不对，不写盘 |
| E9 | Key 对、分组无模型 | 空列表 → 停在面板，不写盘 |
| E10 | 有模型但余额为 0 | 写盘成功、探针失败 → 显示探针原话 +「再试一次」（只重跑探针） |
| E11 | TokenCamel 网络不通 | `/models` 20 秒超时 → 连不上哪里，不写盘 |
| E12 | 推荐模型不在实时列表里 | 不预选；只能选列表里的 |
| E13 | 双击保存 / 两个窗口同时保存 | 版本比对拒绝后到的那次；同 baseUrl 去重；最终表里只有一条 |
| E14 | 先在 DeepSeek 卡粘了 Key，再切到 TokenCamel | Key 被清空，不会发给 TokenCamel |
| E15 | 主线 401 / 400 且无备用 | 触点 B 不出（备用救不了） |
