## 2. 在哪一步做最省、最顺

**结论：中文成片审过之后马上自动开跑，不在剪中文版时同时做；但剪中文版时顺手留好三样「原料」。**

- 不并行做的原因：中文成片在审片时还会改。英文版里最贵的两步（配音、对口型）都绑在成片上，中文一改就得重做、重花钱。等中文审过再做，一次做对。
- 不再「做完很久以后再说」的原因：隔得越久，接手的 agent 越要重新读一遍项目，token 全花在重新理解上。
- 省 token 的关键不是时机，是**把这次手工做的步骤都变成脚本**：切口型片段、按词重排字幕、按超时补 B-roll、动画换字重渲染。脚本跑不花模型 token，agent 只做两件要判断的事：英文脚本怎么写、补时用哪段 B-roll。

剪中文版时顺手留的三样原料（Codex 技能包里写成硬规矩）：
1. **字幕单独一条轨**，审过后自动导「无字幕母版」并登记（已做：clean_master）
2. **成片字幕登记**（已有：kind=srt）
3. **动画里的文字放进单独的文案表**（zh / en 两列），不写死在代码里。英文版只要填 en 列再渲染一遍，不用改代码

## 3. 新流程：创始人只碰 3 次

```
中文成片审过 ──┬─→ 公众号线（agent 自己跑到「整包待批」）──→ 你批整包 → 扫码定时
               └─→ 英文线（agent 自己跑到「英文成片 + 发布包待审」）
                     双语脚本 → 第二个 agent 审稿 → 配音 → B-roll 补时 → 动画换英文
                     → 对口型（ChatCut 弹窗你点一次）→ 字幕 → 缩略图 → 发布包
                   ──→ 你看一次：英文成片 + 中英对照 + 标题文案 + 缩略图，一起批
                   ──→ agent 定时 YouTube / X
```

- **英文脚本不再单独认稿**：改成另一个 agent 逐段对照审一遍（数字、事实、时长），结果放进最终那一次审片里，你看片时顺带看中英对照表，不对就在那次里打回。
- **配音不再单独确认**：在 ElevenLabs 套餐额度内的自动跑；超额才问你。
- **对口型**：ChatCut 的付费确认弹窗绕不过去（它的设计，也是保护你），但改成**只弹 1 次**：把露脸段合成一个片段提交（这次切了 5 段，弹了 5 次）。
- **发布账号**：第一次确认后记住（YouTube 频道 ID、X 用户名），以后只在账号变了时才问。
- **公众号**：维持「整包批一次 + 扫码」，前面的写稿、配图、封面都自动跑完再给你看。
