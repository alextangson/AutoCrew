# 首页 + 内容管线重规划（草案，待创始人确认）

2026-10-25。起因：创始人看首页觉得「等你拍板」是噪音、数据页没帮助、分析技能网页上找不到；内容管线里一个主题发到多个平台却拆成好几张卡、状态对不上。本稿只定方向和边界，确认后再出视觉样张、过 Codex consult、再动工。

## 0. 现状里查实的问题（都有证据）

| # | 现象 | 根因 |
|---|---|---|
| 1 | 「写法改动已批，等发布」3 条永远挂着 | 补丁 10-22 已合进 write-script 技能（03ab78bc），但状态机没有「已生效」这一态，也没人能标（promotions.ts 只有 pending/applied/approved_pending_release/rejected） |
| 2 | 公众号已发，看板仍在「待发布」 | 看板阶段只认视频的发布事实（production/derive.ts:291-299）；公众号的发布记在它自己的 publish-state，看板不读 |
| 3 | 深度思考的英文版单独一张卡在「写稿中」，中文版在「已发布」，公众号又一张卡 | 派生稿（公众号、英文版）是独立的 content，看板按 content 出卡，没有「同一主题」这一层 |

| 8 | 账号洞察、排期会、盲预测、复盘这一条只能在对话里用 | 网页没入口；但现成有 `deliver()`（writing-handoff.ts）能从网页开一个预填好的 Claude/Codex 会话 |

## 1. 首页：一屏三段

参照：YouTube Studio 频道首页（上面一行账号数字 + 最新一条表现）、Linear 的 project 视图（一个项目一行，下面挂子任务状态）。

1. **今天的账号**（最上面一条）
   - 每个勾了的平台一格：粉丝数、较昨天 ±、昨天总播放/阅读、较前 7 天均值 ±。
   - 「刚发那条」一格：发出后 24h/72h 跟这个平台平时比。
   - 回流坏了的平台直接在这一格写「视频号要重新登录 →」，不藏在设置里。
   - 一排「让 AI 看看」按钮：账号洞察 / 开排期会 / 复盘刚发那条。点了用 `deliver()` 开一个预填好的本机 AI 会话（Claude 优先，没有就交总编辑），不在网页里自己跑分析。
2. **要你做的**（默认收起成一行「4 件要你定 ▸」，按主题分组）
   - 主题已发布或已打回重拍的，它名下的成片 / 封面 / 闪帧条目自动关掉。
   - 写法补丁合进技能后自动标「已生效」并消失（修 #1）。
3. **内容管线**（看板，见 §2）

顶部「数据」tab：去掉独立数据页，有用的两块并进首页（「刚发那条」、「全部作品」表放首页底部折叠）；写法实验和预测账本挪进「让 AI 看看」里出的报告。→ 待定 Q3。

## 2. 内容管线：一个主题一张卡

- **卡 = 主题**，不再是 content。中文视频是主线；公众号长文、英文版是挂在这张卡上的「去向」。
- 卡上一排平台小标（用新的平台 logo），每个去向一个状态点：没开始 / 在做 / 待你定 / 已定时 / 已发。
- **列按主线走**：选题 → 写稿 → 录制 → 剪辑 → 发布中 → 全部发完。
  - 「发布中」= 中文视频至少一个平台发了，但还有勾了的去向没发（比如深度思考：4 平台 + 公众号都发了，YouTube/X 没发）。
  - 「全部发完」= 所有勾了的去向都发了，或者被你标了「这条不出 XX」。
- 派生稿的状态归到父卡上（修 #2、#3）：公众号 `record_scheduled published:true` 记为已发。
- 点卡展开：每个去向一行，下一步是什么、谁在做、按钮。

## 3. 选题库

- **星级**：每张选题卡可以打 1–5 星。
  - 1–2 星：立刻进回收站（可恢复），同时作为反馈喂给雷达打分（同类少推）。
  - 4–5 星：钉住，不老化。
  - 没打星的：放满 N 天自动进回收站（建议 7 天），保留雷达分最高的前 K 条不动。→ Q5
- **推荐变多**：→ Q4，需要你说「少」是指哪种。

## 4. 数据回流

- 回流范围 = 你勾的平台 ∩ 能抓的平台。勾了但还不能抓的，在首页那一格写「还不能自动回流」。
- 这一期接上：B站（创作中心）、公众号（后台图文/用户分析），各要你扫一次码。
- 新增**账号级每日快照**：每个平台每天一行（粉丝、总播放/阅读、新增粉丝），存进资料库，首页的「较昨天」就从这里算。
- 视频号：先请你重新登录一次；以后登录掉了首页直接提醒。

## 5. 边界（建完要逐条验收）

- 一个平台没勾 → 不抓、不出格、不出去向。
- 回流失败 / 要登录 → 那一格显示原因和入口，不显示旧数字冒充今天。
- 账号数据只有一天 → 不算「较昨天」，写「明天开始有对比」。
- 主题被打回重拍 → 卡回到「录制」，旧成片 / 封面条目关掉，派生去向暂停并标「等新成片」（已有 lineage 的 isStale 机制）。
- 派生稿单独发了但主线没发（少见）→ 卡停在主线所在列，去向小标显示已发。
- 星级误点 → 回收站可恢复，恢复后不再自动老化。
- 「让 AI 看看」没有本机 AI 也没配模型 → 按钮写明原因，不静默失败。

## 6. 定案（2026-10-25 创始人：「可以 看你说的做」）

- Q1 账号数据放最上面：定。
- Q2 公众号、英文版并进主题卡，不单独出卡：定。
- Q3 去掉「数据」tab，有用部分并进首页：定。
- Q4 选题推荐：按 (b)+(c) 做——每天保证一批新选题（不足时自动补抓），并用星级反馈调雷达打分；加新来源不在这一期。
- Q5 没打星的选题 7 天进回收站：定。
- Q6 账号数据仍每天 09:00 抓一次：定。

原问题留档：

- Q1 首页三段的顺序：账号数据在最上面，可以吗？
- Q2 卡片按主题合并后，英文版、公众号不再单独出卡，可以吗？（单独找它们可以在卡里展开）
- Q3 去掉「数据」tab，把有用的部分并进首页，可以吗？
- Q4 「选题推荐输入少」是指：(a) 来源太少，想加别的源；(b) 刷新太慢，每天新的太少；(c) 推的方向不对，想按星级反馈调？
- Q5 没打星的选题放几天自动进回收站？建议 7 天。
- Q6 账号数据每天几点抓？现在是 09:00 一次。

## 8. Codex consult（2026-10-25）与处理

方向可行，最省的安全做法是「在现有稿件之上做一层服务端分组视图 + 每个主题一份小的去向计划」，不改稿件 id、不换生产状态机。逐条处理：

| # | 级别 | 问题 | 处理 |
|---|---|---|---|
| 1 | P1 | 「主题」没有身份定义 | 主题 = 只读分组：父 = 源视频 content，子 = `derivedFrom.contentId` 指向它的稿（反向索引，不信 siblings 数组、不按标题猜）。没有视频的纯图文稿、只有选题的卡、找不到父的孤儿稿各自单独成卡。稿件 id 和编辑页链接不变 |
| 2 | P1 | 批完了但一个都没发的卡没有列 | **保留「待发布」列**：列改为 选题 → 写稿 → 录制 → 剪辑 → 待发布 → 发布中 → 全部发完。纯图文稿按它自己的阶段走 |
| 3 | P1 | 现有「已发布」只要有一个回执就成立 | 每个去向的状态从它自己的回执推：没开始 / 在做 / 待你定 / 已定时 / 已发 / **没发成**（被拒、结果不明、过点没发）。「全部发完」= 计划里每个去向都确认已发或被标了不出。公众号回执不喂给视频的 D1 |
| 4 | P1 | 全局勾选 ≠ 每条的发布计划 | 每个主题存一份去向计划（要发 / 不出，带谁定的、原话）。新主题按当时的勾选生成默认计划；之后改勾选不回头改老卡；取消勾选后已发的记录保留 |
| 5 | P1 | 主题级关闭待办会藏掉没做完的事 | 「要你做的」只按主题**分组显示**，每件仍按原稿、原轮次关闭；中文发了不会关掉英文版的审片 |
| 6 | P1 | isStale 不等于重拍 | 新增显式「重拍」动作：卡回「录制」、开新一轮；派生去向暂停；已发的保留；已定时的列出来提醒你去撤，不自动撤 |
| 7 | P1 | 选题已有老化（我写错了） | 改现有过期清理为 7 天，保留它的保护规则（已开写、本周片单、刚续过调研的不清）。新增星级字段；打了 ≥3 星的不老化，4–5 星置顶；1–2 星进回收站并给雷达负反馈；从回收站恢复的不再自动老化；改星撤销负反馈。上线前现有没打星的旧选题统一从上线日起算 7 天 |
| 8 | P2 | 「每天保证新选题」缺规则 | 每天目标 10 条新选题；不够时最多补抓 3 轮；还不够就在选题列写「今天只找到 N 条」。人打的星和雷达分分开存；过期 ≠ 不喜欢 |
| 9 | P2 | 账号快照语义 | 每行带：账号、数据日期（北京时间自然日）、抓取时间、口径、是否完整。「较昨天」只和真正的前一天比，缺一天就不比。账号抓取和作品抓取的健康分开记。「刚发那条」用作品数据按同发出时长比 |
| 10 | P2 | 接 B站、公众号不只是改表 | 补齐抓取适配器和状态；公众号复用现有 `wechat_pull` 路径；「回流只抓勾了的平台」在共用执行入口拦，手动「立即抓取」也一样 |
| 11 | P2 | `deliver()` 不会自己开跑 | 「让 AI 看看」要写清每种分析的提示词和范围；按钮结果分三种如实显示：已打开会话（Claude 预填）/ 要你粘贴（Codex）/ 已开始（总编辑） |
| 12 | P2 | 补丁合进仓库 ≠ 已生效 | 标「已生效」要对上当前运行的安装：技能文件里确实有这条补丁，并记下当时技能文件的哈希 |
| 13 | P2 | 分期先拆了旧页面 | 重排分期见下 |

### 分期（按 Codex 意见重排）

1. 先修：写法补丁生效判定（#12 口径）、公众号发布归位、视频号登录提醒。
2. 服务端主题分组 + 去向回执适配 + 每主题去向计划；看板换主题卡（含待发布列、没发成状态、重拍动作）。旧数据页先不动。
3. 首页：账号区先复用现有数据页组件（刚发那条、回流健康），「让 AI 看看」三个按钮；「要你做的」分组。
4. 账号级快照 + 回流跟勾选走 + 接 B站、公众号；账号格子随快照一起上。
5. 选题星级 + 7 天老化 + 每日补抓。
6. 首页能覆盖数据页的所有动作和链接后，再去掉「数据」tab。
