# 审稿规则补强 — 规格

2026-10-03。吸收 dbskill 的 AI 写作特征识别、口播逻辑延续检查、开头诊断、文稿共鸣诊断四套方法，用我们自己的话重写进审稿判据。不标出处。创始人 10-03 要求与标题方法库同时开工；下面的默认取舍由我定，创始人可随时改。

改动集中在 `src/modules/writing/script-review-prompt.ts`（判据表），加少量确定性提示。不新增工具。

## 一、AI 腔判据补强（所有稿型）

现有 `STYLE_RULES` 保留。补以下几条（措辞自写，不照搬）：

1. 「不是 X，是 Y」式翻转用得太密：一篇一两次可以，段段翻转就是在教训人。
2. 每段结尾都收一句金句：节奏变油，金句失去分量。
3. 替读者说一句他没说过的蠢话，再去纠正（稻草人）。
4. 同一个让步模板反复用（「你可能会说……但其实……」走好几遍）。
5. 给概念起名的仪式用了不止一次。
6. 开头套「钩子 + 痛点 + 承诺」三件套的模板感。
7. 结尾「你值得」「愿你」式祝福。
8. 翻译腔（「作为一个……」「这使得……成为可能」）和为避免重复刻意换同义词。

与现有判据的取舍：和现有「不强制反常识、反问、CTA」的立场一致，新判据只指出模式滥用，不要求删光。

## 二、核心主张（所有稿型）

新增一条：「核心被稀释」——几个主张平铺，读完说不出这篇的那一句话。其他内容应当是证据、例子、解释或行动建议。

和现有判据的关系：`DEPTH_RULES`「信息罗列无论点」只在有调研材料时启用，`ANGLE_DEPTH_RULES`「论点被稀释」只在有角度卡时启用。新条目在两者都不在场时兜底，在场时不重复出现。

## 三、口播流畅（只对口播 / 短视频稿型）

审稿人按段过三件事：

1. **段间断裂**：上一段到这一段缺了承上启下的那句，观众跟不上。
2. **信息密度掉了**：同一个意思换说法重复、绕圈子、说了等于没说的段落。
3. **念不出口**：单句太长、书面语（鉴于 / 基于以上 / 综上所述 / 针对）、术语后面没跟一句大白话解释、连续自问自答。

确定性提示（代码判，只提示不拦）：
- 单句超过 30 字（按句末标点切；引号内引文、英文和数字串不计入）。
- 书面语词表命中。

## 四、开头诊断（只对口播 / 短视频稿型）

审稿人检查开头：
1. 不看标题能不能听懂在讲什么；
2. 是不是一开口就把答案说完了；
3. 观众凭什么听你讲（可信度只能来自稿里有据的事实，不得要求补造身份、成绩）；
4. 开头的承诺正文有没有兑现。

前置判断：正文本身单薄、没有可用材料时，直接指出问题在内容，不去改开头。

不吸收：dbskill 的「话题 + Hook + 可信度」开头公式和涨粉式示例——与创始人品味相反。

## 五、严重度（默认取舍，创始人可改）

| 判据 | 严重度 |
|---|---|
| AI 腔新增 8 条 | advisory；同一模式密到影响观看时可升 blocker（和现有 STYLE 一致，由审稿人判） |
| 核心被稀释 | blocker |
| 段间断裂 | blocker |
| 信息密度掉了、念不出口 | advisory |
| 开头承诺正文没兑现 | blocker |
| 开头其他三项 | advisory |
| 确定性提示（长句、书面语） | 只提示，不进 blocker |

理由：blocker 会触发修订轮，判据越多越容易来回打转；只有「观众会直接划走 / 读完没东西」的问题才打回。

## 六、边界情况（交付范围）

- 创作者规划或原话里明确要的写法（比如指定清单结构、指定某句金句）优先，审稿不因新判据打回。
- 修订轮不能因为新增判据无限打转：沿用现有收敛上限，新判据不改收敛逻辑。
- 已过审的旧稿不重审。
- 判据表变长后 prompt 预算：只对适用稿型注入口播 / 开头判据，长文不带。
- 长句提示排除引文、英文、代码、数字串；没有句末标点的超长段落按段算一次，不刷屏。
- 新判据的 `rule` 名可在 issue 里一眼认出（沿用现有 rule 名进 issue 的约定）。

## 七、测试

- 不对模型输出做精确断言。测 prompt 组装：口播稿带口播 / 开头判据，长文不带；有角度卡时不重复出现「核心被稀释」。
- 确定性提示：长句切分、排除规则、书面语命中，各有用例。
