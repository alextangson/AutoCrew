# AutoCrew PRD v3 — 产品方向与重构蓝图

> 状态：方向已定，已吸收 2026-06-10 两轮评审裁决（7 视角评审 + 对抗验证），待落实施计划
> 日期：2026-06-10
> 取代：[PRD-v2.md](PRD-v2.md)（保留作历史）
> 一句话定位：**一个跑在创作者自己机器上的"短视频内容数字员工"——用你的真实素材和真实发布表现，越用越懂你，产出过审安全、平台原生的口播脚本。**

---

## 0. TL;DR（给未来的自己 / 协作者）

AutoCrew 是一个**本地优先的桌面应用**。内核是**双层架构：外层 = local-store 持久化状态机（闭环本体），内层 = 自研薄 agent loop（架在现有 src/runtime 之上，只活在单个步骤内）**。不 fork 任何源码——CC 专有许可与 §9 开源计划冲突；OpenClaw fork 是上游追赶债 + 安全负债，只当零件仓库（extension-relay 通道参照、skill 标准兼容）。在它之上跑一条**单一英雄流程：知识口播数字编剧**——选题 → 口播脚本（钩子 + 正文 + 分镜）→ 去 AI 味 / 合规 → 一稿多发到抖音/视频号/小红书 → **回流真实发布数据，逐条打标到产出它的那一稿，喂回下一轮**。

护城河**不是"会写脚本"**（通用 agent 也会），而是那份**每个创作者私有的、带结果标签的数据集**。2026 年的诚实版本：有浏览器和记忆的通用 agent 在能力上也拿得到——可防御的是**时间不可压缩 + 零摩擦默认值 + reward schema + 合规内建**的叠加（§3）：任何人都能搭一次这个闭环，但没有产品替你把它变成默认值并坚持 30 个周期。

变现走 **open-core + 会员制**：开源引擎引流，付费 = 赛道包 + 托管飞轮 + 私有数据集。终局是一个多 agent 的"内容营销 crew"——但那是北极星，**v1 只做一条流程做穿**。

## 1. 背景：v1 为什么停了，这次变了什么

### v1 的死因（已逐行核对代码，不是猜）

不是架构差——它有干净的 `src/runtime/`、199 个通过的测试、真实的转换层。它死于**两件事**：

1. **英雄流程从来没真的跑通。** 头号承诺"自动发小红书/抖音"是个 stub——[publish.ts](../src/tools/publish.ts) 只做了公众号草稿，其他全部 early-return。一条最后一步是占位符的流水线，等于没产品。
2. **首次体验一周内反复横跳三次。** 建 5 问 onboarding 墙 → 觉得难用拆掉 → 重加一个更狠的 throwing gate → 再用 `/calibrate` 软化。根因：OpenClaw 的 agent 根本没读 `AGENTS.md`，整套 onboarding 架构压在一个**错误的假设**上。

**一句话：基础设施的野心跑赢了"能用的用户结果"。** v3 的全部纪律就是反这一条。

### v2 → v3 的核心转向

| 维度 | v2（旧） | v3（新） |
|---|---|---|
| 宿主 | 双宿主：OpenClaw 插件 + 手搓 MCP server，重复注册、已在漂移 | **单一基座**：自研薄引擎（src/runtime + 薄 loop），跑在本地桌面应用里 |
| 生成 | delegate 给宿主读 SKILL.md（非技术用户那边根本没有宿主 agent）| **进程内生成**，单一 model provider |
| 载体 | 小红书图文为头号场景 | **短视频口播脚本**，一稿多发；小红书图文后置 |
| 护城河 | 模糊（"去 AI 味 + 风格学习"，但都是占位）| **带结果标签的私有数据集**（时间×默认值×schema×合规的叠加，§3）|
| 交付 | CLI / 插件对话 | **本地优先桌面应用**（非技术友好）；CLI/MCP 降级为后期开发者渠道 |
| 形态扩展 | 写死在执行器里 | **共享引擎 + 声明式赛道包** |

## 2. 目标用户 & Beachhead

- **第一用户**：个人创作者 / KOL（含为卖货获客而做内容的小商家）。
- **Beachhead 赛道**：**知识类口播**。三个理由：
  1. **Dogfood**——创始人本人每天做知识口播，是 0 号用户。**没有创作者在环里，就建不出 per-creator 飞轮。**
  2. **合规负担最轻**——~90% 被现有违禁词/极限词过滤覆盖。带货会在第一天就压上广告法级合规。
  3. **已经 80% 建好**——口播 playbook 已存在于 [write-script/SKILL.md](../skills/write-script/SKILL.md)。
- **明确不在 v1**：带货、剧情段子（赛道包后置）；公众号（交给 musegzh）；小红书图文（后期拓展）。

## 3. 护城河（经对抗式压测后的诚实版本）

> 压测结论：**thesis 原则上成立，但在当前代码里是假的——四根支柱有三根是占位符。** thesis 只在 v1 把那一根"通用 agent 结构上抄不走的支柱"真正建起来时才成立。

### 唯一活下来的护城河

**在"结果数据诞生的那一刻"占据特权位置。** AutoCrew 坐在创作者"发布—measure"的工作流里，积累一份**私有的、per-creator 的、带结果标签的数据集**：*这一版脚本 → 这些真实数字 → 所以下一轮往 X 偏*。

> 2026 年的诚实版本（评审修订）：通用 agent（Claude in Chrome / computer use + 持久记忆）在**能力层面**可以复刻闭环的每一环——"拿不到"已不成立。可防御的是四件不性感但真实的东西的**叠加**：
> 1. **时间**——带标签纵向历史的价值与真实发布周期数成正比，时间不可压缩，任何竞品从第 0 周期开始；
> 2. **默认值**——AutoCrew 把"回填+打标"做成零提示词、默认开启的产品行为；通用 agent 路线要求用户自己当编排者并坚持纪律，绝大多数非技术创作者不会、也坚持不了；
> 3. **schema**——赛道包定义的 reward signal 与 draft↔variant↔outcome 归因结构，是自由文本记忆给不出的。**这份 schema 是 v1 第一公民交付物**（当前代码里只是扁平 `Record<string, number>`，护城河本体还没有 schema）；
> 4. **合规风控内建**——§6 红线（低频、只读、人类节奏）是产品级工程；拿通用 agent 裸抓后台的用户是在拿自己账号赌限流。
>
> 一句话：**任何人都能搭一次这个闭环，但没有产品替你把它变成默认值并坚持 30 个周期。**
>
> 另：最危险的对手不是通用 agent，是**拥有原生完播率数据的平台第一方（字节系）**。AutoCrew 唯一的结构性位置是第一方永远不会做的**跨平台归因**——从便利功能升格为护城河支柱。

### 诚实承认（这些目前都不是护城河）

- **风格学习目前很弱**：[diff-tracker.ts](../src/modules/learnings/diff-tracker.ts) 只有 8 条写死正则 → [rule-distiller.ts](../src/modules/learnings/rule-distiller.ts) 固定中文串，置信分是装饰性的。所有人收敛到同样 8 条。产出是 5KB 明文 JSON，能直接粘给任何 agent。→ **v1 必须用 LLM 风格建模替换正则蒸馏。**
- **爆款库不存在**：[quality-baseline.ts](../src/modules/analytics/quality-baseline.ts) 里字面是 `commonHookTypes: [], // placeholder`。→ **v1 必须做成真实、per-creator-format 的。**
- **"闭环"是手动录入**：[clipboard-publisher.ts](../src/modules/publish/clipboard-publisher.ts) 只排版，没有任何读回。→ **v1 用浏览器自动化读创作者自己后台（见 §6）。**
- **安全是静态子串表**：不差异化，正确地做成免费。

### 三个恐惧，逐个有解

| 恐惧 | 压测裁决 | 解药 |
|---|---|---|
| 开源包=一次性下载 | **成立且致命**（如果你卖"包"——文本可无限复制）| **open-core**：开源引擎是分发，不是产品；卖飞轮+数据+包（§9）|
| 被通用 agent 替代 | **对**——除非建起真实的带标签闭环 | 把 §6 的闭环建真 |
| 受众窄→定价难 | 真，但最好解 | **同一引擎按层级 39元→几千**，窄是分层问题（§9）|

## 4. 产品定位 & 北极星

- **v1 = 一个 agent 干一件事**：知识口播数字编剧。
- **北极星 = 完整内容营销 crew**：研究员/选题/编剧/审核/分发 多 agent 协作，从知识库持续产出多平台内容。这正是 "AutoCrew = auto + crew" 名字的兑现。
- **纪律**：crew 是北极星**不是 v1 build**。`spawn-planner` / `spawn-writer` / `spawn-batch-writer` 等 skill 保持休眠，直到单流程飞轮**被证明会复利**。*能用 workflow 解决，就不要加 agent。*
- **Crew 呈现层裁决（2026-06-11 增补，创始人定位重申后的综合）**：crew 的「团队感」不必等多 agent 架构——v1 即把既有管线阶段**拟人化为角色呈现**：选题侦察员（选题雷达）、编剧（生成+风格）、合规审核员（过滤+发布门）、数据分析师（回流报告/归因）。卡片署名到角色，UI 隐喻 =「你的数字员工团队」（S2 设计系统核心隐喻，见 v1-capability-roadmap）。架构仍是单引擎 workflow——纪律不破，呈现先行。
- **素材库接入编剧（S2.9 增补）**：编剧新增 `search_assets` 工具，可按名称/标签/类型检索素材库；稿件可从素材库挂接媒体（复制快照），库语义为引用式（入库不复制原文件，删记录不删原文件）。
- **Copilot → Autopilot 信任阶梯（2026-06-11 增补）**：不是开关，是三级阶梯。**L1 Copilot**（现在）= 你说它做 + 人工确认门；**L2 定时拟稿** = 外层调度每日跑选题雷达 → 自动产 2-3 篇初稿进待审队列（"睡醒有 3 篇待审稿"——数字员工的第一个真实体感时刻；技术 = 调度器 + 既有生成链，选题雷达质量验证后排期）；**L3 自动发布** = 远期，受 §6 红线（写操作独立风控评审 + 默认关闭 opt-in + 逐次显式确认）约束，v1 不碰。每级解锁的前提 = 上一级的质量数据——回流闭环（§6）是整个阶梯的燃料。

## 5. 核心架构

**分层（自底向上）：**

```
┌─────────────────────────────────────────────────────────────┐
│  桌面应用外壳 (Tauri / Electron)                              │
│  · 非技术友好 UI（本地 web UI）  · 内嵌 webview 只承载 UI     │
│  · 打包引擎 + 扩展安装向导（登录态留在用户真实浏览器）        │
├─────────────────────────────────────────────────────────────┤
│  内容层（AutoCrew 自有）                                      │
│  · 英雄流程：口播数字编剧 (§7)                                │
│  · 声明式赛道包 (§8)   · 三个齿轮 a/b/c (§7.2)                │
│  · 安全/合规转换（复用 humanizer/zh, sensitive-words）       │
│  · 浏览器回填适配器（扩展+native messaging 主通道，§6）      │
├─────────────────────────────────────────────────────────────┤
│  引擎（自研薄层，架在现有 src/runtime 之上）                  │
│  · 外层编排：local-store 11 态状态机 + 调度 + 人类确认门      │
│    （挂起/恢复 = 显式状态，所有状态落盘）                     │
│  · 内层：步骤内短时 agent loop（~500 行自研或 Agent SDK，     │
│    带轮次/token 预算上限）——只用于生成与兜底解析              │
│  · ToolRunner 中间件链：阻断型检查走同步中间件；              │
│    EventBus/hooks 只做观测  · 多 provider（OpenAI 兼容）      │
├─────────────────────────────────────────────────────────────┤
│  本地存储                                                    │
│  · 复用 local-store 状态机 + 新增 knowledge-note / 带标签性能 │
│  · 私有数据集（护城河）默认本地，可选加密云同步              │
└─────────────────────────────────────────────────────────────┘
        │（account-bound，薄云后端）
        ▼
┌─────────────────────────────────────────────────────────────┐
│  薄云后端（复用 pro/gate + api-client 模式）                  │
│  · auth / license / 订阅校验   · 可选私有数据加密同步         │
│  · broad 爆款信号（消费 蝉妈妈/飞瓜，不自建爬虫）            │
└─────────────────────────────────────────────────────────────┘
```

**关键架构决定：**

- **本地优先桌面应用**：因为浏览器自动化要碰用户本机登录态 session，纯云 SaaS 碰不到。数据默认在本地（护城河在用户机器上）→ 用**account-bound 可选云同步**补回迁移成本和跨设备。
- **引擎来源（评审已裁决，原"抽取 CC shell"作废）**：不抽 CC 源码——专有许可与 §9 开源层直接冲突，且是冻结 fork 维护债；不 fork OpenClaw——上游高速破坏性变更 + 2026 年初安全危机（CVE-2026-25253 一键 RCE、4 万+暴露实例、skills 市场 12% 投毒）的攻击面与心智负债，而本产品拿着创作者登录态，安全负债即产品风险。**自研 ~500 行薄 loop 架在 src/runtime 之上，或用 Claude Agent SDK**（取决于模型选型 spike，见 §14）。OpenClaw 当零件仓库：extension-relay 浏览器通道参照、多 provider 适配参照、skill 标准兼容（§9 开源层 = OpenClaw 兼容赛道包，借现成生态分发，顺带解掉开源代码来源的法务问题）。**引擎跑的第一个东西必须是口播数字编剧，不是 crew。**
- **双层架构裁决（终结"用 Loop 组织一切"之争）**：闭环是状态机，loop 是状态机里个别节点的实现细节。agent loop 是分钟级、单上下文、进程内原语；营销闭环是日历级、跨会话、含人工确认。逐步骤标注：选题/脚本生成/兜底解析 = 带预算上限的 loop；humanize、违禁词、排版 = 纯函数，模型不在环。**所有跨人工动作或时间等待的边界必须是 local-store 显式状态（awaiting_user_confirm / awaiting_metrics），禁止进程内等待（轮询/sleep/挂起的 agent 会话）。**
- **三层记忆模型**：(1) 持久结构化存储 = 护城河数据（draft↔outcome、风格模型、playbook），**绝不经有损摘要**；(2) 每步 prompt = 从 (1) 做预算内检索注入（top-k 风格规则 + 当前一稿）；(3) 会话内上下文 = 短暂、小、可丢弃。上下文压缩降级为 v1.5 按需项。
- **单一基座**：砍掉 v2 的双宿主重复注册（`index.ts` 和 `mcp/server.ts` 里 `autocrew_pro_status` 各定义一遍、已漂移）。CLI / MCP / API 降级为**后期**薄适配器，共用同一引擎。

## 6. 性能闭环（护城河的发动机）

> 这是整个 thesis 的命门。压测裁决：**只要别把它定义成"自动 API 摄取"，闭环就成立**——2026 年自动 API 是幻想（视频号无 API；小红书只给公开点赞收藏，完播率/涨粉只能导出/截图；抖音 OAuth 企业门槛 + 无完播率 + 禁止转售分析条款）。

### v1 机制：浏览器自动化读"创作者自己的后台"（三层通道，评审修订）

> 外部事实（已核实）：Chrome 136（2025-05）起 CDP 调试端口对默认 user-data-dir 失效，"接管用户日常 Chrome 已有登录态"这条路已被平台方移除。原"创始人已验证可行"需复核验证环境（Chrome 版本 / 启动 flags / user-data-dir）。

- **主通道：Chrome 扩展 + native messaging**（Claude in Chrome / OpenClaw extension-relay 已验证模式）——content script 跑在用户真实 profile 里，零重登、无 CDP attach、无自动化横幅、真实指纹，风控暴露面最低。中国分发：Edge Add-ons（大陆可访问）+ 桌面 app 内 CRX 安装向导。
- **辅通道：专用自动化 profile + CDP**（app 以自有 --user-data-dir 启动，用户每平台扫码登录一次）——不愿装扩展用户的降级。
- **兜底**：导出 CSV 上传（三大后台都能导出含完播率/涨粉的自有数据）；结构化粘贴；截图 OCR。
- **运行时口径**：回填默认走**确定性适配器**（per-platform、版本化、可单测）；LLM 仅用于兜底数据解析与适配器失效后的辅助修复，**不做 computer-use 式自由浏览**（token 成本、不可复现、随机轨迹扩大风控面）。
- **核心动作**：把每条指标**逐条打标到产出它的那一稿**（draft → outcome 的链接 + schema，v1 第一公民交付物，见 §3）。
- **reward signal 从赛道包读**（口播 = 完播；带货 = 转化；段子 = 互动）。

### 适配器可靠性（这个赌注本身，一等产品功能）

- 抓取优先级：**捕获页面自身的后台 JSON 接口** > LLM 读 DOM/截图（接口变更后的自愈层）> CSS 选择器（仅快速路径，现 browser-cdp.ts 依赖抖音混淆类名 `.ECMy_Zdt` 即反面教材）。
- 适配器定义（URL、接口特征、字段映射、选择器）= **云端可下发配置**（复用 §5 薄云后端），不编译进 app 版本——平台改版不等发版。
- 每个平台适配器带健康指标；连续失败 N 次自动切换"本周改用 CSV 导出，30 秒完成"引导。**禁止静默返回空。**
- **回填 verify**（脏标签直接腐蚀护城河本体）：落库前值域校验（完播率 0-100%、日期与发布时间一致）；draft↔outcome 用平台侧稳定标识（标题 + 发布时间戳）双因子匹配；异常值（0 或暴涨）转人工确认，不静默入库。

### 红线（写进产品，不可妥协）

1. **v1 仅只读、低频、用户真实浏览器**（非 headless、非服务器农场）。任何写操作（含发布表单预填）需独立风控评审 + 默认关闭的 opt-in + 用户对每次提交显式确认；浏览器能力层把 read-only 与 form-fill 拆成隔离的权限开关（给 v1.5 留经评审的演进空间，不默默突破红线）。
2. **绝不从云服务器碰账号**；绝不自动登录/替用户输密码；绝不抓 session 之外的东西。
3. **只收创作者自己的、已可见的、自己主动触发的数据**；**绝不跨创作者聚合转售**（踩抖音条款）。
4. **反讽风险**：产品卖点是"不被限流"，**这个抓取机制本身绝不能害用户被限流**。保持人类节奏的低频只读。
5. **合规框架（法律红线，非美学）**：在《AI 生成合成内容标识办法》+ GB45438-2025（2025-09-01 生效）下，**去 AI 味只能定义成"自然口吻/品牌腔/质量"，绝不能是"绕过 AI 检测/去标识/去水印"**——提供绕过标识的工具会被罚。违禁词同理：定义成"符合平台规则"，不是"绕过审核"。

## 7. 英雄流程（v1）：知识口播数字编剧

### 7.1 单流程（不是 crew）

```
选题 → RAW-prepped 口播脚本（选题钩子 + 口播正文 + 分镜）
     → always-on 去 AI 味 + 违禁词/极限词过滤
     → 一稿多发到 抖音/视频号/小红书（各自原生标题+文案+hashtag，clipboard/paste）
     → 回流真实表现（§6）→ 逐条打标到这一稿 → 喂回风格模型 + 爆款 playbook
```

输入：一个选题 / 一篇对标爆款（粘贴或链接，链接经 read_url 工具读取）/ 一句话想法 +（可选）几条用户素材（轻量没入式知识库）。

**选题雷达（2026-06-11 增补，创始人裁决）**：选题不能只等用户给——按 profile 的定位/赛道**自动抓相关热点**，评分后以选题卡呈现（兑现 README 头号承诺「帮我找这周的选题」）。架构口径（§5 双层架构的活例子）：`find_topics` 是步骤内工具（读热点缓存 → 按定位过滤 → fastModel 评分）；**定期抓取是外层调度的事**（app 启动/定时刷新热榜缓存落盘），绝不是挂起的 agent 会话轮询。合规口径：v1 只读消费**公开热榜/RSS 源**（源清单 = 云端可下发配置，对齐 §6 适配器模式），不自建爬虫；账号后台维度的 broad 信号仍走 §7.2b 第三方（蝉妈妈/飞瓜）。

**Day-1 热启动（首跑历史回灌，评审新增——v1 最高杠杆产品决定）**：onboarding = 连接后台 → 批量导入创作者已有的历史作品 + 表现数据（**CSV 导出优先**，零风控暴露；浏览器自动化只做日常增量，符合 §6 红线"低频"）→ 10 分钟内产出第一份 per-creator playbook 报告（"我看完了你过去 30 条：你的爆款都在前 5 秒抛反常识钩子，完播率比你的平均高 40%"）。把 baseline n 从 0 拉到几十、风格种子用真实历史文案（比等编辑 diff 好得多）、wow 时刻从第 3 周提前到第 1 天——同时是 §12 行为风险的最强对冲（首次回填发生在动机最高的 onboarding 时刻，而非要求用户先养成喂数据的新习惯）。

### 7.2 三个齿轮 = 产品脊椎（全在一条流程里，不是 crew）

| 齿轮 | 现有种子 | 今天是什么 | **v1 必须做到** |
|---|---|---|---|
| (a) 风格学习 | diff-tracker, rule-distiller, [visible-learning.ts](../src/modules/learnings/visible-learning.ts), [creator-profile.ts](../src/modules/profile/creator-profile.ts) | 8 正则→固定串；可移植 5KB JSON | **用 LLM 风格建模替换正则蒸馏**（从用户的编辑 + 粘贴的爆款里学：用词癖好、句子节奏、招牌短语）。保留 visible-learning 的"我从你的编辑里学到了 X" UX，挖掉背后 8 正则引擎。风格状态留本地（可云同步）。|
| (b) 爆款 playbook | quality-baseline | `commonHookTypes: []` 占位 | **做成真实、per-creator-format**：结构化打标的钩子/结构，从创作者确认的爆款刷新 +（单独）一个 broad 层消费第三方爆款信号（蝉妈妈/飞瓜，只做 broad 层，不自建爬虫）。填掉 `commonHookTypes` 占位。|
| (c) 性能闭环 | addPerformanceEntry, trackPerformance, buildBaseline | 手动录入，无读回 | **建浏览器自动化摄取（§6）+ 逐条打标到具体脚本变体**。reward signal 从赛道包读（口播=完播/收藏/关注）。**配可见归因**（与 visible-learning 对称）：生成时"基于你上一条的完播曲线，这稿我把钩子压到 5 秒内"；回填后"这条数据教会了我什么"；app 打开首屏 = 回流报告 + 归因卡片（数据成熟是天级事件，这是 39 元复购可感知的界面）。|

### 7.3 交互模型与 UI 规格（Agent 态，2026-06-11 增补）

> 缺口来源：§5 对 UI 层只写了一句"非技术友好"，交互模型从未定义——README 承诺的是对话式体验，引擎内核是 agent loop，但两者之间的呈现层是空白，实现于是默认滑向功能屏堆叠（dogfood 壳的四屏形态）。本节裁决产品的交互形态。当前 `desktop/renderer/` 四屏是 §11 第 0 步的验证脚手架，按本节重构。

**核心裁决：Agent 态 = 对话驱动 + 状态机执行 + 卡片呈现。三者缺一不可。**

- **对话是驱动层**：README 的产品承诺本来就是对话式（"帮我找选题"→"把第 2 个写成笔记"→"太 AI 味了，改口语一点"）。每轮对话落到 local-store 状态机的显式状态上（§5 双层架构裁决不变——对话不是进程内挂起的 agent 会话，是状态机的人机接口），可挂起可恢复；人类确认门（发布门/合规门）以卡片内嵌在对话流里，不弹模态。
- **卡片是呈现层**：回到对话流里的不是文本段落，是结构化产物——选题卡（带评分）、稿件卡（钩子/正文/分镜 + 平台变体 tab）、归因卡（§7.2c）、playbook 报告卡。每张卡上的操作按钮与对话等价：点"改口语一点"按钮 = 输入同一句话，双通道殊途同归到同一个状态机动作。
- **反护城河红线：裸 chat 框禁止。** 纯文本 chat 是在和通用 agent（Claude/ChatGPT）的 chat 正面竞争——正是 §3 警告的"通用 agent 也会写脚本"阵地。差异化全部住在结构化卡片、零摩擦默认值和闭环数据里，对话只是入口。

**布局**：左侧对话流（主驱动）+ 右侧工作区（当前卡片的展开态：稿件编辑、报告全文、风格规则）。日常打开首屏 = 回流报告 + 归因卡片（§7.2c 已裁决）。

**Day-1 onboarding（§7.1 热启动的 UI 落地）**：

1. 欢迎 + 赛道确认（v1 仅口播，单选退化为一句话确认）；
2. 连接平台 / 导入历史（CSV 优先；**可跳过**，跳过 = baseline n=0 冷启动）；
3. 风格校准对话（从历史文案种子化风格模型；无历史则 3 句偏好问答）；
4. 10 分钟内产出第一份 playbook 报告 = wow 时刻（"我看完了你过去 30 条……"）。

红线（v1 死因 #2 的教训，throwing gate 不许还魂）：**onboarding 永不阻断**——每一步可跳过，跳过后随时在设置或对话里补；**绝不在 onboarding 问 API key**（§9 已裁决国产模型 + 薄云中转 + 积分计费，终端用户无 key 概念）。

**个性化中心**：

- 风格规则：可见、可编辑、可停用——visible-learning UX 从只读升级为可写（§7.2a 的 UI 面）。
- 对话内实时纠偏："太 AI 味了" → 记录偏好 → 可见确认（"已记住：口语化优先"）→ 下次生成自动应用。
- 设置页：账号/积分、平台连接、合规级别、**开发者区**（自填 provider / API key，折叠隐藏——dogfood 期的默认路径，终端用户不可见层级；替代现状的 env/engine.json 手工配置）。

**反模式清单（评审用红线）**：裸 chat 框（无结构化产物）；功能屏堆叠（工具感，不是员工感）；onboarding 阻断墙；首跑暴露 API key；模态弹窗打断对话流。

**布局演进注记（2026-06-11，创始人定版）**：双栏是第一形态；目标形态为「任务工作台」（Accio Work 式 IA）——左侧边栏（新任务/任务历史/数字员工/定时任务/账号积分）+ 中央 hero 输入与会话视图，前置依赖对话持久化。稿件侧配「工作台」：应用内编辑、框选改写（PendingEdit 采纳/放弃，编辑信号喂 §7.2a 飞轮）、版本时间线与回滚、11 态 pipeline 可视化。见 v1-capability-roadmap S2.7/S2.8。

**S2.8 增补（2026-06-11 落地，解除妥协）**：

1. **对话持久化落地**：此前「流式输出/对话历史持久化」一项在 v1-capability-roadmap 标注为「已声明妥协」（S2 末或 S4）。S2.8 提前解除：会话存于 `~/.autocrew/conversations/<id>/`（meta.json + messages.json，原子写）；`chat:turn` 改收 `{conversation_id?, message}`，主进程全权管理历史；首轮成功后才落盘，失败不建空壳；重启可完整回放含卡片。任务 = 会话，这是侧边栏任务列表的本体。

2. **IA 定版为任务工作台**：上述「目标形态」于 S2.8 正式落地（见设计文档 `docs/superpowers/specs/2026-06-11-sprint2.8-task-workbench-design.md`）。三件套：左侧边栏（＋新任务 / 任务历史 / 数字员工 / 即将上线预留 / 底部设置）+ 中央 hero 空态与会话视图 + 右侧按需滑出抽屉（承载回流报告/稿件工作台/风格/设置/侦察员）。**crew-bar 正式退役**——职能并入侧边栏「数字员工」区（侦察员/编剧/审核员/分析师四角色，点击开抽屉）。IPC 通道从 28 扩至 31（新增 `conversations:list` / `conversations:get` / `conversations:delete`）。CDP 冒烟 8/8 通过（含重启回放含卡片验证）。

## 8. 赛道包模型（破解"受众窄"）

> 压测：抽象成立，**但有条件**。口播/带货/段子是**三个不同目标函数**（完播/转化/互动），fork 比想象深。

- **必须先把格式逻辑从执行器抽进声明式包，再加第二个赛道。** 现在 [write-script/SKILL.md](../skills/write-script/SKILL.md) 把口播 playbook（"5-8 信息点"结构）写死在执行器里。**v1 第一个交付物就是把它抽成第一个声明式赛道包**——一举既出产品又证明 pack 抽象。
- **一个赛道包 =** 钩子集 + 结构骨架 + 选题引擎 + 成功指标定义 + 合规叠加层。性能闭环的 reward signal 从包里读。
- **扩展次序**：口播（证明飞轮 + pack 机制）→ 带货（付费意愿最高，证明飞轮后再上重合规包）→ 段子（最难模板化、变现最弱）。
- **长期**：开放 pack 层给第三方作者（设计师/操盘手），做供给侧飞轮，不必每个赛道自己建。

## 9. 变现 & Open-core

### Open-core 切分

| 层 | 开源 / 免费 | 付费 / 复购 |
|---|---|---|
| 横向引擎 | 去 AI 味 humanizer、违禁词/极限词过滤、基础脚本骨架 | — |
| 赛道包 | — | 各赛道的钩子库 + 结构 + 合规叠加 |
| 托管/本地飞轮 | — | per-creator 风格/playbook/性能数据，持续变好 |
| 私有数据集 | — | 带结果标签的历史——真正的护城河 |

> 为什么复购：下载一个**没数据没飞轮**的引擎对竞品毫无价值——这正是重点。复购价值是**持续交付的**（这周脚本更好，因为飞轮又转了一圈）。反例：妙鸭 9.9 买断 → 掉到 ~342 名，自己承认唯一活路是订阅 ARR + B 端模板生态。

### 定价（终结纠结）

**会员 + 积分混合，绝不买断。** 锚点用创作者已经在付的（秘塔 24-48、即梦 55-79）。

**单位经济（评审新增，顺带裁决 §14 原 Q3）**：英雄流程单次完整跑约 ~82K in / 15K out tokens；Claude 级模型即使满配分层路由 + 缓存，日更用户月 COGS ¥55-75，超出 39 元定价下 COGS 预算（¥12-16）4-6 倍。→ **国内消费者层走国产模型 + 薄云中转**（中转同时是积分计费、防 open-core 破解、合规换模的唯一可行位置——现 gate.ts 纯客户端校验恰好证明为什么必须服务端）；强模型只用于核心生成，过滤/排版/打标用便宜档位。
**2026-06-10 spike 实测修正**：DeepSeek v4 上单次英雄流程切片 ~2K tokens、成本 < ¥0.001——国产模型路由下日更用户月 COGS 坍缩到 ~¥0.1 量级，毛利空间远宽于上述 Claude 级估算；且 v4-flash 质量达标（5 条 writingRules 全遵守），弱档可承担部分生成任务。

**免费层三原则（滥用防护）**：注册 = 手机号验证（生成式 AI 服务的合规必选项，SMS 成本计入获客）；免费生成额度绑定"手机号 + 硬件指纹 + IP"三元组，单账号价值压到低于接码成本（让刷号 ROI 为负，不指望完美识别农场）；零 COGS 纯函数（去AI味/违禁词）完全不限量，作为传播型引流。

**漏斗对冲桌面安装损耗**：纯函数能力做成网页工具当流量入口（"在线先试 → 下载解锁完整数字编剧"，消费级桌面激活率约为 Web 的 1/3-1/5）；v1 预算列入 Apple 公证、Windows EV 证书、360/腾讯管家白名单提交、国内 OSS/CDN 自动更新通道。跟踪"网页工具访客 → 下载 → 首次生成"分段转化率作为获客健康度指标。

- **免费**：always-on 去 AI 味 + 违禁词 + 基础口播数字编剧 + 小额月度脚本额度。（安全过滤是引流，不是 SKU。低门槛筛付费意愿。）
- **个人 39 元/月**：完整口播包 + 个人风格飞轮 + 私有 playbook + 一稿多发 + 生成积分。**计量"生成"，固定"飞轮和安全"**（让他们天天用 = 黏性）。
- **商家/MCN 几百元/月**：多账号 + 团队 + 性能回流看板 + 带货合规包。margin 在这层。镜像蝉妈妈/飞瓜的个人→专业→企业阶梯。**→ 这就是"受众窄"的答案：同一引擎按层级从 39 元卖到几千。**
- 借即梦"创作者成长计划"机制：发布 N 篇优质脚本送积分——**同时**喂性能数据 + 提留存。

## 12. 最大风险 & 最便宜的验证

**风险**：**半手动闭环根本转不起来——创作者不愿每轮喂数据**，于是 (a)(b) 退化回"通用去 AI 味 + 平均 emoji 数"，护城河/复购/迁移成本全塌。这是**行为风险，不是技术风险**。

> 创始人决定：不先做 Wizard-of-Oz 行为验证，而是用**浏览器自动化读自己后台**把回填摩擦降到接近零（通道已改为扩展为主，原 CDP 验证需按 §6 注记复核环境）。**这把"行为风险"转成了"自动化可靠性 + 合规风险"**——所以 §6 的红线就是这个赌注的对冲。

**最便宜的对冲（贯穿 v1）**：创始人本人每天 dogfood 知识口播流程（v1 建成之前即用 OpenClaw 插件原型先跑，见 §11 第 0 步）。盯两层指标（评审修订："下一稿确实因为数据变好"在 n=3 下统计上不可归因——单条表现方差被选题/时机/流量池主导，原表述删去）：

- **(A) 可靠性**：回填成功率、已发布稿 outcome 标签覆盖率 ≥80%、适配器挂掉后恢复时长——这才是这个赌注真正押的东西。
- **(B) 学习代理**：生成稿编辑距离随稿数下降（风格学习在起作用）、数据驱动建议被采纳进下一稿的比例、回填动作留存。性能→质量的真因果验证推迟到 v1.5（更大 n）。

(A) 稳定 → thesis 成立，放心扩赛道；自动化频繁挂 / 触发风控 → 在扩张前回退到导出上传 + 转向商家/MCN（那里有人是"专门干录数据这活的"）。
