# 回流数据认领到稿子 + 补老作品 — 规格（已确认）

2026-10-03。背景：「只看不发」回流首轮成功（抖音 15 / 视频号 15 / 小红书 10），但新入账 35 行**一行都没绑定到稿子**（contentId 全是 null）。创始人要求查清并补上，第 3 项选 A（补老作品记录）。

## 查到的原因

1. **一篇稿子只登记一个平台**：`matchDraft`（`src/modules/flywheel/outcome-store.ts:233`）只在 `c.platform === 行平台` 的已发布稿里找。资料库 5 篇已发布稿都登记成「抖音」，视频号 / 小红书的行永远认领不到。
2. **拿稿子标题对平台标题**：发布标题是发布包里按平台重拟的（`videoKit.postTitle`，如「thinking effort 开到 max…」发出去叫「深度思考开到max…」），对不上。
3. **发布链接没补记**：设计里的精确绑定靠「补记发布链接 → 解析作品 id → 登记绑定表 `platform-items.json`」。这 5 篇没补记过。
4. **抖音作品 id 被截坏**：19 位 id 按 JS 数字解析丢了精度（如 `7681645549023497000`），既不能精确绑定也拼不出链接。
5. 25 行老作品（2026-09-27 资料库改造前发布）在资料库里**没有任何稿子记录**。

## 改什么

### ① 修抖音 id 精度
抖音抓取器从响应里取字符串形态的作品 id（不经数字解析）；已入账的截坏 id 不改原行（append-only），下次抓取带正确 id 的新行按 latest-wins 覆盖。

### ② 认领逻辑
- 一篇稿子可以挂多个平台：认领时把「稿子平台」和「发布包里登记过的平台」都算进候选。
- 标题比对同时用稿子标题和各平台发布包里的 `post_title`；仍保持现有阈值和时间窗。
- 绑定证据新增 `manual`（创始人确认的人工绑定），和 `url` 一样当精确事实；模糊命中仍不登记。

### ③ 人工绑定入口
新增一个正式入口（扩展现有工具，不新建工具）：给定 稿子 id + 平台 + 平台作品 id，登记绑定（via=manual），并对已入账的同作品行按新归属补一条（不改旧行，追加新行，latest-wins）。

### ④ 补老作品记录（选 A）
新增「历史作品」记录：状态已发布、来源标 `imported_history`，只有标题、发布日期、各平台作品 id 绑定，没有正文。
- 不进写稿、审稿、剪辑、发布任何流程，不出现在待办和看板的生产列里。
- 一条视频发了几个平台 = 一条记录挂几个平台绑定。
- 可以删除（删记录同时删它的绑定），不影响回流原始行。

## 边界情况（即验收清单）

- 同一平台作品已绑定别的稿子：拒绝，报出现有归属，不覆盖（要改先解绑）。
- 稿子 id 不存在 / 平台不认识 / 作品 id 空：拒绝并说清哪项不对。
- 重复执行同一绑定：幂等，不重复追加行。
- 历史记录重复创建（同标题同日期同平台作品）：识别为已存在，不重复建。
- 抖音 id 修复前入账的截坏行：不再参与绑定（id 不可信），等下次抓取带正确 id 的行覆盖；绑定用正确 id。
- 历史作品被误当成生产稿：所有生产 / 审稿 / 发布入口对 `imported_history` 一律不受理并说明原因。
- 删除历史记录：同时删绑定；回流原始行保留，归属回到未绑定。
- 认领逻辑放宽后的误认：模糊命中仍不登记绑定；放宽只影响候选范围，阈值和时间窗不变。
