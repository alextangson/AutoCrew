# 发布台改版：视频稿「待发布 / 已发布」页（2026-10-12 草案，待创始人确认）

接上一批《一条视频一张卡》（`docs/2026-10-12-one-video-one-card-flow-spec.md`，已上线 835bffff）。

## 现在的样子（问题）

视频稿到了待发布 / 已发布，稿件页顶部是新的「现在轮到你」卡，下面却还挂着旧的整页「发布台」（`frontend/src/views/PublishWorkspace.tsx` → `EditorTools.tsx` 458 行）：
- **按单平台设计**：只有一个「平台链接」输入框、一个「确认已在平台发布」按钮、一组「回流数据」手填框——一条视频发四个平台时，填进去的是哪个平台说不清（新的回执已经按平台分槽，这里还是老口径）。
- **大量手工活**：生成发布文案、准备视频发布包、发布前检查、复制文案、补记链接、手填播放点赞评论——这些现在都是 Codex 在对话里做、或数据回流自动拉的；创始人的定位是「看进度 + 偶尔手动」。
- **跟顶部卡重复**：平台状态、标已发在卡上已经有了。
- 与 9-28 草图（`review-preview/发布台草图/G-draft-4.png`）差得远：草图是封面 + 一张卡 + 「各平台」一张表 + 折叠的口播稿。

## 目标样子（参照 G-draft-4）

从上到下：
1. **标题行**：「已发布 · 10-02 周五 18:00 公开」/「待发布」+ 标题（沿用上一批）。
2. **封面 + 现在轮到你卡**：左边 3:4 封面缩略图（已选封面），右边沿用上一批的 StageCard。已发布、没事可做时，卡写「还有 N 天公开；公开后第 1、3、7 天自动跟平时比」或「公开第 3 天：比平时好 / 差」。
3. **各平台表**（新，取代旧发布台）：每个目标平台一行——
   | 平台 | 状态 | 活动 | 数据 | 动作 |
   - 状态：未发 / 定时 10-02 18:00 · 审核中 / 已公开（作品链接）/ 被驳回：原因 / 应已公开没核到。
   - 活动：发布计划里这个平台挂的活动名（`campaigns`），没有就空。
   - 数据：公开后显示播放 · 点赞 · 评论，和「比平时」（与数据页同一口径，`src/modules/flywheel/metrics-window.ts`）；未公开写「公开后回流」；回流断了写原因（例：「视频号登录过期，去 ego lite 登录后自动接上」）。
   - 动作（每行最多一个显眼的）：未发 →「让 Codex 发」；被驳回 →「重新提交」；待核 →「确认发了」；已公开 → 无（「更多」里有纠正 / 补链接）。
   - 行可展开：这个平台的标题、文案、标签（来自该平台的发布包 videoKits[平台]）+「复制文案」。
4. **口播稿**：默认折叠，标「定稿」，展开只读（沿用）。
5. **手动工具**（折叠，默认收起，放最底）：发布前检查、给某平台补记链接、某平台手填数据（只在该平台没有回流时出现）、采纳判定改判、配图与附件、版本记录。

删掉：页面级的单个「平台链接 / 确认已在平台发布 / 补记链接 / 回流数据」、「生成发布文案」「准备视频发布包」两个派活按钮（这些在对话里说即可；卡上「让 Codex 发布」照旧）。

文字稿（公众号）本批不动——它只有一个平台，旧发布台对它是对的。

## 边界清单（= 验收清单，待确认）

1. **没有发布计划**：表里按稿件平台给一行「未发」，卡上主按钮「让 Codex 发布」；计划读不到 → 表上方一行「发布计划读不到：原因」+ 重试，不显示成「未发」。
2. **某平台没有发布包 / 发布包过期**（正文或成片变了）：行里写「发布包还没备 / 已过期」，展开处不显示旧文案。
3. **定时已过但没核到公开**：状态写「应已公开 · 还没核到」，动作「确认发了」（沿用上一批的追问）。
4. **作品链接缺失但已公开**（数据回流按标题认的）：状态「已公开（没有作品链接）」，「更多」里补链接。
5. **回流没开 / 登录过期 / 抓取失败**：数据列写具体原因和怎么接上，不写 0，不留空。
6. **刚公开、数据还没回来**：写「公开 N 小时，数据还没回来」；超过 24h 没回来按第 5 条报原因。
7. **比平时**：基线样本不足（例如该平台少于 5 条历史）→ 只显示原始数字，写「历史太少，不比」。
8. **重开了这一条（第 2 轮）**：表只显示本轮；上一轮的各平台记录折叠在「以前的发布」里。
9. **计划里删掉了某平台但已有回执**：照样显示这一行（沿用上一批口径）。
10. **复制文案失败**（剪贴板权限）：按钮旁写原因，文案在展开区可手动选中复制。
11. **读取中 / 失败**：表格先出骨架；失败一行原因 + 重试。
12. **手动工具里的动作**：都按平台带上平台和轮次（沿用上一批），补链接要校验是这个平台的作品链接（沿用 isWorkUrl）。

## 创始人已定（10-12）
- **左侧全程进度栏一起做**：所有视频稿的稿件页左边一条：写稿 → 录制 → 剪辑 → 封面 → 发布 → 数据，做完的写本地日期，当前一步红点，被退回的写「退回 · 原因」；下面放平台、字数估时长、「在访达打开这一条」、版本记录、交接详情（折叠）。来源全是已有事实（认稿决定、原片事实、成片 / 封面批准、登记、回执、回流），不新增存储。
  - 13. 某一步没走（导入的稿没认稿就剪了）：那一步写「跳过」，不写日期，不画成做完。
  - 14. 窄屏（< 1100px）：进度栏收成标题下一行小字「写稿 ✓ · 录制 ✓ · 剪辑 ● …」。
- **比平时 = 数据页同一口径**：同平台、同公开天数（第 1 / 3 / 7 天）跟历史作品比，复用 `metrics-window.ts` 的算法，不另写一套。

## Codex 会审吸收（2026-10-12，覆盖上文冲突处）

1. **比平时 = 数据页真实口径**：数据页用的是「最新累计播放 vs 该平台中位数、样本 ≥3」，不是按第 1/3/7 天比。照它来（复用 `frontend/src/views/data-answers.ts` 背后的同一算法，挪到服务端共用），删掉「第 1、3、7 天」说法；卡上写「比你抖音的中位数高 / 低 X%」，样本不足写「历史太少，不比」。数据页本身不改。
2. **按标题认的不算公开**：`metrics_title` 显示「待核」，不显示「已公开（无链接）」。边界 4 改为：只有可信证据（计划 public / 按作品 id 回流 / 创始人确认）才显示已公开。
3. **数据按本轮这件作品取**：先由本轮回执槽定出作品（作品 id / 链接），再取这件作品的数据快照；对不上或对上多件 → 写「数据对不上是哪一条」，不按 content_id + 平台硬取。
4. **手填数据要后端支持平台**：`flywheel:record` 扩展平台、作品、数据日期、轮次校验；只在该平台不自动回流（B站，或回流关闭）时出现在手动工具里。
5. **补链接 = 新的按槽操作**：服务端新增「给本轮某平台槽补作品链接」，保留发布状态、时间和把关来源，服务端用 isWorkUrl 校验；不复用 i_published。
6. **应已公开**：一律显示「应已公开 · 还没核到」；只有上一批的 24h 追问条件成立时才给「确认发了」（带 fact_id），否则只有「更多」里的纠正。
7. **只改本体启用的视频稿**：影子 / 被排除的视频稿、导入的历史只读页照旧用原来的页面，不造可操作的第 1 轮数据。
8. **一个服务端页面读模型**：新增一个接口一次返回：各平台行（回执推导的状态、计划里的活动名 / 审核状态 / 定时时间、各类时间、作品链接）、数据与比较、回流状态、该平台发布包文案（规范化的标题 / 文案 / 标签、来源、是否过期、拟发 vs 实发）、计划读取错误、进度栏各步、已批准的封面、定稿标识。卡片和表都读它，一个刷新协调器；回执 / 回流事件和定时到点时刷新。
9. **时间按平台分开**：定时时间、提交时间、观察时间、实际公开时间分开给；倒计时和「公开 N 天」按平台算；不知道实际公开时间就写不知道。标题行写「N 个平台已投出」，不写单个公开时间。
10. **回流原因分类**：不支持（B站）、未开启、登录失效、抓取失败、抓到了但没对上这件作品——按平台回流状态 + 对作品的匹配结果给，不凭「24 小时没数据」猜。
11. **文案以服务端为准**：拆出标签；旧发布包经 videoKitsOf 迁移；新鲜度按 draft / register 指纹；已投出的平台显示实发文案（计划里的），未发的显示拟发文案。
12. **进度栏每步要证据**：写稿 = 认稿决定时间；录制 = 原片入库时间（标「原片到」，不说成录制时间）；剪辑 = 成片批准；封面 = 封面批准；发布 = 首个平台提交；数据 = 首次回流。状态有：未到 / 进行中 / 完成 / 被撤回 / 被退回 / 没有记录（后面的步骤做了但这步没证据，例如导入稿没认稿）——不用「跳过」。
13. **封面与定稿的来源**：封面取当前有效的封面批准 / 登记里的那组，不按文件名找；「定稿」标签只在认稿的正文哈希与当前正文一致时显示，否则标「当前稿（未认）」。
14. **一个动作面**：发布表模式下卡上的平台标签只显示状态、不带动作，动作都在表的行里；卡只留一个主按钮。
15. **手动工具按实际盘点**：视频稿的「确认已在平台发布」块本来就不显示、配图在剪辑阶段；采纳判定、版本记录是整条稿级别的，不按平台。
16. **顺序**：后端读模型 + 两个新写操作（补链接、按平台手填数据）先上 → 发布表 UI → 进度栏 → 比较文案。分提交。
