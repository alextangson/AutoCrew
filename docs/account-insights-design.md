# 账号洞察 · 设计与验收卡

目标：用户发起一次“账号洞察”，当前宿主拿到现有内容与回流证据，交付可回读的账号报告和新媒体团队下一步行动。沿用宿主订阅，AutoCrew 不调用后台模型，不抓新平台数据，不代替用户执行建议。

入口：MCP prompt `insights` → `autocrew_insights prepare` → 宿主分析 → `submit` → 返回报告；`list/get`回读。prepare 冻结证据并返回稳定 pack_id，submit 引用同一快照中的证据 ID，报告保存于工作区 reports/account-insights。不改变既有宿主权限；Claude/local-user 等原有不限权入口可用，codex 剪辑工位限制保留。

| 不变量 | 代码与验证 |
| --- | --- |
| 累计、本期新增与发布队列分开；跨平台不加总播放 | facts / 窗口与跨平台测试 |
| 只有正好 D+7 的日快照才能称 D+7，D+30 不替代 | facts / 定龄边界测试 |
| 未绑定也显示；缺字段不补0；待复核不进基线 | facts / 缺失与待复核测试 |
| 数据读取失败显式说明，不能说成零表现 | facts / 错误来源测试 |
| 标题、正文、旧复盘只作资料；有长度及采样范围说明 | facts + instructions / 注入与预算测试 |
| 必须有证据支持的判断，以及明确团队行动 | report validation / 未知引用与空动作拒收测试 |
| 先冻结后提交；不跨工作区读包；重复相同提交幂等，不同提交不覆盖；回读校验报告与正文摘要 | store / 归属、重试、冲突及损坏报告测试 |
| 报告只记建议，不能自动改人设、领任务、写稿或发布 | 工具仅开放prepare/submit/list/get；隔离副作用测试 |
| 使用者能找到完整报告；MCP发现与调用一致 | 注册表、prompt / 协议集成测试 |

报告包含：账号结论、范围与可信度、分平台表现、内容观察、工作流缺口、最多3个优先方向及各岗位动作、后续验证。每条建议包括 owner、priority、action、deliverable、successMetric、timeframe、evidenceRefs；没有数据时优先建议补数据，不编造增长率或受众画像。

预算：默认30天、最大366天；每平台至多8个作品例子，内容正文至多8×800字符，选题至多8×400字符，历史复盘至多1×2000字符。统计覆盖全量范围，正文仅为明确标注的样本。输出至多3条判断、8条行动、6条限制，字段逐项限长。任何被截断的集合给出total/shown。

验证：使用临时工作区、禁止网络；复用现有聚合函数的计数逻辑，洞察仅采用严格同龄数据。真实账号样例由当前宿主读取快照后整理，不能以该单次样例声称模型行为已稳定。服务接入、测试和模型质量分别报告；不因上线验证触发付费探针或中断其他任务。
