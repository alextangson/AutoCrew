# 数据回流重写：像真人一样看后台 — 规格（已确认）

2026-10-03。创始人要求：别再自己构造请求调平台接口（可能被平台警告），改成模拟真实用户看数据，新写。

## 为什么

现行抓取器（2026-08 按社区资料写，从未用真实后台校准）在页面里**主动构造请求**：
- 视频号：自己 POST 内部接口，带随机生成的 `finger-print-device-id` 头；路径与官方页面不同（官方走 `/micro/content/cgi-bin/...`）；只认 HTTP 200，而官方后台所有请求都返回 201 → 今天误判失败。
- 小红书：自己调用页面里的签名函数 `_webmsxyw` 生成 `x-s/x-t` 再请求 → 今天返回业务码 300011。
- 公众号：同样在页面里主动 fetch 后台接口。

这些在平台眼里不是正常浏览行为，有被风控 / 警告的风险，接口一变就坏。抖音抓取器本来就是「旁听」，今天只读试跑抓回 12 条正常。

## 2026-10-03 只读探查（证据）

在 ego lite 里只打开官方页面、只旁听页面自己的响应，不发任何请求：
- 视频号 `https://channels.weixin.qq.com/platform/post/list` → 页面自己收到 `/micro/content/cgi-bin/mmfinderassistant-bin/post/post_list`（HTTP 201，`errCode:0`），每条作品带 `readCount / likeCount / commentCount / forwardCount / favCount / createTime / objectId`。
- 小红书 `https://creator.xiaohongshu.com/statistics/data-analysis` → 页面自己收到 `/api/galaxy/creator/datacenter/note/analyze/list`（HTTP 200），`note_infos` 每条带 `share_count / coverClickRate / comment_count / post_time` 等。

## 怎么做

1. **只看不发**：每个平台在 ego lite 的 Agent TaskSpace 里打开官方数据页，开启网络旁听，读取页面自己收到的数据响应。代码不调用任何平台接口、不加任何请求头、不调用签名函数、不用 `page.fetch` 碰平台后台。
2. **像人一样翻页**：需要更多数据时，滚动或点击页面上的「下一页 / 加载更多」，每个动作之间随机停 2–6 秒；三个平台串行。
3. **只取近期**：只翻到覆盖最近 30 天发布的作品为止，最多 3 页（对账只需 T+3、D+7）。
4. **解析复用**：数据字段映射到现有的回流记录格式；字段缺失 = 页面数据结构变了，零写入、状态可见（schema_changed）。
5. **四个平台都改**：抖音（已是旁听，统一到新框架）、视频号、小红书、公众号。删掉所有主动构造请求的代码（不留开关）。
6. 节奏不变：每天 9:00 一次 + 错过补一次；手动「立即抓取」不限。

## 边界情况（即验收清单）

- 页面跳到登录页 → `needs_login`，待办「在 ego lite 里登录 XX 后台」，当天不再碰。
- 页面出现验证码 / 滑块 / 风控提示 → `risk_control`，立刻停手关页，当天不再碰该平台，不尝试绕过。
- 页面打开了但约定时间内没等到数据响应 → 失败、零写入、写明「页面没返回作品数据」。
- 数据响应结构变了（字段缺失 / 不是 JSON）→ `schema_changed`，零写入。
- 翻页按钮找不到 → 只用已拿到的那页，状态标注「只拿到第 1 页」，不报失败。
- 作品比 30 天更早的部分 → 不翻、不写。
- 抓取中途出错 → 已拿到的完整页照常写入（每页独立校验），出错原因可见。
- 任何路径都关闭自己开的页（沿用今天的父进程兜底关页）。
- 不碰创始人自己的标签页；不弹前台（沿用今天的实测结论，新写后再实测一次）。
- 每个平台一次抓取有总时长上限，超时杀进程、关页、记失败。

## 不做

- 不读页面上的文字来抓数（只读页面自己收到的数据响应，更稳）。
- 不新增平台、不改对账口径。
