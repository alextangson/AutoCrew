# LLM 风格建模 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Checkbox tracking.

**Goal:** 兑现 PRD §7.2(a)：用 LLM 风格建模替换 8 正则蒸馏（"所有人收敛到同样 8 条"的反面），并**接通整条学习闭环**——现状勘察确认 diff-tracker/rule-distiller 在生产路径零调用方（content-save 收 diff_note 但不写 diff，蒸馏无人触发），管线是断的。

**Architecture:** 新 `style-distiller.ts` 用引擎 fastModel（首个消费者）+ submit_rules 工具调用做结构化输出（沿用 generate-script 的信任边界模式）：吃新增 EditDiff + 已有规则 → 产出语义去重后的新 WritingRule（中文祈使句 + 证据引用）。`analyzeStyleSamples` 同通道吃粘贴的爆款样本（用词癖好/句子节奏/招牌短语）。content-save 的 update 路径接通 recordDiff。新工具 `autocrew_style`（distill / absorb_samples）。**保留**：visible-learning 三件套 UX 原样（generateEditFeedback 的正则即时反馈定位为零延迟"初步观察"，不再产规则——规则唯一来源是 LLM 蒸馏，PRD 的收敛问题在规则层解决）；diff-tracker 的存储层（recordDiff/listDiffs）。**删除**：rule-distiller.ts 全文（PATTERN_TO_RULE/伪置信度/阈值计数），其测试一并删。

**设计决定（锁定）：**
- 蒸馏触发 = 显式工具调用（agent/用户驱动），不做后台定时（宿主无常驻进程；桌面壳时代再议）。`shouldDistillStyle` 供 skill 判断时机（新 diff ≥3）。
- 蒸馏状态：`<dataDir>/learnings/distill-state.json` `{lastDistilledAt: ISO}`——只蒸馏新于此的 diff，幂等可重跑。
- confidence 字段（WritingRule 必填）：由模型在 submit_rules 里自报 0-1，clamp 后入库，语义="模型对该偏好成立的把握"——比旧版 0.5+count×0.05 的伪置信度诚实；不参与任何门控（与现状一致）。
- 每次蒸馏新规则上限 3 条（prompt 约束 + 代码截断）——防规则爆炸稀释注入权重。
- 语义去重靠 prompt（已有规则全文给模型，要求只提"语义上全新"的）+ 代码层精确字符串去重兜底。

### Task 1: style-distiller 核心

**Files:** Create `src/modules/learnings/style-distiller.ts`、`style-distiller.test.ts`

```typescript
// 导出合同
export interface StyleDistillResult {
  newRules: WritingRule[];      // 已写入 profile 的新规则
  skippedDuplicates: number;    // 模型返回但与现有精确重复被兜底拦下的
  diffsAnalyzed: number;        // 本轮吃掉的新 diff 数
  summary: string;              // 给 visible-learning 风格的中文展示（🎯 学到 N 条新偏好：…）
}
export async function distillStyleRules(
  dataDir?: string,
  deps?: { runLoopImpl?: typeof runLoop },
): Promise<StyleDistillResult>;

export async function analyzeStyleSamples(
  samples: string[],            // 粘贴的爆款文本（1-5 条）
  dataDir?: string,
  deps?: { runLoopImpl?: typeof runLoop },
): Promise<StyleDistillResult>;  // diffsAnalyzed 语义复用为 samplesAnalyzed 数

export async function shouldDistillStyle(dataDir?: string): Promise<boolean>; // 新 diff ≥ 3
```

实现要点：
1. `distillStyleRules`：listDiffs → 过滤 createdAt > distill-state.lastDistilledAt（**先读 diff-tracker.ts 确认 EditDiff 的时间字段名**）→ 0 条新 diff 时直接返回空结果（不调模型，不更新状态）→ loadEngineConfig + 组装 prompt（system：风格分析师角色 + 规则要求[祈使句/具体可执行/≤3 条/不与给出的已有规则语义重复/每条带 evidence 引自 diff + confidence 0-1]；user：已有规则全文 + 每个 diff 的 before/after 节选[各截 400 字]）→ runLoop(config, {model: config.fastModel, maxTurns: 3, tools: [submitRulesTool]})。
2. `submit_rules` 工具：parameters `{rules: [{rule: string, evidence: string, confidence: number}]}`；信任边界校验照搬 generate-script 模式（数组/字符串/数值类型逐项校验，confidence clamp [0,1]，rule trim 后非空；不合规 → `Error: ...请修正后重新调用` 自纠通道）；捕获后截断至 3 条。
3. 入库：对每条先精确去重（profile.writingRules 含同文本 → skip 计数），其余 addWritingRule({rule, source: "auto_distilled", confidence})。**evidence 不入 profile**（WritingRule 无此字段，YAGNI 不改 schema），进 summary 展示。
4. 成功后写 distill-state.json（lastDistilledAt = 本轮最大 diff 时间戳）。模型未提交 → 抛错且**不**更新状态（下轮重试同批）。
5. `analyzeStyleSamples`：同通道，prompt 改为"从爆款样本提取用词癖好/句子节奏/招牌短语"，不动 distill-state。
6. 函数全部 <50 行（拆 prompt 构造/校验 helper）。

测试（mock runLoopImpl，照 generate-script.test 的 fake 模式——fake 必须真正调用 LoopTool.execute）：
- happy path：2 条新 diff + fake 提交 2 条规则 → profile 多 2 条 auto_distilled、state 更新、summary 含规则文本
- 语义自纠：fake 先提交 confidence 超界(1.5) → execute 返回错误文案，再提交合规 → 成功
- 精确重复兜底：fake 提交 1 条与现有 profile 规则全同 → skippedDuplicates=1，不重复入库
- 无新 diff：不调模型（fake 带调用计数断言为 0）、state 不动
- 截断：fake 提交 5 条 → 只入 3 条
- 未提交：抛错 + state 不动
- shouldDistillStyle：2 条新 → false；3 条新 → true
- analyzeStyleSamples happy path + 空 samples 抛参数错

Commit: `feat: LLM style distillation — fastModel first consumer, replaces regex rule mapping`
