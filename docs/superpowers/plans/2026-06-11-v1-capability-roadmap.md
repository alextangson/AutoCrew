# v1 能力图与建设顺序（2026-06-11 创始人 dogfood 后裁决）

> 背景：Agent 态壳（agent-ui 分支，已合并 `8388bc1`）上线后创始人首轮真实 dogfood，发现两类问题：bug 级（链接不读、markdown 不渲染）与结构级（回流发动机/选题雷达/知识库全部缺位）。本文档是 CTO 排序裁决，作为后续 sprint 计划的唯一事实源。PRD 对应增补：§7.1 选题雷达。

## 一、定位裁决（为什么是这个顺序）

跟主流产品拼对话/写作能力必输（通用 agent 更强）。唯一能 PK 的是 PRD §3 的结构性位置：**坐在创作者「发布—回流」工作流里的私有带标签数据集**。所以排序原则：

1. 体验 bug 先止血（第一印象决定用户给不给你机会装数据）；
2. 喂料侧补全（选题雷达 + 链接读取 + 知识库——内容生产的输入完整性）；
3. 视觉统一升级（一次设计系统落地，不碎片化缝补）;
4. 然后全力建**回流发动机**（§6，最大也是唯一不可替代的一块）。

## 三、Sprint 划分

### Sprint 1 — 体验止血 + 喂料补全（本周）
1. **markdown 渲染**：chat 气泡与卡片正文支持粗体/列表/标题/行内代码的安全渲染（自写 ~100 行解析器或白名单转 DOM，维持 textContent 纪律：解析后只产文本节点与白名单元素）。
2. **read_url 工具**：chat-router 新工具，抓网页正文（超时/大小上限/纯文本化），结果进对话上下文供写作与风格吸收；同时是选题雷达的取数原语。
3. **选题雷达 v1**：
   - 外层：热榜源清单（RSS/公开榜单，按赛道配置，源清单结构预留云端下发）→ app 启动/手动刷新拉取，缓存落盘 `~/.autocrew/topic-radar.json`；
   - 工具：`find_topics` 读缓存 → 按 profile 定位过滤 → fastModel 评分 → 选题卡（新卡型 topic，带「就这个写」按钮 = 双通道）。
4. **知识库轻版**：`~/.autocrew/knowledge/` 目录，文本文件即条目；生成时按选题关键词检索 top-k 注入 prompt；设置页给入口说明。
5. **报错与 loading 清单**：dogfood 中记到的文案/状态问题统一清掉。

### Sprint 2 — 视觉统一升级 ✅ 基底已合并（2026-06-11，DESIGN.md + 团队工牌×暖纸落地）

> 创始人验收追加两项（2026-06-11 裁决，依序执行）：
> **S2.5 Agent 实时工作状态流**：loop 工具事件 → IPC 推送（首条主进程 push 通道）→ 角色署名状态气泡（「侦察员扫热榜中… ✓ → 编剧写稿中…」），消灭「正在干活…」黑盒等待。见 2026-06-11-sprint2.5-status-stream.md。
> **S2.6 角色可编辑面板**：点团队栏 chip 打开该员工的工作档案（编剧=风格规则、侦察员=源+定位、审核员=合规级别、分析师=指标偏好）——现有设置重组进角色隐喻。S2.5 后出计划。

#### 原 S2 范围（基底部分已完成）
**核心隐喻 =「你的数字员工团队」（PRD §4 crew 呈现层裁决）**：选题侦察员/编剧/合规审核员/数据分析师四个角色拟人化，卡片署名到角色，首屏 =「你的团队今天干了什么」。design-consultation 产出 DESIGN.md（字体/色板/间距/卡片语言/角色视觉/动效）→ design-shotgun 出 3-4 版布局方案（含与主流对话产品的对标）创始人挑选 → 按选中方案整体重刷 renderer CSS（零框架不变，逻辑层不动）→ design-review 截图对比验收。流式输出视工作量决定是否随本 sprint 带上。

### Sprint 2.7 — 稿件工作台（2026-06-11 创始人 dogfood 裁决，插 S3 前）
> 依据：应用内编辑是飞轮进料口（§7.2a 编辑信号）+ 创始人网页版 qingmoagent 的成熟交互设计（框选→浮层→PendingEdit 采纳/放弃，~90% 可搬）。引擎侧版本管理（local-store versions/）与状态机 update/transition 已存在，本 sprint 主要是接 UI。
1. 可编辑稿件视图（textarea，保存=版本快照）+ 版本时间线 + 一键回滚
2. 框选改写：浮层工具条（重写/扩写/缩写/口语化 + 自由指令）→ PendingEdit diff 卡（采纳/放弃/定位）→ 采纳/放弃信号喂风格学习
3. Pipeline 揭幕：稿件按状态分组 + 单稿流转时间线（11 态状态机纯呈现）+ 合法流转操作

### Sprint 2.8 — IA 重构「任务工作台」（创始人定版方向：Accio Work 式）✅ 已完成（2026-06-11）
> 目标形态：左侧边栏 = 新任务 / 任务（会话）历史 / 数字员工 / 定时任务 / 设置与账号 + 底部积分与用户；中央 = hero 输入（带上下文 chip：赛道/知识库）/ 会话视图。**前置依赖：对话持久化**（任务列表的本体，此前声明的妥协就此解除）。智能体切换 = crew 角色对话入口；「插件」「消息渠道」「团队」预留菜单位（素材库为首个插件候选）。S2.7 后出计划。
>
> **实况注记**：对话持久化+IA 落地，crew-bar 退役，31 通道，CDP 冒烟 8/8（重启回放含卡片）。前置依赖已解除。

### Sprint 2.9 — 引用式媒体素材库 ✅ 已完成（2026-06-11，提前自 backlog）
> 目标形态：库是索引、项目是快照的媒体素材库（视频/图片/音频）——入库=引用原路径不复制；删记录永不删原文件；原文件移走→灰显「文件已移动或删除」+「重新定位」。存储 `~/.autocrew/library/`（folders.json + assets/<id>.json，原子写）。功能：导入（多选对话框，路径白名单）、扁平文件夹、标签、搜索（名称+标签）、类型筛选、图片缩略图（CSP img-src file: 实测可渲染）。稿件挂接=复制进项目目录（快照），>500 MB 先确认；挂接副本移除不影响库内原文件。编剧新增只读工具 search_assets（按名称/标签/类型检索，回素材卡）。见设计文档 `docs/superpowers/specs/2026-06-11-sprint2.9-asset-library-design.md`。
>
> **实况注记**：引用式媒体库（库是索引/项目是快照）、40 通道、search_assets 工具、CDP 冒烟 10/10（缩略图 CSP 实测）。
