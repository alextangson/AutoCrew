# v1 能力图与建设顺序（2026-06-11 创始人 dogfood 后裁决）

> 背景：Agent 态壳（agent-ui 分支，已合并 `8388bc1`）上线后创始人首轮真实 dogfood，发现两类问题：bug 级（链接不读、markdown 不渲染）与结构级（回流发动机/选题雷达/知识库全部缺位）。本文档是 CTO 排序裁决，作为后续 sprint 计划的唯一事实源。PRD 对应增补：§7.1 选题雷达。

## 一、定位裁决（为什么是这个顺序）

跟主流产品拼对话/写作能力必输（通用 agent 更强）。唯一能 PK 的是 PRD §3 的结构性位置：**坐在创作者「发布—回流」工作流里的私有带标签数据集**。所以排序原则：

1. 体验 bug 先止血（第一印象决定用户给不给你机会装数据）；
2. 喂料侧补全（选题雷达 + 链接读取 + 知识库——内容生产的输入完整性）；
3. 视觉统一升级（一次设计系统落地，不碎片化缝补）;
4. 然后全力建**回流发动机**（§6，最大也是唯一不可替代的一块）。

## 三、Sprint 划分

### Sprint 1 — 体验止血 + 喂料补全（本周）
1. **markdown 渲染**：chat 气泡与卡片正文支持粗体/列表/标题/行内代码的安全渲染（自写 ~100 行解析器或白名单转 DOM，维持 textContent 纪律：解析后只产文本节点与白名单元素）。
2. **read_url 工具**：chat-router 新工具，抓网页正文（超时/大小上限/纯文本化），结果进对话上下文供写作与风格吸收；同时是选题雷达的取数原语。
3. **选题雷达 v1**：
   - 外层：热榜源清单（RSS/公开榜单，按赛道配置，源清单结构预留云端下发）→ app 启动/手动刷新拉取，缓存落盘 `~/.autocrew/topic-radar.json`；
   - 工具：`find_topics` 读缓存 → 按 profile 定位过滤 → fastModel 评分 → 选题卡（新卡型 topic，带「就这个写」按钮 = 双通道）。
4. **知识库轻版**：`~/.autocrew/knowledge/` 目录，文本文件即条目；生成时按选题关键词检索 top-k 注入 prompt；设置页给入口说明。
5. **报错与 loading 清单**：dogfood 中记到的文案/状态问题统一清掉。

### Sprint 2 — 视觉统一升级
design-consultation 产出 DESIGN.md（字体/色板/间距/卡片语言/动效）→ design-shotgun 出 3-4 版布局方案（含与主流对话产品的对标）创始人挑选 → 按选中方案整体重刷 renderer CSS（零框架不变，逻辑层不动）→ design-review 截图对比验收。流式输出视工作量决定是否随本 sprint 带上。

### Sprint 3 — 回流发动机（护城河本体，PRD §6 蓝图执行）
Chrome 扩展（extension/ 已有雏形参照）+ native messaging + 账号绑定向导 + 定期低频只读抓创作者后台 + 回填 verify + 逐条打标到稿 + playbook 刷新。红线照 §6 全文执行。这是最大的一块，进入前单独出实施计划。
