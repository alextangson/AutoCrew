# S2.8 设计稿 — 任务工作台 IA + 对话持久化

> 状态：创始人已认可（2026-06-11，含 crew-bar 退役）。对应路线图 Sprint 2.8。
> 形态定版：Accio Work 式 — 左侧边栏 + 中央 hero/会话 + 按需滑出工作台抽屉。

## 0. 背景与问题

当前会话态是 renderer 内存数组（`desktop/renderer/chat.js` 的 `chatHistory`），
每轮取最近 12 条传 `chat:turn`，应用重启即丢——这是 Agent-UI 重构时声明的妥协。
S2.8 解除该妥协（对话持久化 = 任务列表的本体），并把 IA 重构为任务工作台。

**创始人三裁决**（2026-06-11 brainstorm）：

1. **IA 骨架** = 默认两栏（侧边栏 + 中央会话），稿件工作台/报告/风格/侦察员按需右侧滑出抽屉，S2.7 工作台体验不动。
2. **持久化粒度** = 文字 + 卡片（重开会话完整重现）；状态时间线是瞬态，不存。
3. **「数字员工」语义** = 打开 S2.6 角色面板抽屉，引擎层零改动；「定向角色对话」留给后续迭代。
4. **crew-bar 退役**——职能被侧边栏「数字员工」完全取代（整体认可时一并拍板）。

## 1. 范围：一个 sprint，两个阶段

- **Stage 1 对话持久化**：存储 + IPC + chat:turn 改造。完成即有独立价值（重启不丢会话）。
- **Stage 2 IA 重构**：侧边栏 + hero 输入 + 抽屉化 + crew-bar 退役。

## 2. 数据流归属：主进程全权

`chat:turn` 改收 `{ conversation_id?, message }`：

1. 主进程载入会话（无 `conversation_id` → 预生成 id，**首轮成功后才落盘**，失败不留空壳）。
2. 取最近 12 条消息的纯文本作为 loop history（截断策略集中于主进程，现行 12 条不变）。
3. runLoop 成功 → 把 user 消息 + assistant 回复（含本轮 cards）一次性原子追加落盘。
4. 返回 `{ ok, data: { reply, cards, tokensUsed, conversationId } }`——renderer 拿到
   `conversationId` 用于续聊。
5. 失败的 turn 不落盘（与现行为一致）；`needsSetup` 路径同样不建会话。

弃选方案：renderer 持有 history + append 通道写回——双写竞态、渲染层崩溃丢回合、
history 可被 renderer 伪造。主进程全权消掉全部三个问题。

Renderer 的 `chatHistory` 数组删除，会话连续性完全由 `conversation_id` 承担。

## 3. 存储设计（复制 contents 既有模式）

新文件 `src/storage/conversation-store.ts`（不动 local-store.ts）：

```
~/.autocrew/conversations/<id>/
  meta.json      # { id, title, createdAt, updatedAt, turns }
  messages.json  # ConversationMessage[]
```

```ts
interface ConversationMessage {
  role: "user" | "assistant";
  content: string;
  cards?: ChatCard[];   // 仅 assistant；只做回放渲染，不进 LLM 上下文
  ts: string;           // ISO
}
```

- API：`createConversation` / `listConversations` / `getConversation` /
  `appendTurn`（user+assistant 成对原子追加）/ `deleteConversation`。
  全部带 `dataDir?` 注入口（镜像 local-store 测试模式）。
- 标题 = 首条 user 消息截 30 字（超长加 …）。
- 列表只读各会话 `meta.json`，按 `updatedAt` 倒序。
- 写入一律 temp + rename 原子写；JSON 损坏的会话列表跳过 + console 警告，不炸 UI。
- id 生成与 contents 同模式（时间戳+随机后缀）。

## 4. IPC：28 → 31 通道

| 通道 | 载荷 | 行为 |
|---|---|---|
| `conversations:list` | `{}` | 元数据列表（倒序） |
| `conversations:get` | `{ id }` | 全量消息 + 卡片（回放用） |
| `conversations:delete` | `{ id }` | 删除会话目录 |
| `chat:turn`（改造） | `{ conversation_id?, message }` | §2 流程；不再收 `history` |

`channels.ts` 白名单 +3；handler 注册走既有 `buildIpcHandlers` 模式；
preload 暴露对应方法。`history` 字段从 ipc.ts 通道注释表中移除。

## 5. IA 重构（Stage 2）

### 左侧边栏（新组件 sidebar.js）

- **新任务**：中央区切回 hero 空态；首条消息发出即建会话（零仪式感）。
- **任务历史**：`conversations:list` 倒序列表，点击载入回放；删除带确认。
- **数字员工**：4 角色（侦/编/审/析），点击打开对应角色面板抽屉（S2.6 面板平移）。
- **设置**：打开设置抽屉。
- **预留禁用位**（tooltip「敬请期待」）：定时任务、插件、消息渠道、团队——与路线图定版一致。
- **底部用户区**：本地版占位（积分/账号体系 S3 后接入）。

### 中央区

- **空态** = hero 输入 + 上下文 chip（赛道 = profile.industry、知识库状态 = knowledge:status；
  只读，点击开对应抽屉：赛道→侦察员面板、知识库→设置抽屉的知识库状态区，
  即 knowledge:status 现有渲染位）。
- **会话态** = 现 chat-stream + 输入条整体平移；历史会话回放 = 文字 + 卡片按序重渲染
  （复用 cards.js 的 renderCard）。
- Onboarding 首跑流程平移到中央会话区，逻辑不动（不经 chat:turn 的引导消息不落盘，
  以 onboarding.js 现机制为准）。

### 右侧抽屉（drawer 容器）

- 现五 panel（回流报告/稿件（含 S2.7 工作台）/风格/侦察员/设置）原样移入抽屉内容区。
- 卡片点击四向路由（S2.6）从 switchPanel 改为 openDrawer，行为语义不变。
- 同时只开一个抽屉；Esc / 遮罩点击 / 关闭钮收起。

### 退役

- 顶部 crew-bar 删除（重复入口）；其 title 提示信息并入侧边栏数字员工项。
- `workspace-tabs` 删除（入口移至侧边栏/卡片路由）。

### 视觉

遵循 docs/DESIGN.md（团队工牌 C × 暖纸 A）既有 token：角色色、署名卡风格延续；
抽屉滑出动画用现有过渡时长变量；窄窗口（<900px）抽屉全宽覆盖。

## 6. 错误处理

- 会话文件损坏 → 列表跳过 + 警告；单会话打开失败 → toast + 留在当前视图。
- 删除确认（防误触）；删除当前打开的会话 → 中央区回 hero 空态。
- `chat:turn` 失败不落盘；首轮失败不留空壳会话。
