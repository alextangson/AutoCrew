# B-roll 抽帧缝检查（2026-09-30）

状态：定稿 v2。创始人已确认方向与判定规则；已吸收 Codex 会审 4 P1 / 5 P2（§12）。建在内容本体（`2026-09-29-content-ontology.md`）之上：成片事实、`chatcut_project` 事实、创始人决定、推导表。

## 1 为什么

B-roll 放完后，两段 B-roll（或动效）之间露出不到 1 秒的真人 A-roll，看起来像「抽帧」。创始人反复指出（09-29 起多次），规则早已写进技能（`personal-ip-video-loop` SKILL.md 与 evaluation-cases）仍一再违反——文字规则拦不住，要交付前的确定性检查。

## 2 创始人决定（09-30）

- 读 **ChatCut 时间线**判断，不看导出视频（主力已是 ChatCut；需要手改再导进剪映）。
- 夹在两段「盖住画面」的 B-roll / 动效之间、露出的 A-roll 短于 **1 秒**就算缝，**只闪 1 帧也算**。
- 有缝 → 先拦「成片通过」：卡片列每处时间码与修法建议，创始人可逐处点「这处是故意的」放行。
- 检查没跑成 → 同样拦，写明原因，创始人点「这条不查了，放行」才能通过。
- 时间线来源：AutoCrew **直接读 ChatCut 存在本机的工程文件**（一次读全、不靠 agent 配合）；格式认不出就明说「读不了」，不悄悄放行。
- 默认项照准：铺满 + 不透明才算盖住；淡入淡出期间真人若隐若现算露出；片头第一段 B-roll 之前、片尾最后一段之后不算；修法按原片那段声音判（无声→剪气口，有声→拖长前一段 B-roll）；agent 导出前可先自查。

## 3 数据来源（09-30 实测，一条真实的 ChatCut 工程）

- 工程目录：`~/Library/Application Support/ChatCut/projects/<projectId>/project.chatcutproject/`；时间线在 `timelines/Timeline_<hash>.json`（文件名不是时间线 id，要读文件内的 id 对上）；`project.json` 有工程元数据；内部格式 `schemaVersion 4`，不是公开接口。
- 轨道：`{id, order, type, name, hidden, locked, muted}`，order 大的画在上面。条目分 `videoItems / imageItems / motionGraphicItems / pixelEffectItems / pixelTransitionItems / audioItems / audioTransitionItems / text… `；时间单位是时间线帧（`startFrame / durationFrames`），`sourceIn` 是微秒；fps 在工程或素材元数据里（时间线文件本身没有，需确认来源）。
- 几何：`left / top / width / height`（画布像素，画布 1920×1080）、`crop*`、`opacity`、`rotation`、`blendingMode`、`fadeIn/OutDurationFrames`；动效另有素材级 `transparentBackground`（条目 `propertyOverrides` 可覆盖）。
- 字幕是时间线级对象，不在轨道里。定格（hold）是独立的图片条目（如 `X1-last`），和前一段视频几何相同，数据里没有关联。
- 素材：`inspect_asset` 同源的信息在工程文件里有 `path`、`contentSha256`、转写状态。
- 调研脚本（可参考移植）：`~/.cache/autocrew-yt/sliver-probe/detect.py`。去掉定格后能准确找出 5 处缝（6 帧 1 处、12 帧 4 处），现状 0 处。

## 4 判定

- **A-roll**：最低 order 的可见视觉轨上、素材带转写的那条（本条内容的 accepted aroll 事实对应的文件，按 `contentSha256` 或路径对上优先）。认不出 → 未检查（§6）。
- **盖住**：某帧上，存在一个 order 高于 A-roll 的可见条目，满足：裁切后矩形覆盖整个画布；`opacity = 1`、`rotation = 0`、`blendingMode = normal`；不在它的淡入淡出帧内；动效且未设透明背景。图片、视频、动效都可以盖；画中画、贴纸、字幕、`pixel-effect`（如放大）都不算。两个盖住条目之间的 `pixelTransition` 期间算盖住。隐藏轨上的条目不算。
- **缝**：A-roll 未被盖住的连续帧段，长度 1 帧到 fps−1 帧（< 1 秒），且前后紧邻的帧都被盖住。成片第一个盖住段之前、最后一个之后的露出不算。
- **修法建议**：按 A-roll 条目的 `sourceIn` 把缝映射到原片时间，用 ffmpeg 测这段原片的音量：低于阈值（相对原片说话电平，阈值实现时标定并写进报告）→「剪掉这个气口，让两段 B-roll 接上」；否则 →「把前一段 B-roll 拖长盖住」；原片读不到 → 两种都列并注明。

## 5 何时检查、结果放哪

- 触发：本轮有 accepted 的 `cut` 事实，且本轮有 `chatcut_project` 事实（`project_id`，可选 `timeline_id`）。`record kind=cut` 成功后、对账发现新成片后、`chatcut_project` 事实新增后各跑一次；同一成片 sha + 同一时间线文件 sha 只跑一次（缓存）。
- 选时间线：有 `timeline_id` 用它；否则工程里只有一条就用它；多条 → 未检查「不知道是哪条时间线」。
- 对齐：时间线总长（最后一个可见视觉条目结束帧）与成片时长相差超过 1 帧 → 未检查「导出后时间线改过，或对不上这版成片」。
- 结果存成本轮一条检查记录：`{cut_sha, timeline_sha, status: clean | slivers | unchecked, slivers: [{start_frame, end_frame, start_tc, frames, prev_item, next_item, suggestion}], reason?, checked_at}`。时间线在检查后又变 → 下次触发重跑，旧结果作废。

## 6 拦截与放行

- 推导：本轮当前成片的检查 `slivers` 且有未放行的缝，或 `unchecked` 且未整条放行 → 「成片通过」决定拒绝，missing 写「抽帧缝 N 处」或「抽帧检查没跑成：原因」；卡片列每处时间码 + 修法。
- 创始人决定（浏览器会话，模型调用拒）：
  - 「这处是故意的」：绑定 cut sha + 缝的帧区间。
  - 「这条不查了，放行」：绑定 cut sha；只在 `unchecked` 时出现。
  - 成片换了（sha 变）→ 放行不继承，重新检查。
- 已经通过的成片不回溯拦截；已发布的不查。

## 7 agent 自查

- `autocrew_content check_slivers{content_id, chatcut_project_id?, timeline_id?}`：同一套判定，只返回结果，不写事实、不影响批准。成片还没导出时用时间线自身总长，不做时长对齐。
- Codex 白名单加这一个动作；工具说明按瘦身约定写进 tool guide。
- Codex 剪辑技能（`~/.codex/skills/personal-ip-video-loop`）改口：导出前先调 `check_slivers`，有缝按建议修（定格补帧或剪气口）再导出；不再靠人工扫。改动做成补丁，合并后直接打。

## 8 失败要看得见

未检查的每种原因都写明：没有 `chatcut_project` 事实；ChatCut 工程目录或时间线文件不存在（不是 ChatCut 剪的 / 本机没装 ChatCut）；`schemaVersion` 不认识；多条时间线不知道是哪条；认不出 A-roll；时长对不上；读文件或 ffmpeg 出错（原因归类，不透传底层报错里的路径）。任何异常都落成 `unchecked`，绝不当 `clean`。

## 9 边界

E1 没有 chatcut_project 事实 → 未检查。E2 工程目录 / 时间线文件缺失 → 未检查。E3 schemaVersion 不认识 → 未检查。E4 多条时间线且没指定 → 未检查。E5 时长对不上 → 未检查。E6 隐藏轨不算。E7 淡入淡出帧算露出。E8 画中画、贴纸、字幕、pixel-effect 不算盖住。E9 透明背景动效不算盖住（素材默认与条目覆盖都看）。E10 片头片尾露出不算。E11 1 帧也算。E12 放行绑 cut sha，换成片不继承。E13 整条放行只在未检查时出现。E14 检查异常一律未检查、写原因。E15 自查不写事实。E16 未启用本体的库、图文稿、已通过或已发布的成片不查。E17 认不出 A-roll → 未检查。E18 同一成片 + 同一时间线只检查一次；时间线变了重跑。E19 两个盖住条目间的转场算盖住。

## 10 不做

不分析导出视频的画面；不读剪映工程（剪映剪的成片显示「未检查：不是 ChatCut 剪的」，由创始人放行）；不自动修（修由 agent 做）；不查已发布的旧片。

## 11 验收

- 判定单测（合成时间线，不入真实路径）：每条 E6–E11、E19 正反例；5 处缝场景（去掉定格）与 0 处场景（有定格）复刻调研结果。
- 真实数据：只读跑纠正AI 工程，结果为 0 处；把副本里的定格条目去掉后为 5 处且帧区间与调研一致（副本在临时目录，不碰 ChatCut 目录）。
- 拦截：有缝拒「成片通过」；逐处放行后可通过；未检查整条放行后可通过；换成片后放行失效；模型调用放行被拒。
- 自查：返回同样的缝，不写事实。
- 失败：E1–E5、E14、E17 都是 unchecked + 原因，无一当 clean。
- `npm run check`（低并发）全绿；codex review 无 P1/P2。

## 12 Codex 会审后的修订（09-30，优先于上文）

1. **默认拦**（P1）：「成片通过」只在当前成片有一条**有效且输入指纹匹配**的 `clean` 结果、或所有缝已逐处放行、或创始人整条放行时才允许。没有结果（没记工程、还没跑、服务中断、跑到一半）一律拦，missing 写「抽帧检查还没有结果」。校验在服务端 `decisions.ts` 的成片批准写入之前做，不只改推导和界面。
2. **成片与时间线绑定**（P1）：登记成片（`record kind=cut` 带或已有本轮 `chatcut_project` 事实）时，AutoCrew 把当时的时间线文件和它引用的素材元数据**快照**进项目（`04-edit/chatcut-snapshots/<cut_sha8>/`，只存 JSON），检查只针对快照。时间线文件的修改时间晚于成片文件的修改时间（导出后又保存过）→ 未检查「导出后时间线改过，请重新导出再报」。时长比对保留为辅助校验。子区间导出不支持 → 时长对不上即未检查。
3. **完整指纹 + 可重试**（P1）：结果键 = 成片 sha + 快照 sha（时间线 + 所引素材元数据）+ A-roll 事实 id + 检查器版本。批准前重算指纹核对；异步结果按 round、cut、指纹条件写入，过期结果丢弃。读文件等临时失败不缓存，下次触发重试。
4. **只认验证过的遮盖**（P1）：计入「盖住」只限已验证的类型与属性：视频/图片/动效条目；无圆角（`borderRadius` 为 0）；无遮罩；`attributeOverrides` 里没有未知的会影响可见性的键；图片与视频素材无 alpha 通道（ffprobe `pix_fmt` 判）；动效必须能读到透明背景设置且为不透明。读不到或不认识 → 这一条不算盖住；若因此无法判断整段 → 未检查并写明是哪一条。**绝不默认不透明**（调研脚本在读不到时默认不透明，移植时去掉）。
5. **帧率从成片读**（P2）：用成片 `r_frame_rate`（有理数）作时间线时基；读不到 → 未检查。「短于 1 秒」按 `frames × den < num` 判，不写死 30。
6. **先建 A-roll 显示区间**（P2）：按本条 accepted A-roll 事实的素材身份（sha 或路径）找出所有 A-roll 条目（可跨轨、多段），得到 A-roll 实际显示的帧区间，再减去被盖住的帧得到露出段。没有 A-roll 的空洞（黑帧）不算缝。`timelineItems` 分组/嵌套非空、同轨重叠等暂不支持的结构 → 未检查。
7. **转场不当遮盖**（P2）：转场期间一律按「可能露出」处理，若构成 <1 秒段就作为缝报出，标「转场处可能露出」，由创始人判断或放行；不因转场整条未检查。
8. **放行绑定**（P2）：逐处放行绑定 round + cut sha + 结果指纹 + 缝身份（帧区间 + 前后条目 id）；服务端核验放行对应的仍是当前结果里的那一处。已写入的成片批准不回溯拦；撤批、打回、重开后再批，按当时的检查结果重新要求。
9. **检测与建议分离**（P2）：修法建议不再测原片音量，改看本条成片的字幕事实（`srt`，`for_cut` = 这版成片）：缝所在时间内没有字幕 → 「剪掉这个气口」；有 → 「把前一段 B-roll 拖长盖住」；没有字幕或映射不明 → 「请人工判断」。建议算不出来不影响 `slivers` 结论，绝不因此降成未检查。

边界补充：E20 没有结果默认拦。E21 导出后时间线又保存过 → 未检查。E22 圆角/遮罩/alpha 素材/读不到透明设置 → 不算盖住或未检查，绝不默认不透明。E23 帧率读不到 → 未检查。E24 黑帧空洞不算缝。E25 分组/嵌套 → 未检查。E26 转场处 <1 秒露出按缝报并标注。E27 声音/字幕建议失败不改变结论。E28 放行只对当前结果那一处有效。
