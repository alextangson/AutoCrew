# IA v4.2：Dashboard 经营层 + 个性化闭环四补（设计契约）

> 日期：2026-07-08 · 状态：创始人已批方向 + codex 两轮外审收敛（记录见 §10），待创始人终裁
> 依据：PRD-v4 §7（dashboard = 经营循环的读模型）+ 创始人两轮裁决（2026-07-08：灵感源头 / 首跑校准 / 总编辑对话 / 子页面 + dashboard-first IA）
> 与 frontend-v2（2026-07-08-frontend-v2-qingmo-adoption.md）的关系：**增补修订，不推翻**。frontend v2 把 IA 收成「看板即首页」，只留生产层——PRD-v4 §7 已裁的经营层（待审队列为核、晨报、回流首屏）无家可归。本契约恢复经营层，并补齐个性化闭环的四处断裂。分期仍挂 frontend v2 的 B/C/D 期。

## 0. 核心诊断（为什么）

产品的个性化闭环 = **定位 →（过滤）灵感 →（派活）成稿 →（纠正）回喂定位与风格**。逐层核查后，这条闭环断成四截（全部有实证，非感觉）：

1. **灵感库无入水管**：国内雷达仅 2 个 RSS 源（`src/data/topic-sources.json`）且结果只进 cache 不落库；海外雷达五源写死 `save_topics:false`（`chat-router.ts:165`）；`saveTopic` 只有 MCP 层调用——**GUI 与总编辑对话没有任何一条路径能把想法写进灵感库**；顶栏「＋新想法」只是清空对话开新会话（`chat.js:57`）。
2. **首跑校准是 v1 口播时代半成品**：赛道硬编码「知识口播」（v4 P0 已是公众号）；完整四阶段校准（品牌调研→样本→A/B 验证→persona）只活在 chat/CLI skills，桌面端永远产不出 STYLE.md；**双风格存储漂移**（skills 读 `STYLE.md`，引擎读 `creator-profile.json.writingRules`）；v4 §4.3 声音内核/平台包分层与纠正路由二分类**未实现**；onboarding gate 活 bug（`tool-runner.ts:55` 硬阻断，违反「永不阻断」红线，PRD-v3:302 点名至今存活）。
3. **总编辑对话四缺口**：无上下文感知（不知用户正看哪张卡）；对话产物不能入灵感库；写操作（推公众号草稿）无内嵌确认门；会话历史有通道无 UI。
4. **经营层蒸发**：v4 §7「dashboard = 经营面板」与 v3「首屏 = 回流报告 + 归因卡」两条裁决在现 IA 中无落位。

事实修正一则：frontend v2 称「移植 qingmo calibration」，但 qingmo 前端校准页仅剩 `page.tsx.bak`——**校准中心须原生设计，无可移植前端**。

## 1. IA v4.2（裁决）

```
Dashboard（经营层，首页）
  └─ 看板（生产层，一级视图，全屏：灵感库→在写→待审→待发→已发 + 平台矩阵）
       └─ 工作台/编辑器（单稿层）
总编辑对话右栏贯穿三层（v4 §11 保留；"三栏"描述的是看板层内部布局）
```

- 看板是**一级全屏视图**，不是 dashboard 内嵌小组件（拖拽与平台矩阵需要全宽）；dashboard 放**管线摘要卡**（各列计数 + 待审队列直接展开）。
- 平台矩阵中英文行（Twitter/Instagram/Reddit「席位未开通」）**默认折叠**——裁决 F 的诚实呈现保留，但不日常占据视觉、不制造「快能扩平台」的暗示（codex 外审收敛）。
- 对 v4 §11「五页导航作废」的修订：首页从内容流改为经营面板。
- 用户习惯依据：① 创作者每日首个动作是看读数（回访钩子，v3「数据成熟是天级事件」）；② 团队隐喻自洽（晨报墙→车间→工位）；③ 空态即 onboarding（见 §3）。

## 2. Dashboard 组件转正制（红线：假活性 / 未转正不展示 / 宁缺勿假）

| 批次 | 组件 | 数据来源 | 前提 |
|---|---|---|---|
| **一（数据已真实，随 C 期）** | **待审队列**（§7.3-2 核心组件，全功能）、**回填待办卡**（确认已发布→自动生成回填待办，T+1 提醒、T+3 拖延告警、回填后出归因卡——补齐 v4 §7.3-2 点名的三组件）、**校准状态卡**（规则数 + 最近学到，全功能）、任务动态带（runId）、管线摘要卡（朴素版）、**灵感摘要卡**（朴素版） | 本地 store + 引擎 SSE | A1/A2 入水管先通 |
| **二（通道建好后）** | 账号现状（粉丝/阅读曲线）、对标账号动态、情报源健康度 | 公众号摄取通道（短期 CSV 复用 `flywheel:import_csv`，长期扩展扩公众号后台，§6 只读红线内）、A3、A1 源配置 | 数据通道立项 |
| **三（P1 后）** | 目标卡（粉丝/更频目标）→ 总监按目标排产 | 目标模型 + 总监 L2 | 硬前提：文案转正（v4 §8 排序不动） |

**第一批内部再分主次**（codex 外审收敛）：待审队列、回填待办、校准状态三卡做全（它们直接驱动下一步动作）；管线摘要、灵感摘要先做朴素版——**砍壳的视觉完整度，不砍卡的行动力**。

- **待审队列排序规则**：过期告警 > 发布窗口临近 > 新完成；配「连续审稿模式」（审完一篇一键下一篇，晨审动线不回列表）。
- **灵感摘要卡形态**（= 轻版「今日选题裁决台」）：不是计数器，是**今日 top-3 可写机会 + 入库理由 + 一键开写**（纯读模型排序：定位命中 × 新鲜度 × 来源权重，不等总监 L2）。独立裁决台页面等 A1/A3 数据源成熟后再议。
- 目标卡定位：不只是展示——它是总监 L2 从「定时跑批」升级为「按经营目标排产」的排产依据。

## 3. 首跑动线（Day-1 热启动的 v4 落位）

新用户首开 → 落 Dashboard 全空态 → **双通道等价**（v3 双通道裁决）：右栏总编辑开场引导，或点任意空态卡直达对应设置。

- **默认链 = 公众号**（修正现 onboarding 硬编码「知识口播/抖音 CSV」的 v1 心智；口播作为第二席位在赛道确认里可选）。
- 空态文案即引导：风格卡「10 分钟校准你的声音」/ 账号卡「连接你的公众号」/ 对标卡「添加 3 个对标账号」/ 灵感卡「接通情报源」。
- 校准**执行过程在对话里跑**（四阶段校准本就是对话式，skills 已有）；dashboard 风格卡 = 入口 + 状态显示。**禁止把校准做成 dashboard 表单页**（onboarding 墙还魂）。**无历史作品分支**：3 句偏好问答种子化（v3 既有裁决），后续靠纠正飞轮补。
- 校准完成 → 声音内核 v0 + playbook 报告卡（10 分钟 wow）+ 3 张种子灵感卡落库 → **总编辑主动发起「首稿陪跑」**：选题确认 → 生成 → 审改 → 凭据 just-in-time 检查 → 推草稿 → 回执，每步对话内嵌卡片。不做独立 wizard 页——首稿是一次任务流，不是低频配置（codex 外审收敛）。
- 三红线继承：永不阻断 / 每步可跳过 / 绝不问 API key。

## 4. 灵感库五条入水管（A）

灵感库 = 一切「值得写」想法的唯一入口池。灵感卡必须带**入库理由**（命中定位词 / 对标爆款 / 读者追问）+ 来源徽章，否则退化为 RSS 收件箱。stale 卡 14 天自动沉底归档。

| # | 入水管 | 设计 | 排期 |
|---|---|---|---|
| A1 | 雷达自动入库 | 每日 top-N 经**定位过滤 + 查重**后写 Topic；源清单进设置可配置（垂直源订阅）；海外雷达打开持久化 | 近程 |
| A2 | 对话入库 | chat 加 `save_topic` 工具；候选卡加「存入灵感库」按钮；「＋新想法」语义修正为**直落灵感卡**（顺手起会话） | 近程 |
| A3 | 对标拆解（收窄版） | **手动贴对标文章 URL → `read_url` 拆解 → 拆解卡入库**（钩子/结构/CTA）；持续监控系统推到情报员转正后（codex 外审收敛：单人 dogfood 期不需要监控系统） | P1 |
| A4 | 回流反哺 | 已发内容评论区问题 → 灵感卡（读者问什么写什么） | P2 |
| A5 | 历史资产 | 首跑导入代表作中未挖尽的角度，校准副产物入库 | 随 §3 |

**派活接缝（关键防蒸发）**：平台矩阵「生成」与灵感摘要「一键开写」的 brief **必须携带 Topic 全量上下文**——入库理由、来源、证据链接、定位命中词——而不是只传标题（现状 `sendChat("用选题《标题》写…")` 会让灵感库的全部增值信息在派活瞬间蒸发）。

立场：对创作者最值钱的选题源是「定位 ×（读者追问 + 个人存量观点）」，热点只是借力——A1 的定位过滤器是灵魂，定位来自 §3/§5。

## 5. 风格校准统一（B）

- **B2 统一存储**：`creator-profile.json` 为唯一机器事实源；STYLE.md 降级为渲染视图或淘汰。`writingRules` 加 `scope` 字段（`voice_core` | `platform:wechat_mp`），落 v4 §4.3 分层 + 「≥2 平台重复纠正→升格声音内核」路由。
- **B3 拆 onboarding gate**（渐进画像 skill 层已有，中间件硬闸门删）。
- **B4 校准中心原生设计**，归设置：定位档案、规则清单（可停用可编辑）、「最近学到的 N 条」、重新校准 + A/B 验证入口。首跑入口在对话（§3），设置里是回访面。
- **B5 飞轮可见闭环**（外审共识，纠正飞轮的感知面，三点连成线）：
  1. 改稿保存触发学习时，即时轻提示「学到了：{规则}」（visible-learning 落 UI）；
  2. 下一稿生成时，稿件卡标注「本稿应用了你上次的 N 条纠正」（点开可见明细）——**让"越用越像你"可感知**；
  3. 校准状态卡「最近学到」长期可见（§2 第一批）。
- **B6 弃用原因 chip**：采纳三键保持零负担（§10-B 裁决不动）；仅 `rewritten`（最强负信号）时出**可选**一键原因 chip（风格不像 / 事实错 / 结构差），直接喂 §4.3 纠正路由。

## 6. 总编辑补口（C）

- **C1 上下文感知**：`chat:turn` 带 `{view, selected_content_id, selection}`，prompt 注入「用户正看着 X」。
- **C2 产物入库**：`save_topic` 工具 + 生成类回复统一带按钮组（打开工作台 / 存灵感 / 换角度）——按钮与输入等价（双通道）。
- **C3 确认门 + 原地续跑**：推草稿等写操作先出内嵌确认卡再执行（v3 红线）。**发布失败的恢复路径产品化**（codex 外审补漏）：凭据缺失/过期/quota 不是裸报错，而是「缺什么 → 去哪里补 → 补完重试同一稿」的**原地续跑卡**——点卡内按钮直达设置对应项，配置完成回到卡上一键重推，不丢上下文。
- **C4 会话历史 UI**：通道已有（`conversations:list/get`），**降 P1**（当前断点在入库/上下文/确认门，不在找旧聊天——外审收敛）。
- **C5 预算分级**：对话轮保持 `maxTurns=6/20k`；长文生成链单独预算档（`loop.ts:278` 现为全局硬编码）。
- 总编辑 system prompt 注入**定位摘要**（不注入全量风格——总编辑不写稿，写手席才吃声音内核，§4.3 隔离本意）。

## 7. 菜单收敛（D）

- 菜单四项：素材库 / 复盘(records) / 回收站 / 设置。风格档案并入设置=校准中心；drafts 面板死；死代码 `today.js` 随 D 期清场。
- **选题雷达页缓期**：保留作雷达调试面**直到 A1 自动入库落地验证**，再收进设置（外审收敛：清场不抢先于链路验收，保留调试入口）。
- 设置完整 IA：引擎（开发者区折叠）/ 定位与校准中心 / 情报源（RSS 清单+对标账号）/ 平台连接（扩展状态、公众号凭据）/ 发布授权（分级 opt-in，B 级逐平台，对齐 §6 分级表）/ 数据导入导出。
- **待发列卡片带「建议发布窗口」标注**（按平台节奏与已发间隔的轻规则）；完整发布日历排 P2。
- **素材缺口卡**（P1.5，随素材员工最小形态）：写手生成时内联标注 `[缺图:描述]` `[缺案例]` `[缺数据]`，审稿时工作台侧栏列缺口清单，点击 → 素材库检索 / AI 生成候选——直接服务「轻改即用」。

## 8. 数据缺口（不装看不见）

公众号粉丝/阅读数据**现无任何摄取通道**（扩展仅抓抖音作品数据）。第二批「账号现状」开工前必须先裁数据来源（CSV 定期导入 vs 扩展扩公众号后台）。通道未建则账号卡不上——宁缺勿假。

## 9. 优先级（全部绑 P0 北极星「采纳率」）

1. **B2/B3 + 声音内核注入公众号链核查**（harness 修复，决定「像不像你」，先于一切 UI）
2. **A1/A2 + C2 + §4 派活接缝**（近程入水管 + brief 防蒸发，改动量小）
3. **C1/C3**（上下文感知 + 确认门 + 原地续跑）
4. **§3 首跑编排（含首稿陪跑）+ Dashboard 第一批**（挂 frontend v2 C 期；三主卡全功能、两摘要卡朴素版）
5. **B5/B6 飞轮可见闭环**（随工作台迭代，dogfood 动力面）
6. **第二批组件 / A3 / A4 / 素材缺口卡 / D 完整化**（随数据通道与员工编制走）

**硬约束：任何一项与 P0「质量合体 + 采纳率≥50%」抢工期 → 让路。**

## 10. 外审记录（codex，2026-07-08，两轮）

- 第一轮 15 条：**10 条采纳**（首跑公众号心智、brief 防蒸发、待审排序、飞轮可见性、回填待办链、发布窗口轻版、素材缺口卡、会话历史降级、对标收窄、清场缓期）；**3 条反驳成立**（采纳记录器已存在且重方案违背 §10-B 低摩擦裁决；Dashboard 分批表已是防御；英文席位是裁决 F 显式呈现）；**2 条分歧**进第二轮。
- 第二轮全部收敛：采纳三键 + rewritten 可选 chip（B6）；第一批保留但砍壳的视觉完整度（§2 主次分级）；英文行默认折叠（§1）；首稿陪跑胜出 wizard（「首稿是一次任务流，不是低频配置」）；选题裁决台轻版够用（§2 灵感摘要卡形态）。
- codex 终轮补漏 1 条被采纳：发布凭据失败的**原地续跑卡**（C3）。
