# AutoCrew 混合素材剪辑师：小Lin说节奏对标研究与改版规格

> 日期：2026-09-03  
> 状态：研究结论 / 待实现  
> 适用范围：真人口播 A-roll 已完成，AutoCrew 依据 SRT 规划、采购并组装 B-roll、证据画面、图解和趣味素材。  
> 核心判断：当前问题不是“生成画面质量不够”，而是剪辑师把 B-roll 等同于“长时长、整屏、待生成画面”。要对标小Lin说，必须从 **B-roll 生成器** 改为 **按表达功能路由素材的时间线导演**。

## 1. 样本与方法

本次实际查看并下载分析三条同账号竖屏口播：

| 样本 | 时长 | 可检测镜头 | 平均镜头 | 中位镜头 | < 1.5s | < 3s | > 6s |
|---|---:|---:|---:|---:|---:|---:|---:|
| [Deepseek 突然连融两轮 500 亿](https://www.douyin.com/video/7680801661580741926) | 386.57s | 115 | 3.36s | 2.33s | 31.3% | 56.5% | 14.8% |
| [电，怎么卡住了 AI 的脖子？](https://www.douyin.com/video/7660817965343870248) | 341.23s | 119 | 2.86s | 2.20s | 32.8% | 68.1% | 10.9% |
| [养猫一年花 1500 亿，年轻人怎么想的？](https://www.douyin.com/video/7674134024641727787) | 322.33s | 123 | 2.62s | 1.90s | 35.8% | 72.4% | 8.1% |

合计 17 分 30 秒、357 个可检测镜头，约 **20.4 次画面切换/分钟**；约 65.8% 的镜头不满 3 秒。检测口径为缩放到 270px 后、场景阈值 0.18 的硬切检测。它会漏掉同一画面内的推拉、局部放大、字幕/图层变化，因此这些数字是视觉变化频率的保守下界，不是逐帧真值。

这是竖屏样本，AutoCrew 的 16:9 项目不照搬版式；借用的是节奏和“每次切画面承担什么功能”的语法。

## 2. 观察到的剪辑语法

### 2.1 节奏来自功能切换，不来自一直运动

小Lin说不是用 B-roll 铺满口播，而是在以下状态之间快速轮换：

1. **A-roll 直面观点**：关键判断、反问、转折、结论回到人脸。
2. **证据画面**：新闻标题、原始网页、产品页面、报告/图表、人物照片、采访或发布会片段。
3. **现实素材**：服务器、电厂、机房、食品、宠物、实验室等与名词和动作直接对应的真实画面。
4. **解释图形**：数字、流程、层级、地图、对比、关键词章节卡。
5. **趣味断点**：表情包、UGC、小动画、彩条、夸张数字等，只在笑点、吐槽或情绪峰值短促出现。
6. **主持人 PiP**：证据或现实素材全屏时，把主持人保留在圆形画中画里，既不中断讲述关系，也不牺牲信息画面。

画面变化的价值是“换一种认知动作”：看人、看证据、理解结构、感受情绪。连续换十个同质的 AI 工业镜头，虽然也在切，但认知动作没有变，所以仍然显得平。

### 2.2 三个主题使用三套内容视觉

- DeepSeek：融资新闻、人物、官方引语、网页/API、行业现场、芯片和数据中心；趣味素材只做少量反差。
- 电力：发电厂、输电、电气柜、ATS/UPS、机房运维、系统示意图；画面高度贴着具体名词走。
- 猫经济：大量真实猫视频、宠物 UGC、商品/品牌片段、平台页面、卡通解释和更高频的喜剧断点。

因此不应建立“整条视频共用一个视觉世界”。应该只固定栏目识别层，例如字体、字幕、主持人 PiP、章节卡和少量转场；内容层必须随主题和段落变化。

### 2.3 表情包不是装饰，是标点

表情包适合四类位置：

- 预期落空：忙了半天一个字没写。
- 金钱疼痛：钱烧了不少、贵三到十倍。
- 自嘲反转：我以为有团队，其实一个 AI 自言自语。
- 复杂信息后的喘息：连续讲完一段研究或机制后，用 0.4–1.2 秒释放压力。

不应按固定间隔塞表情包，也不应拿影视剧盗版片段自动入库。候选必须记录出处和授权状态；权利不明时只展示候选，等人确认。

## 3. 当前 AutoCrew 为什么必然做不出这种效果

这不是只改 prompt 能解决的问题，现有数据结构和硬规则本身就在阻止目标节奏：

1. `editor.ts` 把任务定义为“挑几个地方盖整屏 B-roll”，来源只有 `asset` 或 `generate`，没有搜索、证据、表情包、图解和 A-roll 镜头变化这些意图。
2. 素材目录为空时，prompt 明确告诉模型“全靠 generate 槽”，因此生成镜头会天然吞掉所有空缺。
3. 软目标把屏录设为 4–20 秒、图版 3–15 秒；而三个样本中 56.5%–72.4% 的可检测镜头不到 3 秒。
4. 开头 30 秒和结尾 15 秒完全禁止覆盖轨；样本恰恰在开头用高频证据、现实画面和 PiP 完成钩子。
5. 每两段覆盖轨之间强制 5 秒整屏露脸，导致无法形成连续的“证据 → 图解 → 现实画面”短蒙太奇。
6. 当前规格明确不做 SFX、zoom，也没有 PiP、分屏、截图局部高亮等小Lin说常用的表现手段。

结论：当前系统不是“审美没调好”，而是被建模成了 **整屏覆盖轨排布器**。要改成 **视觉事件时间线**。

## 4. 新的工作单元：视觉事件，而不是 B-roll 槽

建议将计划契约升级为：

```ts
type VisualEvent = {
  eventId: string;
  outputStartMs: number;
  durationMs: number;
  narration: string;
  purpose: "hook" | "proof" | "concretize" | "explain" | "emotion" | "reset";
  layout: "aroll" | "aroll_punch" | "full" | "host_pip" | "split" | "card";
  sourceIntent:
    | { kind: "provided"; assetId: string; inMs?: number; outMs?: number }
    | { kind: "evidence_search"; query: string; preferredDomains?: string[] }
    | { kind: "stock_search"; query: string }
    | { kind: "meme_search"; emotion: string; action: string }
    | { kind: "graphic"; template: string; content: Record<string, unknown> }
    | { kind: "generate"; mediaKind: "video" | "image"; prompt: string };
  motion?: "cut" | "fade" | "crop_zoom" | "push" | "highlight";
  hostVisible: boolean;
  reason: string;
};
```

这里 `aroll` 和 `aroll_punch` 也是事件。没有新素材不等于没有剪辑：改变景别、加关键词、停顿卡点同样可以制造节奏。

## 5. 素材路由优先级

每个语义 beat 先判断表达功能，再选来源：

| 文案表达 | 第一选择 | 第二选择 | 禁止默认 |
|---|---|---|---|
| 人名、公司、金额、研究、新闻、引用 | 官方页面/原始报道/报告截图 | 带出处的新闻或人物素材 | 抽象 AI 画面 |
| 具体物体、行业、动作、场景 | 用户提供或有授权的真实视频 | 授权素材库 | 无关的未来工厂 |
| 流程、对比、层级、数字关系 | 确定性图解/动效 | 简单实物隐喻 | 生成一台机器代替逻辑 |
| 吐槽、反转、尴尬、意外 | 表情包/UGC/简短反应镜头 | A-roll 表情放大 | 每句话都塞梗 |
| 无法实拍、需要强隐喻的概念 | AI 生成 | 程序化图形 | 把所有段落都统一成一个生成世界 |
| 核心观点、反问、总结 | A-roll | A-roll + 关键词 | 用 B-roll 盖住人 |

默认优先级：**原始证据 → 用户素材 → 有授权现实素材 → 程序化图形 → AI 生成**。AI 生成是补洞工具，不是默认素材库。

## 6. 建议节奏参数

下面是对标目标，不应全部变成死规则；硬校验只守安全、时间和版权边界。

- 开头 0–10 秒：4–7 个有意义的视觉状态，可以有 A-roll，但不能整段静止。
- 普通解释段：可检测视觉事件中位数 1.8–2.8 秒；60%–75% 不超过 3 秒。
- 现实 B-roll：通常 1.0–3.0 秒；动作确有展开才延长。
- 证据截图：通常 2.0–4.5 秒，用裁切、推近和高亮引导阅读，不把整页原样挂着。
- 图解：单步 1.0–2.5 秒；复杂图按步骤揭示，不一次塞满。
- 表情包/反应镜头：0.4–1.2 秒；通常每 20–45 秒最多一个，必须对上情绪标点。
- AI 生成镜头：通常 2.0–4.0 秒；不允许连续超过两条，不允许成为同一章节的主要画面来源。
- 主持人连续完全不可见原则上不超过 10–12 秒；host PiP 计为可见。
- 不再要求每两条 B-roll 之间完整露脸 5 秒；改为限制“连续缺少主持人锚点”的时长。
- 生成素材总时长建议控制在成片的 8%–15%；整屏 B-roll 总覆盖可在 35%–50%，但主持人通过 PiP 的可见时长应达到约 65%–80%。

## 7. 当前《AI 团队》视频的混合素材重排方向

| 文案章节 | 应主导的画面 | 可保留的生成隐喻 | 应优先替换的旧倾向 |
|---|---|---|---|
| 一个人开公司 / 十个 AI 员工 | A-roll、岗位名称快速卡、真实 agent/UI 录屏、1 个反应梗 | 一次“AI 团队出现”的强设定镜头 | 连续工业流水线 |
| 跑十几分钟 / 通讯记录 / 一个字没写 | 聊天记录界面、进度卡住、空白文档、成本数字、短表情包 | 最多一个“循环交接”隐喻 | 多条相似传送带 |
| agent / 多智能体背景 | 实际产品界面、工具调用、简单关系图 | 一个能体现“自己拆步骤”的短镜头 | 泛科技机房 |
| 坑一：交接损耗 | 装修真实素材、砸墙/返工、聊天转述；Anthropic 与 Berkeley 原始页面/图表 | 一次信息逐层衰减图解 | 把论文证据做成抽象机器 |
| 坑二：人的岗位补丁 | 外科、会计、设计的现实蒙太奇；“补丁”二维图解 | 一个极短补丁隐喻 | 重复的车间/机械臂 |
| 坑三：context rot | 真实长对话/文件滚动、桌面拥挤图解、关键词被埋 | 一次桌面隐喻即可 | 多组不同工业房间表达同一件事 |
| 规矩一：共享事实、隔离规则 | 原件/摘要对比、独立白板、按内容切段的图解 | 不必生成视频 | 复杂门、管道、机械系统 |
| 规矩二：脚本→工作流→单 agent→多 agent | 四级台阶图、真实自动化/表格/终端录屏、数字 3–10× | 仅用于难以实拍的概念过渡 | 每一级都生成一台机器 |
| 规矩三：标准答案 / 独立检查 / 权限 | 文件校验、敏感词扫描、权限弹窗、白纸审稿人图解 | 一次权限边界隐喻 | 反复出现门禁或流水线 |
| 六个岗位变脚本 | 真实脚本运行、文件归档、ffprobe/检查结果、8/13 数字卡 | 不需要 | 抽象“裁员机器” |
| 五个派发者从未派发 | 调度日志、零派发计数、单 AI 自言自语、A-roll 反转 | 结尾可留一个强隐喻 | 继续展示团队工厂 |

建议不要废掉现有 58 条生成素材，而是做三类处理：

1. **保留**：确实与某个具体表达一一对应、且能成为章节记忆点的少数镜头。
2. **缩短**：把原来 5–10 秒的生成镜头裁成 1.5–3.5 秒，只承担一次语义强调。
3. **替换**：凡是涉及真实机构、研究、软件界面、数字和具体生活场景的段落，优先换成证据、录屏、现实素材或图解。

对 11 分 42 秒成片，建议把“58 条 B-roll”升级为约 **200–240 个视觉事件**（已有 A-roll 硬切也计入）。它们不等于 200–240 份素材：A-roll 景别变化、同一截图的两次裁切、数字卡和 PiP 变化都算事件。建议准备约 55–75 份独立资产，其中 AI 生成视频约 8–12 条，而不是继续追加几十条生成视频。

## 8. AutoCrew 的执行结构

不要建立“找素材 agent → 图解 agent → 生成 agent → 剪辑 agent”的长交接链。按内容段落给一个 `SegmentDirector` 完整负责 30–60 秒，它看到该段完整 SRT、A-roll 和必要事实，并调用以下工具：

- `evidence_search`：找官方页面、新闻、报告、人物/产品证据。
- `stock_search`：找可商用的真实素材。
- `meme_search`：找情绪相符的表情包/UGC 候选，附权利风险。
- `graphic_render`：生成可编辑、确定性的图表、数字和章节卡。
- `generative_media`：只有前四项都不合适时才调用。

确定性脚本负责：时间码边界、素材时长、去重、清晰度、比例、指纹、出处/授权字段、覆盖率和连续主持人缺席时长。另设独立 `RhythmCritic`，只看原 SRT 和最终预览，不看 SegmentDirector 的思考过程，检查是否贴词、是否重复、是否平、笑点是否过量。

这保留了“按内容拆”的一致性，也避免再造一条岗位交接流水线。

## 9. 人工门应看到什么

每个视觉事件在门内用同一格式展示：

```text
N023｜02:14.200–02:16.000｜“十几分钟，一个字都没写出来”
功能：emotion / 预期落空
版式：host_pip + 全屏空白文档
来源：meme_search / stock_search（候选 3 条）
选中素材：blank-doc-loading-02.mp4，源 00:01.2–00:03.0
动效：hard cut，末尾 2 帧白闪
原因：把“零产出”具体化，并在长解释后制造一次短促笑点
出处/授权：URL、作者、许可、抓取日期、文件指纹
```

用户可以逐条选择：保留、换候选、改搜索词、改成 A-roll、改图解、才改为 AI 生成。确认前先给三个代表样片：一个证据段、一个解释图解段、一个趣味段；通过后才批量采购和渲染。

## 10. 验收条件

- 0–10 秒至少出现 4 个有信息意义的视觉状态，且不是 4 个同类生成镜头。
- 60% 以上可检测视觉事件不超过 3 秒；长截图必须有分步高亮或裁切变化。
- 真实机构、金额、研究与引用优先出现原始证据，不用抽象画面代替。
- 任何章节不得连续出现 3 条 AI 生成视频；生成视频总时长不高于目标上限。
- 表情包必须对上明确情绪 beat，且每条都有出处/权利状态；权利不明不能自动进入正式成片。
- 主持人锚点满足连续缺席上限；长证据段使用 PiP 或在前后回切 A-roll。
- 同一视觉母题连续复用不得超过两次；“工业流水线”只在字面谈流程时使用。
- 每个事件都能追溯到 SRT 句子、时间码、素材来源和选择理由。
- 人工门先审三个代表样片，再允许全片批量执行。

## 11. 实现顺序

1. **P0：契约与节奏**——引入 VisualEvent、sourceIntent、layout、purpose；取消 30 秒无覆盖和 5 秒露脸间隔，改成主持人可见性约束；支持 0.4 秒事件。
2. **P1：搜索与台账**——加入 evidence/stock/meme 搜索槽、候选列表、出处和授权字段；无素材时不再自动等于 generate。
3. **P2：表现层**——加入 host PiP、A-roll punch-in、截图 crop/zoom/highlight、分屏、章节卡和受控 SFX cue。
4. **P3：参考驱动 QC**——保存节奏 profile，比较场景时长分布、来源混合度、重复母题和主持人缺席区间；只把指标当警报，不机械追数。
