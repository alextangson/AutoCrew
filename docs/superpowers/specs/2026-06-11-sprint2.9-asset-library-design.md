# S2.9 设计稿 — 素材库（引用式媒体仓库）

> 状态：创始人已认可（2026-06-11）。对应路线图 backlog「素材库」提前（创始人裁决：dogfood 前把功能做全）。
> 参照：qingmoagent（/tmp 克隆）Asset/Folder 模型，砍掉组织/共享/积分/AI 生成后本地化。

## 0. 背景与三裁决

AutoCrew 已有**稿件级**素材机制（`src/tools/asset.ts` + local-store `addAsset`，可从
sourcePath 复制文件进项目目录），但从未暴露到桌面 UI，且装不下「还没用于任何稿件的素材」。

**创始人裁决**（2026-06-11 brainstorm）：

1. **定位 = 媒体仓库**（视频/图片/音频）。文字素材归 S1 知识库，不重复建设。
2. **入库 = 引用原路径**（库体量大，不复制）。后果全链承担：失效检测、重新定位、删除只删记录。
3. **方案 = A 独立引用式素材库**：「库是索引，项目是快照」——挂接到稿件时沿用现有
   `addAsset` 复制语义，已发布稿件素材自包含；插件机制不建（v1 就一个候选，过度工程）。

## 1. 数据模型

```
~/.autocrew/library/
  folders.json        # LibraryFolder[]（扁平一层，v1 不嵌套）
  assets/<id>.json    # 每素材一文件
```

```ts
interface LibraryFolder { id: string; name: string; createdAt: string; }   // folder-<ts>-<rand>

interface LibraryAsset {
  id: string;            // asset-<ts>-<rand>，正则校验（renderer 可控输入）
  name: string;          // 显示名，默认=文件名，可改
  path: string;          // 原文件绝对路径（引用，不复制）
  type: "video" | "image" | "audio" | "other";   // 按扩展名判定
  ext: string;
  size: number;          // 入库时记录的字节数
  folderId: string | null;
  tags: string[];
  description?: string;
  addedAt: string;
}
```

- **失效检测**：`library:list` 时逐素材 `fs.access(path)`，失败 → 返回值带 `missing: true`
  （计算值，不持久化）。UI 灰显 +「重新定位」（重选文件更新 path/size/ext/type）/「移除」。
- **删除素材 = 只删 JSON 记录，永不删原文件**（引用模式安全底线）。
- 原子写：把 conversation-store 的 `writeJsonAtomic`/`readJson` 抽成共享
  `src/storage/json-atomic.ts`（conversation-store 同步改用，行为不变）。
- 文件夹删除 → 其内素材 `folderId` 置 null（回「全部」），不删素材。
- 损坏 asset JSON：list 跳过 + console.warn（同 conversation-store 容错模式）。

## 2. 新存储模块

`src/storage/library-store.ts`：`addAssets(paths[], folderId?)`（批量；按扩展名定 type；
重复 path 幂等跳过并报告）/ `listLibrary()`（folders + assets + missing 标记）/
`updateAsset(id, patch)`（name/tags/description/folderId/relocate path）/ `removeAsset(id)` /
`createFolder(name)` / `removeFolder(id)`。全部带 `dataDir?` 注入口。

## 3. IPC：31 → 40（9 新通道）

| 通道 | 载荷 | 行为 |
|---|---|---|
| `library:list` | `{}` | folders + assets（含 missing） |
| `library:add` | `{ paths[], folder_id? }` | 路径必须命中 picker 白名单（沿用 import_csv 纪律） |
| `library:update` | `{ id, name?/tags?/description?/folder_id?/path? }` | path 重定位同样要求白名单命中 |
| `library:remove` | `{ id }` | 只删记录 |
| `library:folder_create` | `{ name }` | |
| `library:folder_remove` | `{ id }` | 素材回根 |
| `dialog:pick_media` | `{}` | 多选，媒体过滤器；main.ts 真实现 + 路径登记（复用 createPickedFileRegistry） |
| `content:asset_add` | `{ content_id, library_id }` | 从库挂接：查库取 path/name/type → 现有 `addAsset` 复制进项目；>500MB 由 UI 先弹确认 |
| `content:asset_remove` | `{ content_id, filename }` | 移除项目内挂接（删项目 assets/ 文件 + meta 记录） |

> 设计呈现稿曾写 31→38，遗漏挂接两通道——以本表 40 为准（spec 自审修正）。

- **侧边栏**：数字员工区下方新增一级项「素材库」→ 开抽屉 `panel-library`（DRAWER_TITLES
  +1）；「插件」预留位不动。
- **素材库面板**（新 `desktop/renderer/library.js`）：
  - 工具条：导入素材（pick_media 多选）/ 新建文件夹 / 搜索框（名称+标签）/ 类型筛选。
  - 文件夹列表（全部 / 各文件夹），点击过滤。

## 5. Chat 工具（对话驱动一致性）

`search_assets`（只读）：按关键词（名称/标签）+ 可选类型过滤检索库，回紧凑 JSON
（id/name/type/tags/missing），并 sink 一张 `assets` 卡（新卡类型，列表+「打开素材库」按钮
→ openDrawer("library")）。CREW_TOOL_STATUS 归编剧（「编剧在翻素材库」）。
不给写入工具（导入/删除走 UI，防模型误删）。

## 6. 错误处理

- 原文件不可读/不存在：list 标 missing，不炸面板；挂接时 copyFile 失败 → toast +
  不留半截记录（先 copy 后写 meta，失败即中止）。
- `library:add` 收到未登记路径 → `{ok:false}`（白名单纪律）。
- folders.json / asset JSON 损坏 → 跳过 + warn（folders.json 损坏视为空列表 + warn，不覆盖
  原文件，下次成功写入才修复）。
- id 正则校验（`asset-`/`folder-` 前缀）防路径穿越，复用 S2.8 safeConvDir 模式。

## 7. 测试

- **library-store 单测**：CRUD、批量去重、missing 标记（真实 fs：建临时文件→删→list）、
  folder 删除回根、损坏容错、原子写、id 校验/路径穿越、relocate。
- **json-atomic 抽取**：conversation-store 测试保持全绿（重构不改行为）。
- **ipc 测**：9 新通道注册 + 白名单计数 40 + library:add 白名单拒绝 + content:asset_add
  挂接复制（临时文件实测）。
- **chat-router 测**：search_assets 工具（命中/空库/missing 标记透传）。
- **CDP 冒烟**：导入（picker 经 deps 注入或预登记）→ 打标 → 搜索过滤 → 重启仍在 →
  人为移走原文件 → 灰显 + 重新定位 → 挂接到稿件（工作台可见）→ 移除记录原文件仍在。

## 8. 明确不做（YAGNI）

文件夹嵌套；AI 自动标签；视频缩略图 / markers / b-roll 推荐（S3 后有视觉模型再说）；
组织/共享/积分；拖拽导入；插件机制；素材去重（同文件多记录允许，幂等只按 path）；
库内预览播放器（v1 视频/音频无预览，仅图标与元信息）。
