# 选题会：用定位 + 数据下注，而不是按灵感库顺序写

状态：v2 草稿。v1 经独立评审（Codex 额度用尽，由无上下文的 Claude 审稿代理替代，结论已对照代码抽查）后重写：下注并入现有假设台账，简报复用 insights 统计层，删掉重复字段。等创始人确认 §0.3、§6 后交 builder。

## 0. 背景

### 0.1 为什么要做

- 灵感库只有「受众契合 / 素材 / 新鲜 / 时效」四维入库分；立意卡的分只是证据支撑度（`angle-stage.ts` 自注「不代表传播潜力」）。账号数据只通过复盘→编辑实验一条细线影响写稿，不进选题、不进立意。
- 截至 09-26 的 11 条内容：抖音 Harness 一条 32 万播放、涨粉 733，占抖音累计约 82%，之后没有续集；教学稿攒收藏但 5 秒完播最低（四件套 22.7%），观点/亲历 5 秒完播最高（41–45%）。增长靠单点爆款，没有接力。
- 立意卡收益太空：`topic-1790649955943-bynnpv` 的 `payoff` =「用一个历史类比看懂 FDE 热潮的局限」，没点名给哪类观众，没有数据依据。v3 卡已有 `payoff` 字段，问题在提示词和校验太松，不缺字段。
- `skills/spawn-planner`（触发词「这周写什么」）在做规划但不看数据——升级它，不新增并行技能。

### 0.2 数据现状（决定 v1 能做什么）

- `outcomes.jsonl` 35 行全部 `contentId:null`，全是一次性累计快照（09-26 CSV + 09-24 B 站）；三平台自动回流从未开启（`pull-state.ts:79` 默认关）。
- 历史 11 条在 AutoCrew 里没有对应 Content，形式/画像只能手工补标。
- 已发作品的第 3/7 天快照永远补不回来。**同龄基线要等回流开启后积累：前 4–6 周没有可用基线**，这期间的会只能靠定位 + 累计数据 + 判断，并如实标出来。

### 0.3 待创始人拍板的产品决定

- **选中≠开工**：会上选中只标记进「本周片单」（看板选题列置顶 + 标签），不弹写稿窗口；开工仍是一条一个会话（video-session）。原因：`/api/board/start-writing` 只认浏览器会话，且每条会各弹一个 Claude 窗口，选 3 条弹 3 个。
- **技能命名**：`skills/topic-meeting`（选题会），删除 `spawn-planner` 并把触发词并过来。

## 1. 范围

1. 选题会技能（宿主会话里开，不做 UI）。
2. `meeting_brief` 确定性简报，复用 insights 统计层。
3. 下注 = 假设台账里的一条 hypothesis（扩字段），对账复用 `hypothesis-judge`。
4. 立意卡收紧 `payoff` + 可选画像字段。
5. 数据回流补齐：开启回流、按平台绑定作品、时区修正、历史作品手工标签。

不做：选题会页面；B 站回流（9 条合计 348 播放）；Brier/命中率统计（v1 只记概率，攒够再说）；排期日历。

## 2. 选题会流程（技能）

创始人发起（「开选题会」「这周写什么」），条数与配比当场定。

1. **对账**：读上次会议的下注（hypotheses 里 `meetingDate` = 上次的），由 judge 给 中 / 没中 / 数据不够（带原因）。中/没中的问创始人一句「按当时手里的信息重来，还会这么选吗」，记进 hypothesis。
2. **读简报** `autocrew_insights {action:"meeting_brief"}`（§3）。回流未开启/过期、作品未绑定、量纲未核，开会第一件事先说。
3. **补标签**：简报列出未标形式/画像的已发作品，会上一次问清补齐（§5.4）。
4. **出候选**：来源 = 灵感库 + 技能提的新题（如爆款续集，`autocrew_topic create source:"meeting"`，标待调研）。每个候选写清：
   - 给谁看：档案画像（core/adjacent/surprise 键 + 当前名字）
   - 观众拿走什么：看完能做的一件事或能下的一个判断；「看懂 X」「了解 X」不算
   - 形式：教学 / 观点 / 亲历 / 案例 / 测评；内容线：自由文本（档案没有结构化内容线字段，参照 `industry` 原文）
   - 为什么现在
   - 数据依据：引简报里具体作品 + 数字；没有就写「无数据依据，纯判断」
   - 赌什么：一句可证伪的假设，落成 `watch{platform, metric, day: 3|7}`，metric 只能从 §5.1 可回流表里选
   - 事前验尸：到期没中最可能的 1 个原因（给最强的，不给稻草人）
5. **拍板**：创始人选中 / 改 / 毙。每个选中位由创始人给「高于基线中位数」的概率（具体百分数），技能不代填。
6. **落库**：每个选中位写一条 hypothesis + 会议记录（§4），选题标 `meetingSlot`；毙掉的带理由进会议记录。

技能规则：引用分组结论时必须带 n，n<5 只列数不下结论；比较只在同平台同天龄间做；离群作品（> 5× 同平台中位数）单列不进基线；会上提到的数字都出自简报，不凭记忆。

## 3. `meeting_brief`（确定性，不调模型）

复用 `src/modules/insights/facts.ts`（天龄、`groupByEntity`、中位数、未绑定数、待复核数）与 `metric-window`，不另写统计。返回：

- **数据健康度**：每平台 开启？/ 最近回流时间 / 超 48h 标过期（未开启就只报「未开启」）；未绑定作品数；指标级「未核」标注（见 §5.3）。
- **作品表**：已发作品 × 平台：D+3、D+7（取 ±1 天容差内最近快照，标实际天龄）与最新累计值；形式/画像取自手工标签或会议位，缺则显式「未标」。
- **分组**：按形式、画像，同平台中位数 + n；离群单列。
- **基线**：每平台 × 指标 × 天龄的中位数与 n；n<5 返回 `insufficient` 而不是数。
- **待对账下注**：上次会议的 hypotheses + judge 当前结论（未到期标「未到期」）。

## 4. 存储

- **下注**：`hypotheses.jsonl` 扩可选字段 `topicId, meetingDate, slotId, probability, premortem, wouldRepeat`。判定沿用 `hypothesis-judge`（同平台同龄基线、`MIN_BASELINE_SAMPLE=5`）。「中」= 高于基线中位数；概率即「高于中位数」的概率。不另建下注台账。
- **会议记录**：`<dataDir>/meetings/<YYYY-MM-DD>.json` 只存会议本身：片单（slotId → topicId、hypothesisId、画像、观众收获、形式、为什么现在、数据依据）、毙题与理由、`revision`。同日重开 = 读当前 revision 比较后写（CAS），冲突就报错让后来者重读，不静默覆盖。
- `meetings` 加入 `library-manager.ts` 的 `DATA_DIRS`，否则迁移资料库时会被留在原地。
- **人读纪要**：参照复盘栏的做法（`my-content-plan.ts`）从 `meetings/` 渲染到「我的内容/选题会」，不往托管视图里手写文件。
- **选题**：`Topic.meetingSlot{meetingDate, slotId}`。

## 5. 数据回流补齐

### 5.1 可回流指标表（`watch.metric` 只能选表内）

| 平台 | 自动回流可得 |
|---|---|
| 抖音 | 播放、赞、评、转、藏、完播（未核）、5 秒完播；**涨粉目前不映射**（`douyin-stats.ts:74-81`）——builder 查原始返回里有没有涨粉字段，有就补映射，没有就不进表 |
| 小红书 | 播放、赞、藏、评（`xhs-stats.ts:88-91`） |
| 视频号 | 以 `wechat-video-stats.ts` 实际映射为准，builder 落表 |

### 5.2 作品 ↔ 稿件绑定

- 现有 `matchDraft` 只匹配 `c.platform === 行平台`（`outcome-store.ts:242`），各平台标题也不同；`bindByPublishUrl` 依赖的 publishUrl 线上全空。
- 新增：用发布计划 `publish-plan.json` 里**每个平台各自的** `title + scheduled_at`（按 Asia/Shanghai 日期）绑定到 content，一条稿可对应多平台作品。
- 绑不上的在简报里列「未绑定」，会上一句话确认绑定。

### 5.3 量纲与时区

- 抖音 `completionRate` 一律指标级标「未核」（不是按行剔除），直到用一次真实后台截图对齐量纲；`facts.ts` 按 `needsReview` 整行剔除的逻辑改成指标级，避免连带丢掉有效的播放和 5 秒完播。
- 时区：回流 `publishedAt` 是 UTC（`pull-shared.ts`），`metricDate` 是本地日期，`ageInDays` 和 `outcomeKey` 都截前 10 位 → 北京时间 0–8 点发的作品天龄差 1，CSV 行和自动行会分裂成两个作品。统一按 Asia/Shanghai 取日期（现有 +08:00 的行结果不变）。
- 只用 D+3/D+7 下注：12h TTL + 日抓 ≤2 次下，D+1 可能是发布后 7h 也可能 29h。

### 5.4 历史作品手工标签

`platform-items.json` 条目加可选 `format`、`personaKey`；会上补，简报读。

### 5.5 创始人动作

数据页开启三平台回流 + 扫码登录；提供一张抖音后台完播率截图对齐量纲。

## 6. 边界清单（待创始人确认）

1. 回流未开/过期：会照开，简报顶部写明，相关下注判「数据不够」。
2. 冷启动：前 4–6 周没有同龄基线，下注照记，对账大多是「数据不够」——如实说，不拿累计数冒充同龄比较。
3. 小样本：n<5 只列数；离群（>5× 中位数）单列。
4. 灵感库空或都不合适：技能提新题入库（待调研），不凑数。
5. 一个都不选：照样落会议记录（空片单 + 毙题理由）。
6. 选中的题已在写稿/被认领：显示状态，不重复建，不抢认领。
7. 选中的题已有立意卡或 `selectedAngle`：会议位注入不进去，问创始人重跑立意还是接受偏离。
8. 会议位选题豁免 3 天自动过期（`topic-expiry.ts`），**豁免到下次开会为止**；下次会没再选中就恢复正常过期。
9. 下注作品没绑定：按平台各自标题+日期匹配，匹配不上判「无法对账」并列出。
10. 档案画像改名/重校准：存 key + 名字快照，旧下注按快照展示。
11. 同日两个会话同时开会：CAS，后写者报冲突重读。
12. 简报或读数据失败：技能停下报原始错误，不凭记忆开会。

## 7. 立意卡

- 选题带 `meetingSlot` 时，把 画像 + 观众收获 + 形式 + 赌什么 注入立意 user message；没有会议位的照旧。
- **不加 `takeaway`**：收紧现有 `payoff` 的提示词和校验——必须是看完能做的事或能下的判断，拒「看懂/了解/认识 X」式空话（确定性前缀检查 + 提示词）。
- 加**可选** `forPersona{key: core|adjacent|surprise, name}`、`hookType`（亲历/观点/反常识/教学/案例）。存量 v3 卡没有这两个字段照常通过校验；改写已有卡时不因画像改名而失败（`angle-cards.ts:145-156` 用原卡校验处要放过）。`primaryPersona`（涨粉/立信/变现 目标键）语义不动。
- 有会议位时卡要服从会上定的形式和画像；偏离要在卡上写明理由，由创始人选。
- 立意提示词加简报里的形式表现摘要（带 n），只当参考，不强制结构。

## 8. 验收

- 固定数据集（复制现有 35 行 outcomes + 构造多天快照）跑 `meeting_brief`，基线/分组/健康度精确断言（确定性层）。
- 时区：UTC 00:30Z 与 +08:00 两种 `publishedAt` 的同一作品归为一个，天龄一致。
- 绑定：一条稿三平台不同标题，按 publish-plan 各自绑上。
- 边界 1/2/7/8/9/11/12 各有单测；存量 v3 卡校验回归测试。
- 真实会话开一次选题会：出纪要 + 会议记录 + hypotheses 新行 + 片单在看板置顶；其中一题走到立意，卡上 `forPersona/hookType` 与会议位一致、`payoff` 不是「看懂 X」。
