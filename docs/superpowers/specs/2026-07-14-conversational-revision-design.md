# 对话式修改（Conversational Revision）— 设计

- 日期：2026-07-14
- 状态：设计已确认，待实施计划
- 相关：收编「基本要重写」死路（whole-draft）+ 选段改写（SelectionBar 红绿 diff）两条旧路径

## 背景 / 问题

现在的"修改"是**一次性 + 二选一的贩卖机**：指令进 → 一个结果出 → 采纳 / 放弃。两条路径都这样：

- **选段改写**：编辑器选段 → SelectionBar → `draft:rewrite_selection` → 内联红绿 diff → 采纳 / 放弃。
- **整篇重写**：对话里打字 → `reviseDraft`；或点「基本要重写」→ 只调 `content:adoption` 记个分、**不触发任何重写**（死路）。

缺的正是创作真正需要的：**反问**（指令模糊时 Agent 硬猜着下笔，输出质量因此打折）、**迭代**（出了结果只能整块采纳/扔）、**部分采纳**。

## 目标

把"修改"从"出一版让你裁决"改成**一段锚定焦点的对话**：选中一段（或整篇）→ 和总编辑来回 → 它**不清楚就反问、清楚就改** → 编辑器里那段**原地红绿 diff 实时更新** → 迭代到满意 → **收下这版** → 替换 + 存新版 → **这一刻才学**。

## 核心模型：修改焦点（revision focus）

```
focus = { contentId, scope: 'selection' | 'draft', selection?: { start, end, text } }
```

- 焦点活在**对话上下文**里，由编辑器设置（选段 →「改这段」；不选 →「改这篇」）。
- 对话顶部钉「正在改：〈这段 / 整篇〉」，× 取消焦点。
- 焦点存在期间，总编辑的每一轮都**只作用于焦点范围**。

## 循环与数据流

1. **编辑器**：选中 span →「改这段 →」设置焦点（contentId + selection）并聚焦对话输入；不选则「改这篇」= draft 范围。
2. 用户在对话里发修改意见。
3. **总编辑**带焦点上下文跑一轮，二选一：
   - **模糊 → 反问**（纯对话回复，不出 diff）。只在真模糊时问。
   - **清楚 → 改**：产出焦点范围的新版本 → 编辑器在该 span 原地渲染红/绿 diff（复用现成 `pending-edit`），待定。
4. **迭代**：用户继续说（"第二句留着，后半段再野一点"）→ 重跑 → diff 更新。部分采纳 = 对话里指明"留哪改哪"或手动微调绿字。
5. **收下这版**：替换焦点 span（或整篇）、存新版本（旧版进版本记录）、清焦点。
6. **采纳即学习闸门**：若该焦点期间发生过 ≥1 次修改，把（旧文 → 新文 + 本轮意见）喂给 `record_edit → 蒸馏` 管线，沉淀成 style rule 进 Memory。**采纳前不学**，以后写稿/改稿自动带上。

## 组件与接口

- **对话侧（总编辑）**
  - 对话轮参数新增 `focus`（contentId / scope / selection）。
  - 增强改写工具 `revise_focus`：入（focus + 会话）→ 出**要么** `{ question }` **要么** `{ revised }`（selection 范围回新 span；draft 范围回新标题+正文）。必须**允许反问**，不强制每轮都改。
  - system prompt：焦点存在时"模糊则问、清楚则改，编辑只落在焦点范围"。
  - 新动作「收下这版」：提交待定的焦点变更 + 触发延迟学习。
- **编辑器侧**
  - 选段给「改这段」入口（收编现有 SelectionBar），设置对话焦点（编辑器 ↔ 对话共享状态）。
  - 渲染焦点 span 的红绿 diff，改由**对话最新一版**驱动（非旧的一次性内联），可反复更新。
  - 采纳复用 `adoptPending` 的替换逻辑 + 版本保存。
- **学习**：采纳那一刻 `record_edit(before, after, note=累计意见)` → 现成蒸馏 → style rule。延迟、只在采纳时。

## 复用 vs 新增

- **复用**：对话 loop + `reviseDraft`（扩成带 scope + 能反问）、`pending-edit` diff 渲染、`adoptPending` 替换、内容版本、`record_edit → 蒸馏`、writingRules 注入。
- **新增**：修改焦点的上下文传递（编辑器↔对话）、"反问或改（限焦点）"的工具、「收下这版」动作、采纳时触发延迟学习。

## 已定取舍

- 反问**只在模糊时**，不每轮问。
- **diff 长在编辑器**、对话只承载来回（不塞聊天卡片）。
- **「收下这版」= 确认 = 学习闸门**，三合一。

## 不做（YAGNI）

- 逐句粒度的部分采纳 UI（用对话 + 手动改绿字覆盖）。
- 多个焦点并存。
- 不经采纳的自动学习。

## 测试（断言不变量，不冻结 LLM 文本）

- `revise_focus`：模糊输入 → 返回 `question`；清楚输入 → 返回 `revised`（mock 模型）。
- selection 范围：只替换该 span，正文其余部分原样保留。
- 采纳：版本数 +1；学习**恰好触发一次**；未采纳 → 学习**不触发**。
- 反问轮：不产生 diff、不动正文、不存版本。
