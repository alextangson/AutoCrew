## 2 统一内容比对器

一个比对器服务三处：agent 报原片（§3）、收件箱与监视文件夹（§4、§5）、导出目录新版本（§6）、卡片挂载核对（§7）。

- 从 `video/handoff/match-l1.ts`、`match-l2.ts` 抽成 `production/match/`（纯函数 + 转写调用），旧交接模块改为引用它或原样留作死代码（三期删），不反向依赖已关闭模块。
- **比对池**：未删除、未归档、有正文的视频稿。A-roll 比对用有效认稿前后的稿（draft_ready 起，含剪辑中——多 take 要能被认出来）；导出比对用 draft_ready 起全部（含已发布）。正文取冻结副本（有）否则当前正文。
- **转写缓存**：按**完整 sha256** 持久化到服务目录（完整哈希复用对账现有 `dev:ino:size:mtime` 哈希缓存，不在锁内算）；每个字节内容只转写一次。不用 quickHash 当键——它不覆盖等长中段修改（§14-9）。缓存只存转写文本与时长，不进资料库、不进仓库。
- **队列**：持久作业键 = (sha256, 用途, 目标稿或池版本)，同键不重复入队；终态 = 已判 / 失败 / 取消；失败退避重试（1 小时后，最多 3 次，之后停在「失败」并可见）；比对池变化（新稿认稿、正文改了）只用缓存转写重新打分，不重转。对账 tick 只发现与入队，不等转写完成。单工人、一次一个；优先级 = 有人明确要的（agent record、卡片挂载）> 自己去找的（收件箱、监视文件夹、导出目录）。ffmpeg 与转写子进程用 `nice -n 10` 跑。整个比对不持文件归属锁、不持内容写锁；只有落结果（写事实 / 搬运）时进 §7 事务。
- **限额**：前 120 秒；ffmpeg 60 秒、转写 90 秒超时（沿用 `match-l2.ts`）；单个作业总时限 5 分钟。
- **暂停**：设置里「暂停自动找原片」只停「自己去找」的转写；agent record 与卡片挂载照常。
- **转写没就绪**（`notReady`：uv / .venv / 模型）→ 只比文件名，结果带原因「转写环境没装好，只比了文件名」，不静默（E29）。

### 2.1 判定与校准

- 结果 = 每条候选稿的 L1 等级 + L2 分数，排序后给 `{winner?, top3, reason}`，并带作业输入快照：文件 sha、每条池内稿的 round、正文哈希、标题（§14-2）。
- **L1 强命中**（统一定义，§14-18）：1a 现有标题前缀规则 `exportMatchesTitle`（≥ 6 字前缀）或 `matchL1` 强命中；「池里唯一」= 没有别条稿被任一规则命中。系列前缀、旧标题等只算弱命中，不自动认。
- **自动认（winner）**只在两种情况：L1 强命中且池里唯一；或 L2 已校准且「有效字数 ≥ 80（沿用 `match.ts` 短转写保护）且 目标分 ≥ 下限 且 比第二名高出 ≥ 差距」（池里只有一条稿时第二名按 0 算，下限仍要过）。空转写、短转写一律不自动认。否则没有 winner，只给前三名作候选依据。
- **校准先行**：先写只读脚本 `scripts/calibrate-aroll-match.mts`，对资料库里已有 accepted 原片与成片的稿，算「对自己稿的分」与「对最像的别条稿的分」，输出每条的两分与差距到 `~/.cache/autocrew-yt/ontology-1b/calibration.json`（只存分数与内容 id，不存转写文本、正文）。结果先给创始人看，再定下限与差距写进代码常量（注释写样本量与分布）。拉不开 → `calibrated=false` 保持，L2 只给建议不自动认。
- 校准前 L2 一律不自动认。

## 3 agent 报原片：`pending_match`（原 spec §3-6 落地）

`record kind=aroll`，来源在可搬入根（收件箱、开了「允许 agent 直接搬入」的监视文件夹）：

1. L1 对目标稿强命中且池里无别条强命中 → 照旧直接 accepted 并搬。
2. 否则：转写没就绪 → 直接 candidate，evidence 写原因，next_action 让 agent 告诉创始人去卡片上点。
3. 否则写 `pending_match` 事实（记绝对路径、sha、大小、修改时间、`source_path`），入队（高优先级）。回执：「正在核对这段原片是不是这条（约 2 分钟）：对上了会自动挪进项目，之后用 `content summary` 取新路径导入 ChatCut；对不上会转成候选等创始人点」。
4. 作业完成 → 进事务，先核（§14-1/2/6）：事实仍是同轮、同 sha、同作业代号的 `pending_match`（创始人已确认 / 拒绝 → 作业结果作废，无副作用）；池内各稿 round / 正文哈希 / 标题与快照一致（变了 → 用缓存转写重新打分再判，不用旧 winner）；再按原 spec §3 **重跑全部落位检查**（根当前是否仍可搬入、路径安全、A-roll 独占含 pending 预留、ChatCut 引用、本体启用）；最后复核文件身份（重新算完整 sha，与作业输入不等 → 作废重排）：
   - 变了 / 不见了 → 事实转 `rejected`，evidence「核对期间文件变了 / 不见了，没挪」，时间线记一条。
   - winner = 目标稿 → accepted 并按原 spec §3-7 搬入改名。
   - 其他（别条更高、分数不够、失败、超时）→ `candidate`，evidence 写前三名与原因。
5. **服务重启**：恢复事务后，本轮所有 `pending_match` 重新入队。
6. **中途变故**：稿重开文稿 / 归档 / 删除 → 丢弃作业，事实按轮次进历史，不搬。
7. **独占**（§14-3）：`pending_match` 是对该 sha 的预留。**所有**收 A-roll 的入口（record、收件箱自动挪、卡片挂载、候选确认、改挂）在同一把文件归属锁里查「各轮 accepted 归属 + 当前 pending 预留」。B 稿 record 同一文件 → 拒 `aroll_pending_elsewhere`「正在核对是不是《A》的原片」；创始人在 B 卡片挂载同一文件 → 先提示同句话，确认后取消 A 的作业（A 的事实转 rejected，evidence「创始人挂到了《B》」）再挂。A 稿同一文件重复 record → request_id 重放 / 同 (sha,kind) 幂等返回当前状态。
8. 卡片与看板：`pending_match` 显示「正在核对原片」+ 开始时间；summary 的 `pending` 字段同样给出（写稿段稿件也给，§14-16）。
9. **后台工人不继承锁上下文**（§14-4）：`withFileOwnership` 用 `AsyncLocalStorage` 判重入，工人必须在独立异步上下文启动（服务启动时建、或 `AsyncLocalStorage.exit`），队列只传数据；落结果时自己取锁。测试：工人提交与并发 record / 重开文稿真正互斥。

## 4 收件箱自动挪（Q1 A）

对账每轮发现收件箱里新的稳定视频（10 秒不变、读得出时长）：

- **自动挪的前提**：winner 存在，且 winner 是「等 A-roll」的稿（有效认稿前后、本轮还没有 accepted 原片）。L1 唯一强命中可直接判；否则入队转写（低优先级），出结果再判。
- **按批判定**（§14-5）：收件箱文件不逐个出结果就搬。已发现的收件箱文件**全部**有结果（已判 / 失败）后统一判定：按目标稿聚合，同一目标多个文件 → 全部候选；单个的在锁内按 §3-4 同一套检查复核后才搬。之后新到的文件进下一批。
- 自动挪 = 事实 `source=reconcile`、accepted、`auto_attached: true`、`source_path` 记原位置，按原 spec §3-7 搬入改名；时间线「从收件箱自动挂上」；卡片 badge「从收件箱自动挂上，不对就点『不是这条』」。
- **多 take**：同一轮对账里两个新文件都指向同一条 → 都只做候选，不自动认；某条已有本轮原片 → 后来的一律候选（E25）。
- **没能比完**（转写失败、超时、读不了）与「比完了没对上」分开（§14-14）：前者进文件级错误状态，列头与对账警告写「N 个视频没核对成：原因」，按 §2 退避重试。
- **对不上**（无 winner、池外、得分不够）：留原处；指向前三名稿的做候选（带分数依据）；一个也不像的计入待录制列头「收件箱里有 N 个视频没对上」。列头点开：文件名、大小、时间、猜测、「指定给…」（= 卡片挂载决定）、「在访达中显示」。
- 已被创始人对某条点过「不是这条」的 sha 不再自动挪到那条。

### 4.1 「不是这条」撤销自动挂上

对 `auto_attached` 的原片（收件箱自动挪、pending_match 自动认）点「不是这条」：

这是原 spec §2.5「只有重开文稿能解冻」的**受限例外**（§14-10），只为撤销系统自己做错的自动挂上：

- 前提（锁内核）：模拟移除这条事实后重新推导，结果必须是「待录制」，且本轮没有任何批准、登记、发布观察、「我发了」依赖它；没被 `chatcut_project.uses_aroll` 引用。不满足 → 拒，说原因：「ChatCut 工程在用这个原片，先在 ChatCut 里换掉」/「这条已经在剪了，要换原片请重开文稿」。
- 做（一个持久事务，§14-11）：写决定 `auto_attach_undo`（持久，时间线可见）；文件挪回 `source_path` 所在目录——目标目录逐段 lstat 拒符号链接、核目录身份（dev/ino）与事务开始时一致，目录已不在 → 挪回收件箱并告知；目标名用排他创建占位（原名被占 → `-2` 后缀，写进回执），不覆盖任何文件；事实转 rejected（按条记住）；清 `doc.frozen`（冻结副本留作历史），阶段推回待录制。
- 搬回、拒事实、解冻共用一个提交点；中途失败按事务日志恢复；恢复不了 → 保留日志、报告文件实际所在路径。跨卷沿用复制→核哈希→删除（E28）。

## 5 监视文件夹（原 spec §9.1-2）

- **设置**（本机配置，和剪映导出目录同一文件 `video.json`，键 `arollWatchFolders: [{path, scan, allow_move}]`、`arollAutoFindPaused`）：默认空、不暂停。
- **只有浏览器会话能改**（§14-7）：监视文件夹、两个开关、剪映导出目录（它也是可搬入根）的修改只收同源浏览器会话；本地 bearer / MCP / `/api/invoke` 改这些键一律拒。「可搬入根」是服务端凭据，不能让模型自己加。
- **路径**（§14-8）：存 `realpath`；必须存在、是目录、不是符号链接；与资料库**相交**即拒（在库内，或是库的祖先目录）。搬入只限该目录**顶层**文件；每次使用时复核目录身份（dev/ino）与无符号链接，变了 → 该文件夹停用并提示。
- **设置页新段「原片从哪里找」**：收件箱路径（固定，只读 +「在访达中显示」）；监视文件夹列表（「添加文件夹…」原生选择器、删除、两个开关「给建议」「允许 agent 直接搬入」）；「暂停自动找原片」；转写环境状态（就绪 / 未就绪 + 现有预热入口）；每个文件夹最近一次扫描结果或错误。
- **扫描**（开了「给建议」的）：每 60 秒一轮，只看顶层；视频扩展名；14 天内修改；≤ 10 GB、≤ 60 分钟（超限只比文件名）；10 秒稳定。只在比对池里有「等 A-roll」的稿时才转写。
- **结果只出建议**：对上的做候选（带依据，badge「发现疑似 A-roll」），从不自动挪——「允许 agent 直接搬入」只管 agent record。对不上的静默跳过（下载里大量无关视频，不计入列头）。
- **读不了**（EPERM / EACCES）→ 该行显示「读不了：去 系统设置 → 隐私与安全性 → 文件与文件夹，给运行 AutoCrew 的程序打开这个文件夹」，看板顶部对账警告同样列出；恢复后自动消失（E30）。
- 全文件 sha256 只在要写事实时算（对账现有哈希缓存复用）；扫描与转写不持锁。
- **上线时**（Q2）：在创始人本机 `video.json` 加 `~/Downloads`，两个开关都开。

## 7 卡片挂载核对（原 spec §9.1-3）

- 挂载照旧同步完成（现有文件名提醒不变）。挂上后入队（高优先级）核对：别条的分数超过这条且满足 §2.1 差距 → 卡片 badge「这段原片听起来更像《X》」，两个按钮「改挂到《X》」/「就是这条」（记住，不再提示）。
- **「改挂到《X》」**（§14-12）：现有 `reassign` 只转移历史轮原片，当前轮用不了。改挂 = 双内容事务：本条按 §4.1 同样的前提撤掉（但文件不挪回原处），同一事务里按原 spec §3 检查后收进《X》并搬入改名。前提不满足 → 按钮换成说明「这条已经在剪了，要改挂请先重开文稿」。
- 转写没就绪 → 卡片小字「没做内容核对：转写环境没装好」。核对失败同样写原因。

## 8 摘要（原 spec §9.2）

`autocrew_content action=summary` 对制作段稿件，以及已有制作事实或 pending 的写稿段稿件（§14-16）新增：`missing[]`、`badges[]`、`candidates[]`（≤3：fact_id、kind、来源、依据摘要）、`pending[]`（pending_match：fact_id、开始时间）、`aroll[]`（本轮原片事实：fact_id、state、round、项目内绝对路径、失败 / 作废原因——agent 轮询 pending 就看这里取新路径）、`changes[]`、`latest_seq`、`next_since_seq`、`has_more`（§14-17）。

`changes` 按 seq 升序分页：`since_seq` 之后（不传给最近 10 条），放不下就截尾，`next_since_seq` 只推进到最后实际返回的那条，`has_more=true`；绝不因截断跳过事件。总长仍 ≤ 1.5 KB：先截 changes（翻页），再截 candidates 依据。工具说明补一句 `since_seq` 与翻页。上限的唯一例外：单条必需路径本身超过预算时，返回最小形状并标 oversize，不截路径。

## 11 边界

B1 转写没就绪 → 只比文件名并写原因。B2 转写失败 / 超时 → 候选 + 原因，不静默。B3 核对期间文件变了 / 不见 → rejected + 原因，不搬。B4 重启 → pending 重新入队。B5 核对中稿被重开 / 归档 / 删 → 丢弃作业、不搬。B6 同文件核对中被报给别条 → 拒并说是哪条。B7 多 take → 候选不自动认。B8 自动挂错 → 「不是这条」挪回原处原名、解冻、回待录制；已被 ChatCut 引用或已有别的制作事实 → 拒并指路。B9 挪回时原名被占 → 加后缀并告知。B10 对某条点过「不是这条」的文件不再自动挪到那条。B11 监视文件夹读不了 → 设置页与看板提示授权，恢复后消失。B12 超限文件只比文件名。B13 暂停只停自己去找的转写。B14 无「等 A-roll」的稿时不转写监视文件夹。B15 转写缓存按 quickHash，同文件不重转。B16 比对与转写不持锁，落结果进事务。B17 校准前 L2 不自动认。B18 校准数据不含正文 / 转写文本。B19 导出目录名字不同的字幕不猜。B20 summary 超长先截 changes。B21 预览服务不顶掉正式服务登录。B22 失效 token + 有效 cookie 不报错。B23 监视文件夹路径不能在资料库内、必须存在。B24 收件箱对不上的计入列头，监视文件夹对不上的不计。B25 核对结果迟到、创始人已点过 → 结果作废无副作用。B26 核对期间正文 / 标题改了 → 重新打分再判。B27 核对期间关了「允许 agent 直接搬入」或原片被 ChatCut 引用 → 不搬、转候选并写原因。B28 pending 预留对所有收原片入口生效。B29 同批多文件指向同一条 → 全部候选。B30 撤销自动挂上只在推导回待录制且无依赖时允许。B31 挪回原处不跟符号链接、不覆盖，目录没了回收件箱。B32 模型改不了监视文件夹、搬入开关、剪映导出目录。B33 与资料库相交的目录不能当监视文件夹。B34 转写证据绑完整 sha。B35 摘要翻页不漏事件。B36 同一作业不重复入队，失败退避后停在可见的失败态。

## 12 不做

不做递归扫描；不用大模型判断归属；监视文件夹不自动挪；不做字幕内容比对；不改发布、登记、阶段推导表；Downloads 对别的用户仍默认不加。
