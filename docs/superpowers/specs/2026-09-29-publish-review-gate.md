状态：定稿 v2。创始人已确认方向与边界；已吸收 Codex 会审 6 P1 / 8 P2（会话见 `~/.cache/autocrew-yt/publish-review-gate/codex-consult.txt`）；创始人 09-29 拍板 B站比例、例外、断连三处（§3、§7、§11）。建在内容本体 1a 第②段之上（登记记录、发布出口、发布回执），见 `2026-09-29-content-ontology.md`。

## 1 为什么

2026-09-29 一个 Claude 会话批量发 3 条视频到抖音/小红书/B站：小红书封面先按 3:4 传，agent 看截图后自行断定「小红书横屏视频封面框是 4:3」改传 4:3——那只是编辑器对横屏视频的默认框。规则在 `src/modules/cover/platform-ratios.ts` 里，但发布技能只写「双尺寸封面」、发布计划每平台只有一个 `cover_path`、交给浏览器的发布包固定只给一张 3:4（`ego-lite.ts`），一次确认汇总也没列各平台封面。同日「纠正 AI」创始人说「用一吧」（A），落进项目的是 B。

根因：明确规则不在 agent 动手时读的地方；没有任何环节核对「计划 vs 规则 / 计划 vs 创始人原话」；检查过的东西和实际执行的东西不是同一份。

## 2 形状

- `autocrew_publish action=check`：所有宿主可调，**Codex 白名单按动作加入** `check` 与 `propose_preference`（`mcp/host-policy.ts`，不整体放开发布），有宿主集成测试。只写检查留档，不改任何业务状态。
- 输入：`content_id`、`plan`（计划 JSON 或项目内路径）、`founder_quotes: string[]`（本次对话里创始人关于这次发布的原话，逐字）、`instruction_id?`（§6）、`overrides?: [{platform, rule, founder_quote}]`（§7）。
- 流程：平台集合与归属 → 确定性检查 → Jev A → Jev B → 按平台汇总。
- 输出每平台：`verdict: pass | warn | block | override`、`items[]`（检查名、结论、依据的原话/规则、计划字段、Jev 答案与概率；没跑成/未检查单列，不算通过）、`payload_hash`、`check_id`；全局 `summary_table`（平台 → 账号 → 封面文件 → 比例 → 用途槽 → 是否符合 → 例外 → 其他提醒），agent 必须原样贴进给创始人的一次确认汇总。
- 留档 `06-publish/checks/<check_id>.json`：输入、指纹组成、全部问题与答案、模型版本、token、耗时、检查时间。

### 2.1 检查身份（Codex P1-4/5）

- **待发布内容哈希**（逐平台）：规范化后的 `{platform, account, content_id, title, caption, tags, covers[{usage, ratio, sha256}], video_sha256, scheduled_at+tz}`；**排除**授权、执行状态、回执、活动核验等过程字段。改一个平台只让该平台失效；成片变化让所有平台失效。
- **检查指纹** = 待发布内容哈希 + 当前登记记录 id + 批准 id + 偏好表版本 + 指令 id + 字幕 sha + 问题集版本 + 模型版本。
- 确定性检查每次调用都重跑（便宜）；Jev 结果按指纹缓存；Jev 没跑成的结果**不缓存**，下次调用重试；同指纹并发调用合并为一次。

## 4 平台集合与归属（Codex P2-8）

- 计划平台列表非空、无重复；每条的 `content_id` 属于本内容、项目路径属于本项目。
- 目标平台集合：指令/原话里点名的平台（代码按平台名词表匹配，含中英文别名）必须都在计划里；计划里多出的平台提醒。漏一个平台 = block（可例外）。

## 5 确定性检查（block，可被 §7 例外）

- **封面**：按像素实算比例（容差 1%），每个上传槽都有且比例对；不许出现规则外比例。封面文件必须是当前登记记录里选定的那一对（按 sha）。发布计划样例改为每平台 `covers: [{usage, ratio, path}]`；旧 `cover_path` 视作单张按像素判。
- **成片**：必须是当前登记记录的成片（sha）。
- **封面字**：计划里的封面字必须等于登记时选封面决定里的封面字；登记没有封面字 → 「封面字未检查」（不算通过，不 block）（Codex P2-11）。
- **标题/文案/标签**：从 `pre-publish.ts` 抽出纯校验函数（不调旧执行器，旧执行器会推进状态），逐平台列清上限与计数口径（标题加权计数、文案字符串长度、抖音文案无硬上限、标签是否计入）（Codex P2-10）。
- **排期**：写了排期必须带时区。
- 文件缺失/读不了/计划形状不对 → block 并指出平台与字段，不猜。

## 6 指令来源（Codex P2-7）

- 网页「让 Codex 发布」：创始人点「复制」或「复制并打开」时，服务端保存**编辑后的实际文本**，生成 `instruction_id` 并写进复制出去的文本末行（「指令编号：ins-…」）；两条路径都存。复制/打开不等于发送或授权。
- check 只用 agent 传来的 `instruction_id` 对应的那份；不传就没有网页指令，**不取「最近一份」**。
- `founder_quotes` 逐字；`publishRules` 全部适用条。

## 8 Jev A：语义把关（warn）

状态只放需要的字段：登记成片的字幕（与成片 sha 绑定）、该平台标题、文案、稿件标题。字幕超 token 上限 → 只比对前段并写明「只比对了前 N 分钟」，此时 A2 的「不支持」只算「未覆盖」，不据此提醒（Codex P2-11）。

- A1 `choice`：标题和文案是否准确反映字幕里讲的事 {准确, 部分偏离, 误导, 无法判断}。
- A2 代码先抽候选说法（数字+单位、百分比、引号/「」里的话、「第一/唯一/最」类）；数值能在字幕里逐字对上的由代码直接判；其余每条一个 `noul`「字幕是否说过或直接支持这句（含否定、时间范围、因果）」。
- ~~A3 `choice`：封面字与视频主题的关系~~ **09-29 上线前评测后删除**（创始人决定）：jev-1.13.0 在 13 条视频、39 例上，26 个反例（别条视频标题 / 开头第一句当封面字）漏报 16 个，正例 13 个无误报——分不开，整题砍掉（问题、指纹与请求输入、汇总项、评测例一并移除）。封面字只保留 §5 的确定性相等检查。

## 9 Jev B：执行是否符合指令（warn）

指令列表 = `founder_quotes` + `instruction_id` 文本（按句切）+ 适用的 `publishRules`，每条编号。对每条指令 × 固定字段集 {平台集合, 账号, 标题, 文案, 标签, 封面, 排期, 活动}，同一请求 fan-out 一个 `noul`「这个平台条目的 <字段> 是否违反了这条指令」，另每条指令一个 `choice`「这条指令约束的是哪个字段 / 不约束发布内容」。代码只在指令约束该字段时看违反概率，结果项自带指令原文与字段（Codex P2-12）。「用一吧」这类含糊选择不靠 B：封面选择由选封面决定绑定文件 sha（本体 §2.4）。

没有任何指令 → 「没有可核对的原话/规则」，不算失败。agent 漏交原话就查不到——已知限制，§11 事后可见兜一部分。

## 10 两档与校准（Codex P2-13）

- 确定性 block（可例外）；Jev 一律 warn。
- 攒够 10 次真实发布是**复盘节点**，不是自动开拦截：拿留档和创始人过每条提醒判对/判错，并**抽查判通过的**找漏报；按视频分开统计误报、漏报、弃权。达到事先写下的标准（复盘时定）才给某个问题开 block，模型钉 `jev-1.13.0`；达不到保持 warn。
- 上线前评测：用已发/待发的真实文案与字幕构造正反例（换别条视频的标题、塞字幕里没有的数字、开头笑点当封面字、原话「小红书用 3:4」配 4:3 计划、漏一个平台、原话与计划一致等），按视频分组，每个问题正反各 ≥5 例；分不开的问题砍掉或只留提醒。中文弱于英文，官方明说。

## 11 执行链（Codex P1-3、P2-9、P2-14）

- **发布包取检查过的快照**：`ego_lite_prepare` 改为按平台出包，必须带该平台当前有效 `check_id`（指纹一致、无未例外的 block），包内含 `covers[]`（用途槽 + 文件 + sha）、成片、标题、文案、标签、排期、例外；过期或被拦的平台不出包。
- **技能改口**（`skills/publish-content/SKILL.md` 与计划样例）：比例以 check 为准、不看编辑器默认框；一次确认汇总前必须 check 并原样贴 `summary_table`；被拦平台不得提交；计划改了重跑；**最终点击前逐字段读回页面与发布包比对**，封面按槽位截图核对实际裁切（B站 16:9 框必核）。
- **断连或内容不在 AutoCrew**（创始人 09-29）：agent 在最终点击前停下来告诉创始人；创始人明确说「这次不检查直接发」才继续，回执标「发布前未把关」。
- **回执绑定检查**：发布回执（`confirm_published`、本体发布回执事实、从发布计划读到的发布状态、手动登记）都要引用该平台 `check_id`，且检查时间早于提交时间、当时无未例外 block；找不到 → 卡片与时间线「发布前未把关」。事后补跑的检查不抹掉这条历史。
  - 「提交时间」是实际提交时间（计划里的 submitted_at / 授权时间，没有就按观察写入时间），从不取定时公开时间；同一槽后来的状态观察继承首次盖的结论（09-29 seg6）。
  - 只标闸门存在之后提交的：资料库启用本体（改口补丁同刻套上）之前的发布没有闸门可跑，不标。卡片上汇总一句「N 个平台发布前未把关」，平台标在各自回执行上。
  - `ego_lite_prepare` 的 check_ids 要求随资料库启用状态生效：启用前旧单包出口不变、check 仅作参考；启用后必须带。
- 数据回流核实待核回执：只认带平台作品 ID 的绑定；按标题相似匹配的不算可信回执。

## 12 接入与失败

- `POST https://api.typesafe.ai/v1/systemone`，直接 HTTP；`model: jev-1.13.0`；超时 15 秒；问题 instructions 写死在代码里，状态里的文字只是数据。
- 密钥：环境变量 `TYPESAFE_API_KEY` 优先，其次本机设置（与其他服务密钥同处，设置页可填）；不进仓库；`autocrew doctor` 检查有无、调一次通不通。
- 失败（没密钥、401/429/5xx、超时、返回形状不对）→ 确定性照常，语义标「语义把关没跑成：原因」进 `summary_table`，不挡发布、不缓存、不静默。
- 成本按 `usage.input_tokens` 记进留档（$0.042/百万输入 token）。

## 13 边界

E1 每平台单独判，一个被拦不影响其他。E2 待发布内容哈希逐平台，过程字段不参与。E3 Jev 没跑成：确定性照跑，语义「没跑成+原因」，不挡、不缓存。E4 创始人特别交代可推翻确定性拦截（§7），逐字可见、留痕、Jev 顺带核对。E5 每条判定附依据与字段，代码拼，不让 Jev 编解释。E6 新偏好 agent 提议、网页确认。E7 密钥本机存、doctor 检查。E8 `summary_table` 原样进一次确认汇总。E9 没有登记字幕 → A 用定稿正文比对并写明。E10 状态文字是数据，不改变问题。E11 同指纹幂等、不重复计费，失败结果可重试。E12 计划形状不对 → block 指出字段。E13 漏平台/多平台/跨项目 → block/提醒。E14 断连或内容不在库 → 停下问，明确放行才发，留痕。E15 回执无有效前置检查 → 「发布前未把关」，事后检查不抹。

## 14 不做

平台违规词/合规风险；图片内容判断（Jev 只收文字）；Jev 用于状态流转或任何批准；发布以外的「执行对指令」；界面判对/判错按钮；B站专门出 16:9。

## 15 验收

- 确定性：小红书 4:3 → block；视频号只 3:4 → block；抖音 3:4+4:3 → pass；B站 4:3 → pass 且汇总含「16:9 裁切核对」；非登记封面/成片 → block；封面字不等 → block；漏平台 → block；带原话例外 → override 且汇总逐字可见；字数口径按平台。
- 身份：改一个平台只让它失效；写回执不让检查失效；原路径文件被覆盖 → 指纹变、重检；没密钥的结果不被缓存。
- 执行链：无有效 check_id 的平台 `ego_lite_prepare` 拒；包内 covers[] 与 check 一致；Codex 宿主能调 check、调不了其他发布动作。
- 指令：复制/复制并打开两条路径都存编辑后文本；不传 instruction_id 不取最近一份。
- 回执：无前置检查 → 「发布前未把关」；事后补检不抹。
- Jev：评测报告（按视频分组、每问题正反例概率、误报/漏报/弃权）；没跑成可见。09-29 评测（13 条视频、195 例）：A1 / A2 / B / 例外原话核对均 0 误报 0 漏报；A3 漏报 16/26 → 已删除，不再验收。
- `npm run check` 全绿；codex review 无 P1/P2。
