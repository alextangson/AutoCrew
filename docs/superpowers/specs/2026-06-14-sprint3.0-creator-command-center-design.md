# S3.0 设计稿 — 创作者指挥台（今日工作台 + 导航壳）

> 状态：创始人已认可（2026-06-14）。「创作者指挥台」里程碑的第一个 slice。
> 后续：S3.1（内容看板 + 数据可视化）、S3.2（选题页 + 素材页 + 视觉升级）。
> 缘起：S2.8/S2.9 把会话、流水线、雷达、飞轮、素材库都建好了，但 UI 把它们埋在一个
> 聊天框和抽屉后面。本 slice 把已有后端能力第一次暴露到创作者母语的主屏。

## 0. 背景与裁决

现状（main，S2.9 后）：中央区是 hero 空态 ↔ chat-stream 二选一；五个面板
（回流报告/稿件/风格/侦察员/素材库）藏在右侧抽屉；侧边栏一半是「即将上线」灰条。
问题不在功能缺失，在**信息架构**：app 围绕"对话/任务"组织，而创作者按"内容 + 数据"思考。

**创始人裁决**（2026-06-14 brainstorm）：

1. **范围** = 今日工作台 + 导航壳。目的页（选题/内容/数据/素材）先复用现有面板渲染、
   从抽屉"提"为一级页，不在本 slice 重设计（留 S3.1/S3.2）。
2. **组织模型** = 中央三模式：**今日**（首屏）/ **会话**（chat-stream+卡片，复用 S2.8）/
   **目的页**。左栏导航切换；命令栏发消息 = 进入会话。
3. **数字员工** = 从导航降级为今日首屏的存在感条；点头像 = 打开该角色页。不做 @派活
   （后端是单 agent + 全工具集，角色仅展示映射；真角色路由留后续）。
4. **任务历史** = Cursor 模型而非 ChatGPT 模型：对话是手段不是产物。「最近任务」放今日
   首屏，「＋新任务」常驻侧边栏顶部，「全部任务」做成轻列表。历史不常驻侧边栏。
5. **视觉** = 本 slice 用现有设计 token 做结构重组；icon rail 等视觉升级留 S3.2。

## 1. 信息架构

### 侧边栏（重组 sidebar.js + index.html）

```
AutoCrew · 编辑部
＋新任务                    ← 常驻顶部，高频
── 导航 ──
今日 · 选题 · 内容 · 数据 · 素材   ← 一级导航，切中央模式/目的页
── 底部 ──
设置（内含「即将上线」预留位说明：定时任务/插件/消息渠道/团队）
本地版
```

- 「即将上线」四条从主屏移除，并入设置页一个「即将上线」说明区（不再占主导航位）。
- 「数字员工」四角色从侧边栏移除（升为今日首屏存在感条）。
- 导航项点击 → `switchView(view)`：`today` 渲染今日首屏；`scout/drafts/report/library`
  渲染对应目的页（复用现有 init*，从抽屉容器搬到中央目的页容器）；会话态由发消息进入。

### 中央区三模式（main.js / 视图切换）

| 模式 | 内容 | 入口 |
|---|---|---|
| 今日 | 今日工作台（首屏，下文 §2） | 默认；导航「今日」；新任务后 |
| 会话 | 现 chat-stream + 输入条（S2.8） | 命令栏发消息 / 就这个写 / 最近任务点击 |
| 目的页 | 选题/内容/数据/素材（现有面板提为一级页） | 导航点击 |

抽屉（#drawer）退役为视图容器——五面板移入中央目的页区。S2.7 工作台、卡片四向路由
改为 `switchView` 目的页。同时只显示一个中央模式。

## 2. 今日工作台（新 today.js）

替换现有 hero 空态。三块卡片 + 顶部存在感 + 命令栏 + 最近任务。

```
┌─────────────────────────────────────────────┐
│ 早上好，今天想做点什么？        [侦][编][审][析] │  ← 问候 + 存在感条
│ AI技术/科技博主 · 6月14日                       │
├─────────────────────────────────────────────┤
│ 📡 选题雷达 — 侦察员今早扫到 N 条，挑了 3 条     │
│   • 选题1（源·热度）          [就这个写]        │
│   • 选题2 ...                                  │
├──────────────────────┬──────────────────────┤
│ 进行中               │ 上条数据回流           │
│ 草稿2 待审1 待发1     │ 完播 42% ↑基线31%      │
│ ⚠ 草稿停2天          │ 《Excel》· 播放1.2万   │
├──────────────────────┴──────────────────────┤
│ 最近任务  • 任务A  • 任务B  • 任务C   [全部任务]│
├─────────────────────────────────────────────┤
│ ✨ 直接说需求…                        [发送]   │  ← 命令栏常驻
└─────────────────────────────────────────────┘
```

- **存在感条**：四角色头像（侦/编/审/析，沿用角色色），侦察员带在线点（刚扫过榜）。
  点头像 → switchView 该角色页（scout/style/report；审核员=说明卡逻辑沿用 S2.6）。
- **选题雷达卡**：今日候选 3 条（标题/源），「就这个写」→ 进入会话发
  「用选题《…》给我写一条口播」（复用现 topic 卡按钮行为）。空缓存 → 引导「点刷新扫榜」
  （调 radar:refresh）。
- **进行中卡**：内容按状态分组计数（草稿/待审/待发），+ 卡顿提醒（draft 态且 updatedAt
  超 N 天的最新一条）。点计数 → switchView 内容页。
- **数据回流卡**：最近一条已发布作品的 completionRate vs 基线 avgMetrics.completionRate
  + 播放量。无已发布 → 空态「发布第一条后这里出现你的数据」。点 → switchView 数据页。
- **最近任务**：conversations:list 取前 5（复用现有），点击 → loadConversation 进会话；
  「全部任务」→ 轻列表（全部 conversations，可删，复用 sidebar 现逻辑搬过来）。
- **命令栏**：底部常驻，发送 = sendChat → 进入会话模式。

## 3. 数据层（S3.0 的后端真活）

### 新增 `getCachedTopicCandidates`（topic-radar.ts）

现 `getTopicCandidates` 在缓存过期时会**联网刷新**（12s×源），不适合首屏同步画。
新增缓存-only 读：

```ts
export async function getCachedTopicCandidates(
  industry: string, dataDir?: string, limit = 10,
): Promise<RadarItem[]>   // 读缓存→rankCandidates；无缓存返回 []，绝不联网
```

（内部复用现有私有 loadTopicCache + rankCandidates，零网络。）

### 新增聚合通道 `today:summary`（IPC 40→41）

主进程组合三个现成数据源，一次返回，首屏一个调用画完：

```ts
// today:summary 载荷 {}，返回 data:
{
  industry: string,                          // loadProfile().industry（无则默认/空）
  radar: { topics: RadarItem[], fetchedAt: string | null },  // getCachedTopicCandidates 前 N
  pipeline: {                                // listContents 分组计数（沿用 app.js GROUPS）
    draft: number, review: number, ready: number, published: number,
    stale: { id, title, days } | null,       // draft 态最久未动且超阈值的一条
  },
  lastOutcome: {                             // 最近已发布作品 vs 基线
    contentId, title, platform,
    completionRate: number | null,           // content.performanceData.completionRate
    baselineCompletionRate: number | null,   // flywheel 基线 avgMetrics.completionRate
    views: number | null,
  } | null,                                  // 无已发布作品 → null
}
```

实现：新 `src/desktop/today-summary.ts` 的 `buildTodaySummary(dataDir?)` 编排
（loadProfile + getCachedTopicCandidates + listContents 分组 + 取已发布作品 performanceData
+ flywheel 基线）。ipc.ts 加 `todaySummaryHandler` 薄包装（守卫 + try/catch + _dataDir）。
镜像 chat-persist 的"主进程编排、测试注入"模式。STALE_DAYS 常量（建议 2）。

## 4. 复用 vs 新建

| 复用（不动渲染逻辑） | 新建 |
|---|---|
| 会话持久化、chat-stream、6 类卡片、确认门 | today.js（今日首屏） |
| 五目的页 init*（report/drafts/style/scout/library） | today-summary.ts + today:summary 通道 |

| 角色色 token、署名、卡片 | 侧边栏导航重组、命令栏常驻 |

## 5. 错误处理

- today:summary 任一数据源失败 → 该块降级（雷达失败→空态可刷新；飞轮失败→数据块空态；
  整体不炸）。聚合 handler try/catch，子数据各自 try/catch 退默认值。
- 雷达缓存空（首次启动 refresh 未回）→ 选题卡空态 +「立即扫榜」（radar:refresh）。
- 无 profile/industry → 用默认赛道占位，不阻断。
- 切视图时目的页加载失败 → 沿用各 init* 现有 toast，不影响导航。

## 6. 测试

- **today-summary 单测**（`buildTodaySummary` 注入 dataDir + 桩）：空库、无已发布作品、
  雷达缓存空、stale 草稿命中/不命中、完整数据各分支；子源失败降级不抛。
- **getCachedTopicCandidates 单测**：有缓存排序、无缓存返回 []、绝不触发 fetch（注入
  fetch 桩断言 0 调用）。
- **ipc 测**：通道注册 41 + today:summary handler（守卫/正常/_dataDir）。
- **CDP 冒烟**（端口 9447，纪律同前 + driver≤3s attach）：今日三块渲染（含真实/空态）、
  存在感条点击切页、就这个写进会话、命令栏发消息进会话、导航切五目的页、最近任务回放、
  新任务回今日、重启。
