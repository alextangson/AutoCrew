# 角度卡 + AI 审稿 agent · 设计 spec v2（codex 评审已吸收，待创始人裁决）

## 0. 背景与裁决

### 0.1 创始人诉求（2026-08-23）

写稿深度不够，成稿不达标，创始人已弃用 AutoCrew 写稿回退到 Claude 手写。诊断（有数据）：220 篇稿子只有 1 篇带过调研简报——深调研是手动挡，从没被踩下去过。修复分三刀：

1. **刀1（已实现，另行提交）**：写作入口自动补深调研，无简报不裸写，降级必留痕。
2. **刀2（本 spec）**：写前「角度决策」——结构化角度卡，创始人点选/改写，品味与观点进管线。
3. **刀3（本 spec）**：AI 审稿 agent——AI 味 + 洞察深度双查，替换「正则删词」成为真正的审稿人。

### 0.2 定位（v2 关键转向，codex P2-1）

v1 设想「写前新开一个角度生成 LLM pass」。codex 指出简报综合阶段**已经**在产
`angleSuggestions`（2-3 条，ResearchPanel 已展示）——再开一个 pass 是重复劳动。
v2 改为：**把简报综合阶段的 angleSuggestions 升级成结构化角度卡**，角度随简报的
revision 体系落盘（天然版本化、天然绑定 topicHash/briefRevision，P1-9 一并解决）。
独立的角度生成 loop 只在两种场合调用：无简报降级、创始人要求重出候选。

## 1. 刀2：角度卡（angle cards）

### 1.1 流程位置

`点写这条 →（刀1 自动调研）→ 简报综合产出角度卡 → 创始人点选/改写 → 开写`。

### 1.2 角度卡 schema（P1-16/P2-3：角度必须约束全稿，不只是 Hook）

- `id`：稳定 id（P1-10；同批 insight/tension 也补稳定 id，brief schemaVersion 升级）；
- `angle`：切入点一句话；
- `thesis`：本稿核心论点——写稿师必须论证它，不是复述简报；
- `coreEvidenceIds`：支撑论点的简报洞察/证据 id（≥1，校验存在性，防编造）；
- `tensionId?`：依托的跨视角张力点 id（有就引，没有不硬编——简报 tensions 允许为空）;
- `antiScope`：明确不写什么（防止四平八稳面面俱到——深度的一半是舍弃）；
- `audiencePain` + `holdTrigger`：目标受众的具体痛点 + 预期停留触发（P2-3：替换 v1
  不可验证的 `trafficLogic` 自述）；
- `hookDraft`：开头钩子草稿（给创始人预览手感）。

候选 2-4 张；**差异性校验**（P2-2）：submit 校验各卡 `thesis` 与 `antiScope` 不得互为
改写（代码侧做字面近似度粗筛 + prompt 明令「论点/受众痛点/叙事结构至少一维不同」，
不引入 embedding——校验是防五卡一角度，不是学术查重）。

### 1.3 存储与优先级（P1-9/P1-13）

- 角度卡是**简报的一部分**（`brief.angleCards`），随 revision 走，绑定关系免费获得。
- 选中状态落选题：`topic.selectedAngle = { briefRevision, angleId }`；改选题文本/重跑
  简报后指针失配 = 选择过期，UI 提示重选（同简报 stale 的现算纪律）。
- **注入优先级**（现存三套角度来源的合并规则）：工作台手填 `direction` > 选中角度卡 >
  无（走今天的老路）。手填 direction 时角度卡仍展示但不注入——创始人手写即最高裁决。
  Topic 旧字段 `angles` 降级为纯展示，不再参与注入（实现时核对现用途后清理）。

### 1.4 创始人观点入口（P1-12——本刀的核心，不是点选按钮）

选择界面三种动作，缺一不可：**点选**一张卡；**改写**卡上任意字段（thesis/antiScope
是主要改写对象）；**手写**自定义角度（落 `direction`，走最高优先级）。改写与手写
就是创始人观点进管线的口子——只有点选的版本兑现不了「品味进场」。

### 1.5 注入

选中/改写后的角度卡渲染进 script-prompt 新块【本稿切入点】：thesis 作为必须论证的
论点、coreEvidence 原文引用、antiScope 列为禁区。未选（直写）整块省略，prompt 与
今天逐字一致（additive 纪律）。

### 1.6 各入口行为（P1-15：不让聊天模型猜 skip 布尔值）

- **工作台「写这条」**：有角度卡且未选 → 弹选择卡（点选/改写/手写/「直接写」四选，
  「直接写」是显式按钮，即用户确认）；无角度卡 → 直接写（现状）。
- **聊天 write_script**：有角度卡且未选 → 工具**不接单**，回执角度候选卡片让用户选或
  明说「直接写」；用户原话已含明确跳过意图（「别选角度」「直接写」）→ 模型转述该原话
  作为 `skip_reason` 传入，落 run-log 可回溯。不再有裸布尔 `skip_angle`。
- **平台矩阵「生成」**（实际发聊天消息）：随聊天路径，行为自动一致。
- **MCP 外部 agent**：不接（同刀1 边界——外部 agent 自己有判断力）。
- 直写稿版本注记标「未经角度点选」。

### 1.7 挂起与回收（P1-14）

等待选角的选题必须豁免 3 天自动回收：`topic.selectedAngle` 未设但 brief 含
angleCards 时，以简报 `generatedAt` 为续期锚（回收判定处显式加此锚，不新增状态字段）。
角度卡不过期、不自动选；聊天可催（「XX 选题在等你选角度」）。

### 1.8 无简报降级（P1-11：不逼模型编证据）

调研失败/未配 key 时**不硬出角度卡**——没有证据的角度卡就是包装过的臆测。降级路径：
提示创始人手写 `direction`（一句话即可），或直接写（刀1 已标「未带简报」）。独立
角度 loop 仅服务「有简报但创始人要求重出候选」的重跑场景。

## 2. 刀3：AI 审稿 agent

### 2.1 流程位置与顺序（P1-3：审稿必须看到终稿形态）

`submit_script 通过 → 组装 → humanizeZh 正则 → AI 审稿 →（revise 时）修订 loop → 每轮修订后重跑 humanizeZh + quality gate → 违禁词扫描 → 转正`。

正则在前：审稿读的是正则改写**后**的文本，终稿不会再被审稿没见过的替换动过。

### 2.2 统一收敛循环（P1-1/P1-2：不复用 loop 内打回通道，gate 每轮重验）

审稿发生在写稿 loop 结束后，原 loop 会话已收束——修订是**独立的 runLoop 调用**：
输入 = 当前稿 + 审稿 issue 清单 + 写稿时的同批材料（简报块、选中角度、个人规则、
voiceSamples），收束工具 = 同款 `submit_script`（字段校验复用）。每轮修订产物重跑
humanizeZh + quality gate——「AI 味修好了但结构改坏了」必须当轮被抓住。总修订上限
2 轮 + 整阶段墙钟 deadline（P1-17；runLoop 的 token 限额是软检查，deadline 是硬闸，
超时丢弃修订、用最后一版过 gate 的稿）。

### 2.3 审稿契约（P1-5）

verdict = `pass` | `revise`，revise 必附 issues：

```
{ id, severity: "blocker"|"advisory", quote: 原文定位引文, rule: 判据名, instruction: 修改指令 }
```

- 判据表两类：AI 味（句式套路/词汇/结构对称病，从 humanizer-zh SKILL 词表升维）+
  洞察深度（信息罗列无论点、论点是简报复述、证据与论点脱节、thesis 未被论证）；
- malformed / 未调工具 / 空指令：1 轮自纠（复用工具返回错误消息通道），仍失败 →
  按审稿失败降级（§2.5）；
- 修订轮只处理 `blocker`；`advisory` 直接透出不打回（防无限润色）。

### 2.4 审稿材料（P1-6：不给材料就没法判「深度」）

审稿 agent 读：终稿全文 + 本稿注入过的简报块（同 briefRevision）+ 选中角度卡
（thesis/antiScope 是「深度」的判定基准：论点论证了吗？禁区守住了吗？）+
voiceSamples（像不像这个人）。没给材料的维度不判（无简报稿只查 AI 味不查证据深度）。

### 2.5 失败处理与留痕（P1-17 全清单 + P1-4 落点）

LLM 失败/超时/schema 违约/修订耗尽仍有 blocker——统一降级：保留最后一版过 gate 的稿
转正，content 元数据落 `review` 字段：

```
review: { status: "passed"|"revised"|"failed"|"skipped", rounds, issues: [...], reviewedAt }
```

- `run_done` 事件 label 追加审稿结论（「已审稿」/「审稿未过，残留 N 项」/「未经 AI 审稿」）;
- 工作台稿卡显示审稿徽章（读 `review.status`——这是 reviewFailures 的真实落点，
  不是函数返回值幻想）；
- 版本注记：修订发生时 `_versionNote: "AI 审稿修订（N 项）"`。

### 2.6 模型路由（P1-7）

engine config 增加 `reviewer` 路由位，缺省 fallback 到 strongModel（同 writer 的
resolve 语义）；run-log `agent: "reviewer"`。审稿是品味活，判错比慢贵——默认强模型，
创始人可在配置降档（裁决点 3）。

### 2.7 改稿链路（P2-4）

`revise_draft`/`revise_focus` v1 不接审稿，但改稿落盘时把既有 `review.status` 改为
`"stale"`——改过的稿不得继续顶着「已 AI 审稿」徽章。

## 3. 验收（P1-18：可判定，不许凭感觉宣布通过）

- **固定样本**：从 `~/.autocrew/contents` 抽 5 篇历史成稿（无简报裸写的那批）作为
  审稿输入，审稿必须产出 ≥1 条 blocker 且 quote 定位准确（判「审稿看得出问题」）；
- **盲评**：同一选题（带简报）新旧管线各出一稿，去标识后创始人盲选，连做 3 题，
  新管线 ≥2 胜（判「整链条真的更好」）；
- **事实保持**：修订轮前后跑违禁词扫描 + 人工抽查证据引用未被改写（判「修 AI 味
  没修掉事实」）；
- 回归：全量 `npm run check` + 现有写稿测试零改动通过（additive 纪律的机器验证）。

## 4. 分期

- **R1 = 刀3 审稿 agent**：纯后置管线（§2 全部）+ content `review` 字段 + 工作台徽章。
  无角度依赖（§2.4 材料缺省降级已定义），独立可验收。
- **R2 = 刀2 角度卡**：brief schema 升级（稳定 id + angleCards）→ 综合 prompt 升级 →
  选择 UI（点选/改写/手写/直写）→ 注入块 + 优先级合并 → 回收豁免 → 聊天入口改造。
- R2 内部可再切：schema+综合+注入先行（无 UI 也能靠聊天选卡跑通），选择 UI 收尾。

## 7. v3：立意阶段与创作方法论（2026-09-02，P0 实验后）

### 7.0 为什么要改

P0（`experiments/p0-inputs-vs-structure/`，36 稿盲评进行到一半）暴露的不是调研量或流程的问题，是**立意**的问题：「DeepSeek Harness」选题 12 篇稿子——不管调研给摘要还是全文、走直写还是全流程——**标题全是「劝你别碰」**。立场不是写手定的，是简报综合那一步定的：tensions[0] 写着「这是不要现在上生产的明确信号」，angleSuggestions[0] 是「为什么 95K Star 的项目反而不能碰」，写手只是执行。创始人的评语：有结构但观点没有深度洞察和剖析，站不住脚，AI 味；流量话题要迎合观众、要有用户心理洞察；要换位、打破知识的诅咒；一条好短视频要有网感五元素里的 2–3 个；一个内容要经得起不同受众画像点评。

三个结构性原因：
1. **立意混在调研综合里**，跟着证据的味道走：证据说项目不成熟，立意就变成劝退。这是 v2 §1.1「角度是简报的一部分」的副作用。
2. **调研的受众视角只有一种人**（「技术 VP 选型陷阱」），且 9 份简报里 5 份的受众视角被引文逐字校验清零——心理洞察本来就不是从网页原文引出来的。
3. **写手的赛道包是结构模板**（钩子五型 + 结构模式），没有立意就只剩结构：这正是「有结构没洞察」。

### 7.1 受众画像：从账号定位倒推

创始人给的三画像（小白有收获想关注 / 从业者佩服 / 老板想找我）是例子，不是定案。倒推逻辑：**画像 = 账号要完成的工作**。一个 AI 博主账号有三项工作——涨粉、立信、变现——每项工作对应一种「看完会做什么」的人。按 `creator-profile.json` 的定位（AI 一线实践者：FDE 部署 + vibecoding；三条线：一手信息差 / 真实实操 / 判断与思考；目标 3 个月 1 万粉）倒推：

| 工作 | 画像 | 他走进来时的处境 | 他看完要做的动作 | 停留触发 |
|---|---|---|---|---|
| **涨粉** | 「被 AI 追着跑的职场人」：25–40 岁，用过 ChatGPT/豆包，没做出过东西，怕被时代甩下 | 热点刷到了，名词听不懂，怕被割 | **关注**：「他讲的我能听懂，下次还想听他讲」 | 名词祛魅、反常识、「原来是这样」 |
| **立信** | 「同行/独立开发者」：vibecoder、做 agent 的、已经踩过坑 | 知道内情，没时间实测，对空话免疫 | **收藏/转发**：「他实测了我没时间测的，数字对得上」 | 具体命令/数字/失败细节、自我否定式开场（对标卡实证藏赞比 1:1） |
| **变现** | 「要落地 AI 的决策者」：现有画像「老周」（中型企业技术 VP）+ 传统行业老板 | 方案商 PPT 看了三十版，前两次 AI 都死了 | **找我**：「这个人在现场，他知道那层看不见的阻力」 | 真实企业名 + 失败原因、内部博弈还原（已在画像里） |

现有画像集（老周 / 苏晴 / 阿杰）全是决策者与投资人——都是变现画像，**没有涨粉画像**。这解释了为什么稿子像对同行说话（知识的诅咒），也解释了「劝退」立场：它是对技术 VP 的谨慎，对另外两种人毫无意义——小白本来就不打算上生产，从业者早知道 rc 版不稳。

画像不是固定三个：每条内容线可以有自己的主画像（一手信息差 → 涨粉画像为主；真实实操 → 立信画像为主；判断与思考 → 变现画像为主），但**三个都要过一遍**。

### 7.2 立意的定义与判据

**立意 = 对某一个画像成立的、可被反驳的主张 + 他看完能做的一个动作。** 四条判据：

1. **误区先行**（来源：Muller/Veritasium 的对照实验——先陈述受众持有的错误认知再反驳，学习效果量 ≈0.8，而「清晰讲解」几乎不产生学习；ajkumar.com 综述）。立意必须回答「这个画像走进来时信什么错的东西」。「劝退」失败的根源就是它没回答任何画像的误区。
2. **三画像收益**：主画像有明确动作（关注/收藏/找我），另外两个至少不反感、最好各得一点。三个都答不上来的立意不能用。
3. **网感元素 ≥2**（§7.3）。
4. **立场站得住**：过反方视角（简报的 counter 视角就是现成的反方）；反向立场（劝退、唱衰）只在给观众一个能拿走的判断框架时成立，否则是对同行说话。

配套纪律（来源：中文短视频运营实践 + 知识类内容研究，§7.8）：
- **一稿一主张**：抖音知识类每期只讲 1 个核心观点；多观点 = 没有观点。
- **前 3 秒 = 误区/反常识 + 提问**，不是「今天聊聊 X」。
- **热点走中层价值**：热点有表层（事件本身）/中层（社会情绪）/深层（文化符号）三层，聚焦中层的完播率显著高于表层（云南微正 案例数据 47%）。95K Star 是表层；「怕落后、怕被割、谁在定义下一代开发方式」是中层。
- **结尾给最小动作**：观众今天能做的、30 分钟内能完成的一步（William Meller「Next Simplest Step」）。
- **换位测试**：立意写完，用「10 岁规则」复述一遍（Meller）；复述不了就是知识的诅咒（Camerer, Loewenstein & Weber 1989）。

### 7.3 网感五元素在知识内容里的对应

| 元素 | 在 AI 知识内容里长什么样 | 例 |
|---|---|---|
| 新奇点 | 认知违背（schema violation）：一个他以为对的东西是错的 | 「95K Star 和它能不能用，是两件事」 |
| 爽点 | 看穿 / 走捷径：一句话把复杂事拆穿；别人花三天他花三分钟 | 「我写了一个插件就懂了万物皆插件」 |
| 痛点→理想状态 | 他今天卡在哪，做到那一步后是什么样 | 「原型地狱 → 一条能上生产的路」 |
| 笑点 | 自我否定 / 自嘲式坦白（对标卡「前 90% 时间都是表面功夫」藏赞比 1:1） | 「我给它写了插件，然后不敢让团队用」 |
| 泪点 | 真实失败的细节，不是煽情 | 「第三次机会没了」 |
| 美点 | 秩序感：一张图把混乱理顺（画面/图版） | 分层图 |

规则：命中 ≥2；不能全靠新奇点（只有新奇点 = 标题党）。

### 7.4 立意阶段流程与角度卡 v3

流程位置：**从简报综合里拆出来**，综合只产事实（summary / tensions / evidence / gaps），不再产 angleSuggestions；立意是独立一步，输入 = 简报 + 内部语料（own-material）+ 画像集 + 选题。

四步（一次 LLM pass，结构化提交）：
1. **误区清单**：三画像各 1–2 条「他走进来时信什么、会问什么」。
2. **候选立意 3–4 个**：每个 = 主画像 × 主张 × 动作 × 命中元素 × 反方一句话 × 第一手锚点（own-material 或简报证据 id）。差异性校验沿用 v2 §1.2。
3. **打分**：三画像收益（0–2 各）、元素数、反方过关、第一手锚点有无；无第一手锚点的立意最高只能得「综述级」。
4. **产出角度卡 v3**，创始人选或系统按分选（当前角度门逻辑不变：有候选未选不接单，直写留痕）。

角度卡 v3 schema（在 v2 基础上加字段，`schemaVersion` 仍不 bump，全可选）：
- 保留：`id / angle / thesis / coreEvidenceIds / tensionId? / antiScope / hookDraft`
- 新增：`primaryPersona`（涨粉/立信/变现之一）、`misconception`（主画像的误区原话）、`personaGains`（三画像各一句「看完会做什么」）、`elements[]`（命中的网感元素）、`counterResponse`（对反方一句话）、`firsthandAnchor?`（own-material 片段 id 或证据 id）、`nextAction`（结尾最小动作）
- 退役：`audiencePain / holdTrigger`（被 misconception + elements 覆盖）

### 7.5 审稿判据升级：多画像评审

v2 §2.3 的两类判据（AI 味 + 深度/证据）保留，新增第三类**立意执行**：
- 三画像各读一遍稿子，回答「看完会做什么」；主画像动作没达成 → blocker。
- 误区是否在前 3 秒被点出、是否在正文被反驳 → 没有 → blocker。
- 元素命中数 < 2 → advisory；结尾无最小动作 → advisory。
- 主张是否可被反驳（复述简报不算主张）→ blocker。

### 7.6 调研受众视角改法

- 任务书按三画像出题：每个画像「他在哪个场景下碰到这个话题、他信什么、他怕什么」。
- **心理洞察不做逐字引文校验**：受众视角的 insight 允许 `sourceIds` 为空但必须标 `kind: "inference"`，综合与立意读到时知道这是推断不是引文；证据类仍逐字校验。这条直接回应 9 份简报里 5 份受众视角被清零。

### 7.7 验证：P0b

同样三个选题，在 P0 跑格器里加一格 `angle-full`：先跑立意 pass（本节 prompt，产 3 个候选按分取 1），把选中的卡作为 `direction` 注入现有写手；与 12 篇「别碰」稿放进同一份盲评卷。判读：立意格在「观点」「事实性」维度显著高于其它格 → 立意阶段立项；三画像动作在盲评里能被读者复述 → 判据有效。创作者零输入不变。

### 7.9 证据按需回查（v3.1，2026-09-03，创始人：「证据不够为什么不让 agent 自己再去搜；硬编就是纯幻觉」）

现状是「调研一次、写手照单写」：证据够不够写手都得交稿，不够只能编。幻觉是流程逼出来的。两个机制，都不新增 agent 类型：

- **写之前：立意带证据需求，定向补证。** 角度卡新增必填 `evidenceNeeds`（1–3 条：这个主张要落地还缺什么证据）。流水线逐条跑一个「补证调研员」短循环（同搜索代理、同配额、同引文逐字校验、同注入定界；引文真但页记错用 `locateQuote` 纠正归属而不是打回），结果作为增补证据块给写手；没找到就明说「没有证据，正文不要编」。
- **写之中：写手可以查证，但不能白写数字。** 写手工具箱加 `find_evidence(need)`（最多 3 次），走同一个补证函数，只返回校验过的引文和来源 id，写手看不到原始网页。配套硬契约：每个数字、每个「某公司/某研究/某人说」必须挂证据 id，找不到就删或标「[未证实]」；审稿把「[未证实]」当 blocker。P0c 里先做成代码侧核验（正文数字是否出现在任一证据/材料里），进 meta；生产版放进 `submit_script` 校验（P1）。
- **上游松一颗螺丝（P1）**：视角配额按需求给而不是固定 4 搜 6 读；引文校验剔除的只剔那一条，不整段作废视角。

同批裁决（P0b 盲评评语驱动）：
- **稿子不写镜头/画面/字幕条标注**（创始人 2026-09-03「删」）。与 `~/.autocrew/STYLE.md` 里「视频化标注」一节冲突，以本裁决为准；画面是稿子定稿之后剪辑师的事（已有 editor agent）。P1 要改口播赛道包与 STYLE.md。
- 角度卡新增必填 `payoff`（收获感：大白话讲清为什么 + 一个能做的方案），审稿按此判 blocker——评语里「没有收获感」「太多专业名词」出现 9 次。
- 自嘲只能嘲行为和判断，不能嘲身份、学历、出身（评语：「我在深圳不是科班出身，这句降低了我的身份」）。
- 内部语料：非本选题的转写最多进一段；第一手材料只用卡上指定的锚点，其余只供口吻参考（评语：「讲 dsh 的结构跟入口之争有什么关系」）。
- 案例账（P1）：案卷按选题记录已用案例，多平台稿与重生成时强制换例——同选题 14 篇稿 12 篇用同两个例子，根因是证据池只有 7–8 条。

P0c = `angle2` 格：angle + 补证 + find_evidence + 数字核验 + 无镜头标注，6 篇给创始人读。
