状态：定稿（2026-09-30）。创始人已定方向（§2）与 §13 四处取舍（全部按推荐，样式范围选 A）；已吸收 Codex 会审 26 条（原文 `~/.cache/autocrew-yt/review-inbox/consult-out.txt`，落点见 §15）。取代本体 spec §10「二期：批准搬进卡片」。建在本体 1a/1b 之上。

## 1 为什么

2026-09-30「会议纪要」实录（`~/.cache/autocrew-yt/review-inbox/friction-0930.md`）：约 30 处要创始人审或确认，只有 3 处走 AutoCrew 页面，3 处都出了问题；其余在聊天与 ChatCut 里。

- 聊天里「封面OK」不算，还得去页面点。审片叫早：任何被收的成片立刻算「成片待你审」。
- 剪辑途中的请示（粗剪、分镜、样片、花费、重画、配乐表）全在聊天，系统无记录。
- 界面写死「Codex 在剪」，当天是 Claude 在剪。没有任何通知。

## 2 创始人决定（2026-09-30）

- 用词说人话（§4）。

## 3 列表

### 3.1 条目 = 一件事

每条带：稿名、一句话要做什么、谁在等（Claude / Codex / WorkBuddy / 没人在等）、多久以前。有 agent 在等的行首小蓝点。点开 = 右侧面板（Notion 页面预览式：标题、几行属性、预览、按钮），只放处理这件事要的东西。

条目有稳定 `item_id`（同一件事刷新不变）和**审阅代次** `gen`（它所展示的具体对象快照：fact id、sha、正文哈希、选项）。任何入口的动作都必须带 `gen`，服务端在锁内比对后消费（CAS）；代次变了 → 回「这件事刚变过，重新看一下」，不写（Codex 7）。

| 类型 | 何时出现 | 面板给什么 | 主按钮 / 次按钮 / 少用 |
|---|---|---|---|
| Claude 想问你（请示） | agent `ask`（§5） | 问题、附件、选项 | 选项按钮 / 说一句… |
| 成片剪好了，看一遍 | 有 agent 标了「可以审了」的成片，且（无有效成片批准，或标的是比已批更新的版本 = 「新版要不要换」） | 播放器；本轮全部成片版本（最新一版 / 上一版…，按剪好时间） | 就用这版 / 还要改… / — |
| 封面做好了，挑一张 | 有完整成对的封面组，且（无有效封面批准，或有比已批更新的组） | 成对并排 3:4 + 4:3，翻组；封面上的字可改 | 用这组 / 还要改… / 这组不要了 |
| 找到一段原片 / 成片 / 字幕 | 候选、自动挂上、收件箱对不上（1b） | 1b 候选视图 | 对，就是它 / 不是 / 指定给… |
| 画面有闪帧 | 抽帧检查有未放行的缝（针对所选成片） | 缝和时间点 | 去剪辑里改 / 这处是故意的 / 这条不查了 |
| 还差一步才能发 | 两项批准都有效但登记没成（缺这版字幕、文件不见） | 原因一句话 + 谁能补 | 让 Claude 补 / — |
| 发之前再看一眼 | 某平台有当前有效、未确认的发布检查（§7） | 检查表（按平台）、提醒项、要本人同意的条款 | 没问题 / 有几处要改… |
| 发了吗 | 按平台槽：计划发的平台没有可信发布证据 | 各平台 | 已经发出去了（选平台） |
| Claude 说已经发了 | 某平台槽只有 agent 的待核说法 | 说法、链接 | 对，发了 / 没发 |
| 稿子写好了，过一眼 | draft_ready（合并成「N 篇稿子」，展开逐篇） | 正文只读 | 稿子没问题 / 还要改… |
| 其他（默认收起） | 写作规则提案、发布偏好提案 | 原界面 | 原动作 |

「正在核对」的原片（pending_match / 挂载核对中）不是条目，只在对应卡片上显示（Codex 20）。

### 3.2 排序

有 agent 在等的（按等待时长）→ 挡住推进的（成片、封面、还差一步、闪帧、原片）→ 发布相关 → 稿子 → 其他。同一条稿多件事各占一行。

### 3.3 终态（Codex 16、20）

- 「就用这版 / 用这组 / 对，就是它 / 没问题 …」→ 写决定，条目消失。
- 「还要改…」→ 写一句话发给 agent（打回决定绑当时的 `gen`），**同一快照不再出条目**；agent 交了新版本或重新标「可以审了」才开新代次。
- 「这组不要了」→ 该组作废（§6.3），条目刷新到下一组或消失。
- 别处（工作台、会话窗口、另一个标签页）处理了 → 列表 5 秒轮询发现后消失，面板开着时提示「已在别处处理」。
- 稿重开文稿 / 归档 / 删除 → 该稿全部条目消失；未答请示关闭并写原因；之后迟到的回答一律拒（「这件事已经关了」）。

## 4 用词与样子

### 4.1 用词

| 不用 | 用 |
|---|---|
| 等你处理 | 等你拍板 |
| 成片待审 / 选封面 | 成片剪好了，看一遍 / 封面做好了，挑一张 |
| 通过 / 通过 v003 | 就用这版 |
| 打回… | 还要改… |
| 作废这一版 | 这组不要了 |
| 是这条 / 不是这条 | 对，就是它 / 不是 |
| 认稿 / 退回重写 | 稿子没问题 / 还要改… |
| 发布前确认 / 我发了 | 发之前再看一眼 → 没问题 / 已经发出去了 |
| 请示 | Claude 想问你（按实际 agent 名） |
| 已通过 · 撤销 (8) · ↓ 下一条 | 这版定了 · 撤回 · 还有 2 件 |

不出现版本号、响度、B-roll、fact、sha 等术语；版本只说「最新一版 / 上一版」和剪好时间；检查结果一句人话（「字幕和画面都没问题」）；输入框提示用真实例子（「比如：开头有点拖，前 10 秒再紧一点」）。

### 4.2 按钮只有三种

- **主**：黑底白字、圆角 8px、高 36px，每个面板最多一个，文字写后果（「就用这版」）。
- **次**：白底细边同尺寸。
- **少用**：灰字，悬停才显底色，放右侧。
- 不用图标方块、分段按钮条、灰掉的按钮；条件不够时按钮位置直接写原因（「还差 4:3，Claude 在做」）。
- 带「…」的动作就地展开输入框，不弹窗，回车发送。
- 能反悔的（就用这版、用这组、对就是它、已经发出去了、稿子没问题）不弹确认，底部深色小提示「这版定了 · 撤回」10 秒；后果大的（重开文稿）就地写明后果再确认。
- 处理完自动打开下一件；键盘 ↓ 切换、回车 = 主按钮。

### 4.3 样式范围（创始人定 A）

全站按钮统一成 §4.2 三种（看板、设置、稿件页、工作台、卡片侧栏）；「等你拍板」列表与面板整块按 Notion / YouMind 样子做（无衬线、浅灰分隔、属性行）；看板其余部分（衬线标题、米色纸感）先不动。

## 5 请示（ask）

### 5.1 发起

`autocrew_content action=ask`：`content_id, request_id, kind(粗剪|分镜|样片|花费|配乐|其他), question, options[{id,label}] 2–4, attachments[{path}]?`。附件必须在本条项目内，创建时记下每个附件的 sha；`kind=分镜` 必须指定 `storyboard_fact_id`，请示绑定该分镜事实的 html sha、回执 sha、素材指纹与 round（Codex 4）。回 `ask_id`。同条同 kind 的未答旧请示被新请示取代（标「已被新请示取代」）；`withdraw_ask` 撤回。

### 5.2 答

网页或会话窗口（§8）：选项 + 可写一句 → 决定 `ask_answer{ask_id, option_id, note, gen}`，`via: founder`。附件在答之前变了（sha 不符）→ 条目提示「附件刚变过」，要重新看。分镜请示答「通过」→ 同时写分镜决定，只批准请示绑定的那份快照；快照已变 → 拒。agent 从 `content summary` 的 `asks[]`（独立游标 `asks_offset`，不与 `since_seq` 混用，Codex 26）取答复。

### 5.3 聊天里答（Codex 3）

agent `answer_ask ask_id option_id founder_quote`（原话逐字）→ 记为 `ask_answer`，`via: agent_reported`，条目显示「Claude 转述你说的『…』，不对点撤回」，保留 24 小时可撤回。**`kind=花费` 与分镜请示不接受转述**，只认网页或会话窗口确认框（花费一旦发生撤不回；分镜通过会写分镜决定）。

### 5.4 附件怎么打开（Codex 21）

- HTML（分镜审阅页）：沿用现有「在系统浏览器里打开本地文件」，**不从 AutoCrew 自己的网址提供**，避免页面脚本借创始人登录调决定接口。
- 视频 / 图片：只读流式提供，`Content-Security-Policy: sandbox` + `X-Content-Type-Options: nosniff`，只认绑定时的 sha。

## 6 封面（Codex 8–12）

### 6.1 成对

- `record kind=cover` 新增 `paths: [3:4 路径, 4:3 路径]` 一次记一组；或第二张带 `pair_with=<第一张 fact_id>`。一组 = 一个版本，成员关系单独存（版本 ↔ fact，带历史）。
- 不带版本也不成对的单张 → 自成一组（缺一个比例），列表不出「挑一张」，卡片写「只有 3:4，还差 4:3」。**不再凭「最新一版缺哪个比例」猜配对**。
- 同一 sha 再次被用到新组 = 新增成员关系，旧组不动（Codex 9）。
- 服务端「用这组」校验两张属于同一有效组、未作废、各槽唯一，封面字与面板展示一致（带 `gen`）（Codex 10）。

### 6.2 对账收封面

所有封面导入路径（`05-cover/vNNN/` 清单、`final/`、`execution.json`、`meta.assets`、`cover-manifest.json`）统一一个准入规则：只有 `vNNN/`（有清单按清单、清单坏了报错不退回全目录扫描）与 `final/` 收为正式组；其余目录按比例找到的只做候选（Codex 12）。**迁移**：已收为 accepted、但来自其他目录、且不属于任何有效批准的封面 → 转候选并写原因；属于有效批准的不动。

### 6.3 这组不要了

决定 `cover_group_retire{group}`：列表、工作台、批准、推导、对账、30 组上限统一走「有效组」选择器，作废的不再计入（Codex 11）；已批的那组不能作废，先撤回批准；文件不删。

## 7 成片与发布

1. **「可以审了」**：`record kind=cut review=true`，或对已收成片单独 `action=mark_ready fact_id`——作为独立、幂等的事件绑定 fact / sha / round，已有文件也能补标（Codex 13）。对账自动收的导出不算待审。
2. **挑任一版通过**：成片批准绑所选 sha。抽帧检查、放行、字幕都按所选成片算，不改「最新」指针；登记只取 `for_cut=所选 sha` 的字幕，缺了 → 批准照存，出「还差一步：缺这版的字幕」（Codex 14、17）。
3. **新版替换审阅**：已批 v1 后 agent 标 v2 可以审 → 条目「新的一版剪好了，要不要换」；不因新版出现而撤旧批准或旧登记（Codex 15）。
4. **发布检查**：每次 `autocrew_publish check` 绑启动时的 round、平台、输入指纹；每个平台只保留当前有效的一组检查，其余标「已被新检查取代」，不出条目（Codex 18）。
5. **「没问题」**：决定 `publish_check_confirm{check_id, gen}`。**不是新的硬门**：出包仍按现有 `check_ids` 规则（Codex 5 按「不强制」定，理由：发布前确认 09-30 已定在聊天里贴表一次，这里只是换成点一下）。
6. **「有几处要改… / 破例」**：检查留档不可变；创始人本人输入的原话 + 选的规则 → 以 `source: founder` 重跑同一次检查，产生新检查（新 check_id），不在旧检查上改 overrides（Codex 6）。聊天里的破例照 09-30 现有规则走（`founder_quote`），不在本 spec 改。
7. **发了吗**：按本轮每个平台槽推导（1a §6），不按整条稿（Codex 19）。

## 8 在会话窗口里审（2b，MCP elicitation）

### 8.1 行为

- `autocrew_content action=review item_id`：服务端锁内生成**不可变挑战**：资料库、content、round、条目代次 `gen`、动作、fact ids、文件 / 正文 / 选项指纹、发起会话（Codex 2）；向**本会话**发 `elicitation/create`：标题 = 稿名 + 要做什么；正文 = 要点 + 站内预览链接；字段 = 选项枚举（**无默认值**）+ 可选「说一句」。
- accept 且选项合法 → 按挑战快照提交，走与网页同一决定入口，记 `source: founder_mcp` + 宿主；快照已变 → 拒，条目留着。decline / cancel / 超时 / 断线 / 服务重启 → 挑战作废，条目原样。迟到回应一律拒；同一挑战只收一次（Codex 24）。
- 宿主本会话没声明 elicitation、或是无人值守任务 → 不弹，回链接「到 AutoCrew『等你拍板』里点」。
- 图片、视频在框里看不到：框里给链接；成片与封面建议在网页看，框里仍可直接答。

### 8.2 安全边界（Codex 1，写明）

防的是：agent 通过正常工具调用、参数、聊天转述代答四件事——模型看不到也填不了宿主弹给本人的框。**不防**：有 shell 权限的 agent 蓄意读本机密钥、手写协议消息伪造回应——这与今天的网页登录同级（它同样能读 `session-secret` 伪造 cookie）。要防这一级需要系统级认证（如 Touch ID），不在本 spec。见 §13-2。

### 8.3 传输改造（Codex 22、23）

- `initialize` 起服务端签发会话（`Mcp-Session-Id`），会话绑定认证主体、资料库、协商版本与客户端能力（含 elicitation）；按会话、不按宿主缓存能力；会话空闲 30 分钟过期。
- `tools/call` 需要追问时回 SSE：先发 `elicitation/create`，等回应，再发结果。客户端回应以独立 POST（带会话 id）送达，服务端按「会话 + 请求 id」配对，回 202；没有对应挑战 → 400。处理 `notifications/cancelled`。
- stdio 转发器：`Accept` 带 `text/event-stream`，增量解析 SSE 并即时写 stdout；从 stdin 读到的 JSON-RPC 回应（无 method）转成独立 POST；请求 / 回应 / 通知分类处理。
- 等待上限 10 分钟，且不超过客户端声明的工具超时；到时发取消并作废挑战。
- Claude Code（stdio 转发器）与 Codex（HTTP）两条都要通。

## 9 提醒（2c）

- 网页：任一 AutoCrew 标签页开着 → 浏览器通知，点了聚焦并打开那一件；标签页标题「(3) AutoCrew」。浏览器拒授权 → 只显示标题数字，不再请求。
- 系统通知：随仓库带一个小通知程序（`vendor/` 或 `sidecars/`，Apple Silicon 可用，`autocrew doctor` 检查），点了用系统浏览器打开那一件的链接。开工前先在创始人机器上验证能弹、能点。
- 只提醒「有 agent 在等」和「挡住推进」两类；同一条稿 10 分钟内合并成一条；已提醒过的同一件事不重复弹。

## 10 其他

- 界面里「Codex 在剪 / 让 Codex 补一张 / Codex 还没报告过进度」按事实 `by.host` 显示真实 agent，无则「agent」。
- 工作台改为只看详情（历史、全部版本、文件），不再放审核按钮；卡片侧栏只留整条稿的动作（重开文稿、挂原片）。看板拖动规则不变。
- 给 agent 的指路（summary `next`、Codex allowlist、技能补丁）按实际已上线的能力生成：2a 只指「等你拍板」；2b 上线后再加 `action=review`（Codex 25）。Codex allowlist 加 `ask / answer_ask / withdraw_ask / mark_ready`（2a）、`review`（2b）。
- 非本体资料库、图文稿：列表只出认稿与发布相关条目，不出成片 / 封面条目。
- 列表只读推导，看板读零写入（沿用）。

## 12 边界
