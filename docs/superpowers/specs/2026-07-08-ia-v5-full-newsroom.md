## 0. 产品北极星(PM 视角先想清楚"好用的数字员工团队"是什么)

一个真人新媒体团队 = 主编(理解老板) + 侦查员(找料) + 写手(成稿) + 审核(把关) + 发布(分发) + 分析(复盘)。
用户对它的核心期待只有四条,v5 全部功能都必须挂在这四条下,挂不上的不做:

1. **懂我**:知道我是谁、写给谁看、什么口吻——定位+受众画像+风格规则是同一事实源(creator-profile),
   所有环节(选题过滤/写作/审稿)都消费它,用户每次纠正都让它更准(纠正即训练)。
2. **省我**:我只做人类必须做的事——拍板选题、终审、最后一击发布。找料/成稿/配图/排版/预填全是团队的活。
3. **听得懂人话**:改稿不是选择题。我说"这段太软了"或框选一句话说"换个比喻",团队精准改那一处,
   并且思考我为什么这么改,下次自己就会。
4. **看得见**:一个指挥台回答四个问题——今天该我做什么?团队正在干什么?我的内容资产什么状态?数据说明什么?

## 1. 红线(继承 + 新增,先于方法)

- 引擎/数据/发布链全部本地,禁止上云(PRD-v4 §11)。
- 发布分级不变:A 级=平台草稿箱(公众号已通);B 级=表单预填/API 直发,**逐平台先过风控评审**
  (暴露面/ToS/风控信号/回滚策略,一平台一文档);**"人最后一击"边界不动**——任何对外可见的发布动作,
  最后确认必须是用户(平台后台点群发,或产品内确认卡)。
- 未转正员工不进 presence(PRD-v4 §7.4);席位制不变:只对用户开通的平台摊工作面。
- creator-profile.json 是定位/画像/风格的唯一事实源;STYLE.md 只是渲染视图(IA v4.2 B2/B3)。
- 违禁词门/humanizer 合规口径不变:「符合平台规则的自然口吻」,绝不表述为绕过检测。
- 秘钥(引擎/搜索/发布/生图)只住本地配置文件(engine.json/publish.json/search.json),不入库、不进对话、不打印。
- 前端载体裁决:**frontend-v2 契约(Vite+React)是编辑器/看板/校准 UI 的载体**,其前提
  「公众号链 P0 验收」已于 2026-07-08 达成——A 期(脚手架)即刻解锁。vanilla 上不再堆新交互
  (避免为将死的壳做双份工),vanilla 只做保命修复。

## 2. 员工编制 v5(能力矩阵与边界)

| 员工 | v5 能力 | 边界(不做什么) |
|---|---|---|
| **主编(总编辑 chat)** | 理解意图、派活、报进展、把关不可逆动作;可派侦查员加源/搜灵感 | 不绕过确认门;不假装已发布 |
| **侦查员** | RSS+海外源(已有)+ **搜索 API(新)**:按定位/画像主动搜集,入库前语义过滤 | 用户没配 key 时诚实降级,不硬爬 |
| **写手(分平台席位)** | 公众号(已通)/口播三平台/X/Reddit/头条 pack;派活 brief 带 Topic 全量上下文 | 未开席位不写;数字不可溯源不写 |
| **审核员** | 违禁词门(已有)+ **受众停留审(新)**:以画像为标准判断"目标受众会不会停下来" | 不静默改稿,只出意见与 FAIL 项 |
| **发布员** | 公众号草稿箱(已通);X/Reddit API 直发(确认卡后);抖音/视频号/小红书/头条预填 | 人最后一击;逐平台评审通过才实施 |
| **分析师** | 回填/归因(已有);画像校准建议(数据反哺画像) | 不编数据 |
| **剪辑师** | **不在 v5**(裁决点 C 未开):视频链交付到"口播稿+分镜+发布件",成片是用户的活 | — |

## 3. 六条主线(对应创始人指令逐条)

- **P1 画像基础**:定位采集(onboarding 补齐)→ 受众画像生成(3 persona,继承 v2 Phase 0.5 设计)→
  与用户校准一次 → 画像进审核标准(受众停留审)。
- **P2 编辑器闭环**(载体=frontend-v2 B 期):标题可改;框选→精准局部改写(自由输入建议,非选择题);
  用户手改 diff → agent 思考 why → 提炼规则 → 入校准(scope 路由已有,IA v4.2 B2)。
- **P3 情报进水**:搜索 harness(用户配 API)+ 侦查员按定位搜集;用户上传文案不再直入灵感库,
  先过定位/画像匹配与去重。
- **P4 指挥台**(载体=frontend-v2 B/C 期):按 §0.4 四问重排 IA,消除拼贴感。
- **P5 平台矩阵**:视频三平台(口播稿→分镜→发布件→预填)+ X/Reddit(API)+ 头条(预填);
  逐平台风控评审文档先行。
- **P6 设置中心**:引擎/搜索/发布(publish.json 可视化)/席位/情报源/画像与风格,一个页面收口。

## 4. 现状盘点(2026-07-08 侦察)

### 4.1 前端(vanilla renderer)

**已存在但发现性差(创始人以为没有=最大教训):**
- **框选局部修改已实现**(selection.js):textarea 选区浮出工具条=4 快捷键(重写/扩写/缩写/口语化)
  **+自由输入框**(「或输入修改要求,回车发送」)→ `draftRewriteSelection{body,selection,instruction}` →
  before/after 对比 → 采纳/放弃;采纳时 `styleRecordEdit` 回喂校准。
- **整篇保存自动学风格**:`contentUpdate` 后端自动记 diff、攒够蒸馏,回 `styleLearned` toast。
- **纠正回喂已有三链路**:框选采纳 / 整篇保存蒸馏 / 采纳裁决重写原因(负信号)。
- 真正"只有选择题"的是**采纳裁决的重写原因 chip**(风格不像/事实错/结构差,无自由输入)。

**确认缺口:**
- 标题不可编辑(workbench.js:55 静态渲染;contentUpdate 只传 body)。
- 保存不采集"为什么改"(版本 note 只读,无输入口)。
- 受众画像:前端零 UI(全库唯一踪迹是 scout.js:16 一句注释)。
- 灵感库(topics):无专属视图、无搜索/筛选/按定位分组;只有看板第一列平铺 + dashboard top-N。
- 设置页=薄壳:引擎 key 开发者区 + 两个跳转按钮;雷达源配置在 scout.js、席位在校准中心,
  定位 input 在 scout 和 style 两处重复(同写 profileUpdate{industry})。
- 导航:顶栏菜单只露 4 项(回流/素材/回收站/设置),drafts/侦查/校准全靠侧门,发现性割裂。
- Dashboard 五卡单通道(dashboardSummary)结构尚可,但情报源健康度行是第二数据源缝在灵感卡里;
  管线卡纯计数无下钻;任务带双重驱动(subscribe+首绘)微重复。

### 4.2 后端

**已存在(比预期多):**
- **局部改写引擎已有**:`selection-rewrite.ts`(LLM,自由 instruction + selection 段,注入活跃风格规则),
  走 IPC `draft:rewrite_selection`。已知缺陷:正文上下文只取头部 3000 字,长文深处的选段上下文缺失。
- **纠正即训练骨干已有**:diff-tracker 落盘用户改稿 diff(content-save + style:record_edit 两个采集点)→
  style-distiller LLM 蒸馏(≥3 条新 diff 触发)→ addWritingRule(auto_distilled);规则三来源齐
  (user_explicit 对话纠正 / auto_distilled 改稿蒸馏 / calibrated 爆款吸收),scope 路由与升格已有。
- 雷达入库是唯一有定位硬门的路径(industry 必填 + LLM 相关性评分阈 7 + 画像消费)。

**确认缺口:**
- **受众画像有读无写**:AudiencePersona 类型 + 三处消费(总编辑提示词注入/free-engine painPoint 评分/
  雷达相关性评审)都在,**全库零写入路径**——永远是 null。创始人 profile 里的画像是老 muse 系统遗产。
- **styleCalibrated 永远 false**:无任何代码路径置 true,"已校准"态不可达(dashboard/渐进画像都在读它)。
- **rewrite MCP 工具是确定性字符串模板**(固定段头硬插),非 LLM;只有 adapt_platform/batch_adapt,
  无自由 instruction、无整篇 polish。
- **灵感库五条入库路径中四条无定位过滤**(手动/chat/topic-create/research 软评分);
  **"上传自己的文案"入口不存在**(素材库只收媒体;absorb_samples 进的是风格规则不是灵感库)——
  创始人观察到的"直接进灵感库"实为缺失该入口后的体感混淆,v5 把它做成显性正确的流。
- **网页搜索能力为零**(free 模式等调用方喂 search_results;只有 RSS+五海外公开源+单 URL read_url)。
- **发布自动化仅公众号**;抖音/小红书/视频号/B站只有剪贴板格式化;X/Reddit/头条零代码。
- **包矩阵**:仅 koubo(口播,软门)+ wechat_article(硬质量门);非公众号平台全部回退 koubo。

## 5. 分期(依赖顺序,每期独立验收)

**V5.0 保命修复(vanilla,即刻)**
标题可编辑(contentUpdate 收 title);采纳裁决"重写原因"增加自由输入;框选工具条发现性提示。
> 边界:仅此三项,vanilla 不再堆新交互(frontend-v2 红线)。

**V5.1 画像基础(后端+chat 承载,不等 React)**
persona 生成模块(定位+代表作+规则 → 3 persona,继承 v2 Phase 0.5)→ 总编辑对话内与用户校准一次
(确认/修正)→ 写入 profile.audiencePersona + styleCalibrated=true → 审核员新增「受众停留审」
(以画像为标准出意见,不阻断,与违禁词门并列)。onboarding 补"受众是谁"一问。

**V5.2 编辑器引擎补口(后端先行,UI 随 frontend-v2 B 期)**
- selection-rewrite 上下文缺陷修复(选段前后开窗,替代头部 3000 字截断);
- rewrite 工具重做:LLM 化 + 自由 instruction + 整篇 polish 动作;平台适配模板句退役;
- 改稿反馈闭环显性化:保存时可选"为什么这么改"一句话(diff_note 已有落点),蒸馏器把 note 作为
  高置信信号;蒸馏产出的新规则在对话内播报(让"它学到了"可感知)。

**V5.3 情报进水(搜索 harness + 侦查员)**
- search provider 抽象(博查/Tavily 起步,配置在 ~/.autocrew/search.json,设置 UI+对话都可配);
- research free 模式接真搜索;侦查员 chat 工具:按定位/画像生成搜索词→搜集→LLM 相关性过滤→入灵感库
  (复用雷达的硬门与去重);
- "上传我的文案"显性入口:文本进来 → 拆(风格样本→absorb / 观点→灵感库,过定位门)→ 用户确认。

**V5.4 平台矩阵(逐平台,通一个交一个)**
- 图文:X pack+API 直发(确认卡=最后一击)、Reddit pack+API、头条 pack+剪贴板/预填;
- 视频三平台(抖音/视频号/小红书):koubo 强化为"口播稿+分镜表+发布件(标题/文案/tags/竖版封面)",
  发布=预填(逐平台过 §1 风控评审文档)或剪贴板;成片不做(剪辑师=裁决点 C 未开)。
- 每平台交付标准:真实生成一篇该平台成品 + 发布件到位 + 发布路径走通(API 到确认卡/预填到后台)。

**V5.5 前端 v2(frontend-v2 契约 A→D 期,吃前面所有后端)**
A 脚手架 → B 管线+编辑器(框选/diff/标题/note 全量体验落 React)→ C 任务动态+校准中心+画像页 →
D 删 vanilla。Dashboard 宏观 IA 按 §0.4 四问重排(今天做什么/团队在干什么/资产什么状态/数据说明什么)。

**V5.6 设置中心**:引擎/搜索/发布(publish.json 可视化)/席位/情报源/画像与风格,一页收口(随 V5.5 C 期)。

## 6. 验收口径

每条线"跑通了再给":真数据、真浏览器、真发布件(公众号今日标准)。平台线逐平台单独验收不打包;
编辑器线以"框选改写→diff→采纳→规则入库→对话播报"全链一次真实操作为验收;
画像线以"生成→校准→styleCalibrated=true→一篇稿被受众停留审给出画像依据的意见"为验收。

## 7. 需要创始人的配置/裁决(集中列出,不零敲)

1. **搜索 API**:博查(中文优先)或 Tavily,任一 key 配进 search.json(V5.3 前置)。
2. **X/Reddit 发布**:X API(免费档写配额有限,可能需 Basic)与 Reddit OAuth 应用——要你的开发者账号;
   两平台的语言/persona(中文还是英文号)需要你定(PRD-v4 §4:每平台席位一个 persona)。
3. **视频三平台预填**:B 级风控评审文档我出,**开启与否你逐平台批**;预填走你登录态的浏览器,
   提交键永远你按。
4. **头条**:无公开自助 API,默认剪贴板+预填;若你有 MP 服务商资质另说。
